# Apple Connector v0.13.0 计划：help/version 命令、picocolors 终端样式与详细使用文档

更新日期：2026-11-17
状态：已批准并实施（2026-11-17）
进度：[v0.13.0-progress.md](./v0.13.0-progress.md)

## 结论

本版本只调整 CLI 的人类可读输出与“使用文档”页面，不改变 Agent 读写协议、JSON envelope、授权判断、native helper 协议、SQLite schema 或 grants JSON：

1. 新增 `apple-connector help [topic...]`，并把 `--help`/`-h` 统一到同一套帮助内容；`help` 支持查看单个命令的详细参数与示例。`version` 已有，但非 `--json` 模式目前输出 JSON；本版本恢复为稳定的人类可读版本行，并增加 `--version`/`-v` 别名。
2. 引入直接依赖 `picocolors`，新增 CLI 展示层：帮助、版本、服务状态、doctor、onboarding 结果和业务数据使用颜色、层级和状态标记；`--json` 保持逐字节机器输出，不带 ANSI。
3. 把“使用文档”从三张步骤卡片扩展为结构化长文档：命令速查、Agent 接入、权限与 profile、日历/提醒事项示例、审批与审计、JSON/退出码、故障排查和安全边界。

版本建议升为 `0.13.0`。若维护者希望以补丁版本发布 CLI 展示调整，请在批准时说明。

## 现状

- CLI 只有 `--help`/`-h` 隐式入口，`apple-connector help` 会报 `Unknown command`。
- `version` 命令存在；非 `--json` 模式当前输出 `{"version":"0.12.0"}`，旧版本文档曾记录人类输出为 `apple-connector <version>`。
- 所有非 `--json` 结果都走 `JSON.stringify(data, null, 2)`，状态、onboarding、错误都没有颜色、图标或分组。
- `picocolors@1.1.1` 目前只是 Vite/Browserslist 的传递依赖，没有声明为直接依赖。
- “使用文档”页只有 3 个常用命令、3 张步骤卡片和两段说明，没有命令参数、示例、错误码或排查路径。
- `scripts/release-verify.mjs` 会以非 TTY 方式执行 `--help`、`version`、`doctor`；现有构建和测试也通过管道读取输出。
- 工作树包含 v0.10.0、v0.11.0、v0.12.0 的未提交改动；本版本叠加在其上，不回退或覆盖。

## 设计

### 1. `help` 与 `version` 命令

- 在命令分发前处理：
  - `apple-connector help`：显示总览。
  - `apple-connector help <topic...>`：显示单个命令或子命令的详细帮助，例如 `help calendar create`、`help reminder patch`。
  - `apple-connector --help`、`-h`：等价于 `help`。
  - `apple-connector version`：人类可读版本行。
  - `apple-connector --version`、`-v`：等价于 `version`。
- 帮助主题覆盖现有全部入口：`setup`、`start`、`stop`、`status`、`open`、`agent init`、`agent init-status`、`skill path`、`calendar` 及四个子命令、`reminder` 及六个子命令、`operation get`、`doctor`、`version`、`help`。
- 总览按用途分组：服务生命周期、Agent 接入、日历、提醒事项、诊断与帮助。每组显示命令、一句话说明和一个示例。
- 单命令帮助包含：用途、语法、必填/可选参数、`--json` 行为、示例和相关命令；不再把全部参数塞进一行。
- 未知主题返回 `invalid_request`，退出码 2，并提示 `Run apple-connector help`。
- `version` 人类模式输出 `apple-connector 0.13.0`；`--json` 继续返回 `{ ok: true, data: { version }, meta: { schemaVersion: 2 } }`。
- `help --json` 继续沿用现有 `data` 为帮助文本字符串的 envelope，不新增机器协议。
- 新增 `--no-color`，仅影响人类输出；与 `NO_COLOR`、非 TTY、`TERM=dumb` 一起关闭 ANSI。

### 2. picocolors 展示层

- `package.json` 增加直接依赖 `"picocolors": "^1.1.1"`，并更新 `package-lock.json`；不引入其他运行时依赖。
- 新增 `src/cli/ui.ts`，集中所有终端表现，业务命令只提交数据：
  - 颜色开关：`--json` 永远关闭；`--no-color`、`NO_COLOR`、`TERM=dumb`、非 TTY 关闭；其他情况启用。
  - 用 `picocolors` 的 `createColors(enabled)` 创建实例，便于测试同时覆盖有颜色和无颜色两条路径。
  - `helpText(topic?)`：标题、分组、命令名、参数、示例和提示分层着色。
  - `versionText()`：单行版本。
  - `formatStatus`、`formatDoctor`、`formatSetup`、`formatStart`、`formatStop`、`formatOpen`、`formatSkillPath`、`formatAgentInit`、`formatOnboardingStatus`：按命令输出人类可读摘要，而不是裸 JSON。
  - `formatJson(value)`：业务列表/操作结果继续以 JSON 结构展示，但做语法着色（键、字符串、数字/布尔、标点）；关闭颜色时输出与当前 `JSON.stringify(value, null, 2)` 完全一致。
  - `formatError(error, json)`：人类模式输出红色 `error` 标签和消息；`invalid_request` 额外显示 `Run apple-connector help` 提示。退出码保持不变。
- 状态与结果使用简单符号区分：运行/成功、停止/失败、警告；符号只在开启颜色时使用，非 TTY 输出保持纯文本可解析。
- 不在人类模式输出任何凭据内容：
  - `setup` 人类输出只说明 admin token 已写入所有者可读文件，不打印 token。
  - `agent init`/`agent init-status` 继续只显示 onboarding ID、URL、过期信息和凭据文件路径，不读取或展示 token。
  - `--json` 的现有字段保持不变，避免破坏机器调用方。
- `result()` 改为接收展示上下文；未知上下文默认走 `formatJson`，保证未来新增命令至少有可读输出。

### 3. “使用文档”详细页面

- 新增 `src/web/docs.ts`，以纯数据保存中英文文档，避免继续膨胀 `i18n.ts`：
  - `GuideSection { id, title, summary, body: string[], commands?: { syntax, description }[], notes?: string[], table?: { columns, rows } }`。
  - `usageGuide: Record<Language, { intro: string; sections: GuideSection[] }>`。
  - 中英文 section ID、顺序和命令集合保持一致，测试锁定。
- 页面内容分为以下章节：
  1. **概览与前置条件**：本机 loopback、macOS 14+、Apple Silicon、受支持 Node、不提供云端/MCP 入口。
  2. **安装与首次接入**：`setup`、`start`、`status`、`open`、`agent init` 的先后关系和每条命令的作用。
  3. **命令速查**：`help [topic]`、`version`、服务生命周期、`skill path`、`operation get`、`doctor [--probe]`。
  4. **Agent 接入**：加载 Skill、保存 onboarding ID、把 URL 交给用户、等待“已完成”、`init-status`、只把凭据文件路径交给 Agent。
  5. **系统权限与 Agent 配置**：系统权限是授权前提、容器可见性、动作/字段/审批的组合规则、默认一年过期、撤销与删除的差异。
  6. **日历命令**：`list-calendars`、`list`、`create`、`update`、`delete` 的必填参数与时间格式；敏感字段通过 `--input`。
  7. **提醒事项命令**：`list-lists`、`list`、`create`、`update`、`patch`、`complete`、`delete`；`--due`、`--due-date`、`--time-zone`、`--clear-due`；`due` 的三种 JSON 形态；重复事项不支持 patch/update/complete/delete。
  8. **审批与审计**：`approval=required` 的写入进入审批页；审批只针对已持久化的不可变操作；审计只保留元数据。
  9. **JSON、退出码与幂等**：所有机器接口使用 `--json` 与 `schemaVersion: 2`；退出码 0/1/2/4；写操作必须提供 `--idempotency-key`；不要用新 key 重试 `outcome_unknown`。
  10. **故障排查**：`service_unavailable`、链接过期、系统权限缺失、容器为空、`permission_denied`、`unsupported_operation`、凭据路径错误的排查顺序。
  11. **安全边界**：仅 loopback、会话一小时过期、不要粘贴凭据内容、不要把管理链接转给其他设备、审计不保存标题/正文/备注。
  12. **参考**：随包文档 `docs/cli.md`、`docs/skill.md`、`docs/getting-started_zh.md`、`docs/install-for-agent_zh.md` 的用途说明。
- 渲染：
  - 顶部保留“常用命令”块，但改为完整、可复制的一行命令。
  - 增加页内目录（TOC），桌面端左侧 sticky，窄屏折叠为横向滚动链接；使用 `#docs-<id>` 锚点，不新增路由。
  - 每个 section 使用标题、短摘要、正文列表、命令表/代码块和提示块；沿用现有黑白灰与蓝色状态 token。
  - 命令块保持等宽字体和横向滚动，不自动换行破坏命令。
- `?section=docs` 与 `apple-connector open --section docs` 行为不变；`#docs-...` 可直接定位章节。

### 4. 兼容性与安全

- 不改 `grantSchema`、`authorize`、Agent RPC、native helper 协议、数据库、审计结构或 `schemaVersion`。
- `--json` 始终是单条无 ANSI 的 envelope；脚本和 Skill 的行为不变。
- 人类输出被视为展示层，不作为机器契约；`release-verify` 仍执行 `--help`、`version`、`doctor`。
- 不在文档页展示或读取任何真实凭据、URL token 或系统权限实时状态。
- 版本元数据升为 `0.13.0`：`package.json`、`package-lock.json`、native helper `helperVersion`、`scripts/release-verify.mjs`、`docs/cli.md` 的当前版本描述；`protocolVersion` 与 CLI `schemaVersion` 不变。

## 不在本版本范围

- 不重写参数解析器，不引入 commander/yargs 等框架。
- 不新增 shell completion、man page、配置文件或交互式 TUI。
- 不改变业务命令 JSON 字段、错误码、退出码或 `schemaVersion`。
- 不新增 Web RPC，不在文档页读取实时系统权限或真实凭据。
- 不生成静态文档站点，不把 `docs/*.md` 自动打包进 Web 前端。
- 不启动常驻服务；预览由维护者自行决定。

## 风险与待确认

1. `version` 人类输出从 JSON 对象改为 `apple-connector 0.13.0`。机器调用方应使用 `--json`；如仍需非 JSON 的旧格式，请在批准时说明。
2. 业务数据的人类输出采用“JSON 语法着色”而不是重新设计表格。这样不改变字段，但视觉提升有限；如需为 list 结果做专用表格，请明确。
3. 人类模式 `setup` 不再打印 admin token（只提示已写入文件），`--json` 保持现有字段。建议采用，请确认。
4. 建议版本为 `0.13.0`；若并入 `0.12.1` 请说明。
5. `help <topic>` 支持多词子命令（如 `help calendar create`），未知主题退出码 2。若只需总览帮助，可缩小范围。
6. 使用文档会明显变长，桌面端采用左侧目录。若希望保持单屏精简，请在批准时说明。
