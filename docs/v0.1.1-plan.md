# Apple Connector v0.1.1 版本计划

状态：计划中（承接 [v0.1.0-plan.md](./v0.1.0-plan.md) 的未完成范围）
更新日期：2026-09-06

## 目标

在不放宽 v0.1.0 的本地授权、不可变计划、审计和“无法可靠判定即拒绝”边界的前提下，补齐既有对象的受控变更、Calendar 写入路径与发布验证。v0.1.1 不是把未验证能力直接打开；每项写入先通过专用 `Agents` 容器的原生验证，再接入服务和 MCP。

## 范围与验收

### 1. Reminders：受控修改与完成

- 支持修改普通提醒的标题、备注和截止日期；支持完成普通提醒。
- 仅允许明确授权清单内、稳定 ID 定位且可确认不属于重复规则/不支持形态的对象。
- 写入采用 prepare → 审批/自动授权 → 执行前重读 → 持久化意图 → 写入 → 回读核验的现有链路。
- 拒绝重复、定位歧义、跨清单、共享状态无法安全处理或原生接口无法验证的对象。

验收：专用 `Agents` 清单中覆盖 Unicode、换行、date-only、带时区日期、并发提交、撤销、冲突、超时/unknown outcome；不得读写其他清单。

### 2. Calendar：个人单次事件创建与受控修改

- 建立可重复的、稳定的授权容器与事件定位方案；不再把日历名称伪装成稳定 ID。
- 支持在明确授权的个人日历创建普通单次事件；在稳定目标定位前不暴露修改能力。
- 若共享、参与者、重复规则或稳定 ID 无法可靠判定，拒绝写入。
- 保留目前已验证的“唯一名称 + 范围读取”路径；名称重复时继续拒绝。

验收：专用 `Agents` 日历完成创建、回读、修改与核验；验证 EventKit/Apple Events 的权限归属、升级后行为和超时结果对账。不得仅凭标题定位写入目标。

### 3. 权限与原生能力门禁

- 记录终端、后台服务、MCP 客户端和最终安装位置的 TCC/Apple Events 权限归属。
- 验证 EventKit 完整访问授权回调与运行时可见性；不能以授权状态替代实际访问验证。
- 为每个 provider/动作维护独立 capability 状态，禁止一个已验证 adapter 解除其他写入门禁。

验收：诊断结果不泄露内容；系统权限、连接器授权和实际 adapter 能力可以在管理端区分显示。

### 4. 管理端与审计收尾

- 增加诊断面板：版本、协议、权限检查、最近错误与存储占用；不得显示 token 或正文。
- 完成授权范围编辑/凭证轮换的交互及回归测试。
- 验证审计导出、清空、WAL checkpoint 与实际磁盘占用在小阈值下的行为。

### 5. 发布候选

- 确定支持的 macOS/Node/架构矩阵并固定最终包依赖。
- 完成 GitHub Release 产物、签名/分发取舍、自有 Homebrew tap Formula、全新安装/升级/卸载验证。
- 补齐双语用户文档、已知限制和首次任务路径；邀请目标用户进行真实安装验证。

验收：最终包可执行 `--help`、`version`、`doctor`、管理资源检查和受限端到端任务；tap 仅在 Release 成功后更新。

## 非范围

- 不支持删除既有 Apple 数据、重复系列编辑、邀请/参与者管理、共享 Notes 写入、远程 MCP 或跨设备同步。
- 不因实现便利而读取 Apple 私有数据库、关闭系统保护、修改 TCC 数据库或要求全磁盘访问。

## 执行顺序

1. 完成 Reminders/Calendar 原生能力矩阵和安全拒绝条件。
2. 实现并验证既有对象变更与 Calendar 写入。
3. 完成权限/安装矩阵、管理诊断和审计负载验证。
4. 构建发布候选、Homebrew tap 与真实用户验证。
