# Apple Connector v0.8.4 计划：修复 Calendar 时间区间解析

更新日期：2026-09-08  
进度记录：[v0.8.4-progress.md](./v0.8.4-progress.md)

## 问题结论

`calendar.list_events` 的请求经过了两层时间校验，但两层接受的格式不一致：

- MCP / 本地 RPC 使用 `z.iso.datetime({ offset: true })`，要求显式时区，并接受带或不带小数秒的合法 ISO 8601 时间。
- Swift EventKit helper 把唯一的 `ISO8601DateFormatter` 配置为 `.withInternetDateTime` 加 `.withFractionalSeconds`。这个 formatter 在解析输入时要求小数秒，因此 schema 已接受的 `2026-09-07T00:00:00+08:00` 和 `2026-09-07T00:00:00Z` 会在 helper 中解析失败，最终统一返回 `Invalid event range.`。

因此，配对和 EventKit 权限不是这次现象的首要嫌疑；失败发生在解析时间、查询日历之前。不带时区的 `2026-09-07T00:00:00` 被 MCP schema 拒绝则是预期行为，v0.8.4 不会放宽这一约束。

同一个 formatter 还用于 Calendar 创建/更新和 Reminders 的 instant due 解析，所以修复应覆盖 helper 内全部 ISO instant 输入，避免只修 `list_events` 后留下同源问题。

## 修复方案

### 1. 统一 ISO 8601 输入契约

- 在 Swift helper 中把“输入解析”和“输出格式化”分开。
- 新增一个集中式解析函数，依次接受：
  - 带显式时区、带小数秒的 ISO 8601 时间；
  - 带显式时区、不带小数秒的 ISO 8601 时间。
- 输出继续使用带小数秒的稳定格式，避免改变已有返回结构和客户端解析行为。
- `calendar.listEvents`、Calendar create/update 的 `start`/`end`、Reminders instant due 的 `at` 全部复用同一解析函数。
- 仍拒绝缺少时区、无法解析或 `to <= from` 的输入；不把本地时间静默解释成系统时区。

### 2. 统一 MCP 参数校验与格式提示

- 为全部 MCP 工具建立共享的参数 schema，不再由 MCP 注册层、本地 RPC 层和业务类型分别维护含义相同但消息不同的校验规则。工具注册时使用共享 schema，RPC 边界用同一 schema 做纵深校验。
- 统一以下常用参数类型及其错误提示：
  - Calendar / Reminders / event / operation 等 ID：非空字符串及对应长度上限；
  - `offset`：大于等于 `0` 的整数；`limit`：`1` 到 `100` 的整数；
  - instant datetime：RFC 3339 / ISO 8601、必须包含 `Z` 或 `±HH:mm` 时区、小数秒可选；
  - date-only：严格的 `YYYY-MM-DD` 有效日期；
  - time zone：有效 IANA 时区名，例如 `Asia/Shanghai`；
  - `idempotencyKey`、枚举值和 mutation 对象的必填字段、类型及长度限制。
- 参数失败信息必须包含：具体字段路径、失败原因、正确格式；格式不直观时同时提供安全的固定示例。不得在错误中回显 token、标题、备注、日程正文等调用数据。
- datetime 的标准提示形如：`Invalid argument "from": expected an RFC 3339 datetime with an explicit timezone, for example "2026-09-07T00:00:00+08:00" or "2026-09-06T16:00:00Z"; fractional seconds are optional.`
- 跨字段校验使用针对关系的提示，例如：`Invalid arguments "from" and "to": "to" must be later than "from".`，而不是笼统的 `Invalid event range.`。
- MCP schema 阶段的失败继续使用协议标准 `-32602 Invalid params`，但正文携带上述可操作提示；已经进入工具处理函数的业务校验失败继续返回 `isError: true` 和稳定的 `invalid_request` 错误对象。
- 在 RPC / 业务边界集中把 `ZodError` 转换成经过脱敏的 `ConnectorError('invalid_request', ...)`，避免当前未识别的校验异常被误报为 `service_unavailable`。
- helper 作为纵深防线，对绕过 MCP 的调用执行相同语义的检查，并区分“时间无法解析”和“结束时间不晚于开始时间”。
- 不改 EventKit 查询的半开区间语义，也不改分页、授权和容器解析逻辑。

### 3. 增加回归测试

- 增加不依赖真实日历内容的 Swift/helper 时间解析测试，覆盖：
  - `Z` 与 `+08:00`；
  - 有小数秒与无小数秒；
  - 缺少时区、非法文本和倒序区间仍被拒绝。
- 增加真正走 `EventKitHelperClient` / `EventKitCalendarReader` 的 opt-in 原生集成测试；用指定测试日历分别查询无小数秒的 `Z`、`+08:00` 范围，只断言调用成功、分页边界和事件结构，不打印日程内容。
- 保留并补强 MCP / 本地服务测试，确认 schema 接受两种合法精度、拒绝无时区输入，并原样把时间传给 provider。
- 为每类共享 MCP 参数 schema 增加表驱动测试，断言无效参数的错误包含字段路径、约束和正确格式；同时断言错误不会回显敏感调用内容。
- 增加端到端 MCP 错误测试，确认 schema 失败返回 `-32602` 与可操作格式说明，业务层参数失败返回稳定的 `invalid_request` tool error。
- 检查 Calendar create/update 和 Reminders instant due 的无小数秒输入，防止同一 formatter 问题在写入路径复发。

### 4. 同步 v0.8.4 版本与发布材料

- 将 npm 包、lockfile、CLI 版本、native helper handshake 和版本相关能力说明同步到 `0.8.4`。
- 更新 README、Agent 安装文档和发布验证中的固定版本引用。
- 不借本补丁改变授权策略、配对流程、日历范围语义或其他产品能力。

### 5. 采用 MIT 许可证并解除发布元数据门禁（修订，待批准）

- 新增仓库根目录 `LICENSE`，使用标准 MIT License 文本，版权归属与年份沿用维护者明确提供或仓库既有发布元数据；不得擅自推测个人或组织名称。
- 在 npm manifest 中声明 SPDX 标识 `MIT`，保留现有仓库、主页、bugs、平台和发布配置。
- 更新发布验证，确认 tarball 含许可证文件且 metadata 为 `MIT`；不执行公开 npm publish、Git tag 或 GitHub Release。
- 将当前 native helper 无数据 `hello` 无响应作为独立环境诊断项：先采集进程栈和启动边界证据；仅在证据表明是本版本代码缺陷时，提出最小修复并重新提交本计划审阅。

## 验收标准

- `calendar.list_events` 对 `2026-09-07T00:00:00+08:00`、对应的 `Z` 表示以及带小数秒的等价格式均能通过 helper 并执行 EventKit 查询。
- 缺少时区的时间仍在 MCP schema 层以参数错误拒绝；无效时间和非递增区间仍返回 `invalid_request`。
- 每个 MCP 工具都使用共享参数 schema；无效参数响应指出字段、原因和正确格式，datetime/date/time-zone 等非直观格式包含固定示例。
- MCP schema 错误和业务层参数错误的错误码边界稳定，且任何校验错误都不回显凭证或个人数据字段值。
- Calendar 创建/更新及 Reminders instant due 与上述输入契约一致。
- `npm test`、`npm run check:jxa`、opt-in `npm run test:native`、`npm run release:verify` 和 `git diff --check` 通过；若发布门禁仍被既有许可证或仓库元数据阻塞，需与本修复的测试结果分开记录。
- 从 v0.8.4 tarball 安装后，CLI 与 native helper 都报告 `0.8.4`，并用实际 MCP 调用完成一次不泄露事件内容的 `calendar.list_events` 冒烟验证。
- `npm run release:verify` 识别 `MIT` 许可证并通过许可证 metadata/file 门禁；本轮不向 npm registry 发布。

## 非目标

- 不接受无时区的 datetime。
- 不用 osascript/JXA 替换生产 EventKit reader。
- 不修改 Calendar 授权范围、写入审批或配对策略。
- 不在测试中创建、修改或输出用户的真实日历事件；原生读取验证仅针对显式指定的测试日历。
