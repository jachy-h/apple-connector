# Apple Connector v0.9.5 计划：权限状态强化与 Agent 授权聚合

更新日期：2026-09-09
状态：待维护者批准
进度：[v0.9.5-progress.md](./v0.9.5-progress.md)

## 背景与结论

v0.9.4 的权限卡已经有淡色背景和小圆点，但“已获完全访问”等结论仍不够醒目。v0.9.5 将把权限结论升级为高对比度的语义 badge、左侧状态条和卡片边框；每种状态仍保留明确的文字，不只依赖颜色。

“策略 v2 已撤销”与“策略 v1 已启用”不是同一个 profile 的两个并存版本。每次创建 profile 都生成新的 client ID，初始 policy 版本为 v1；撤销某一 client 时，该 client 的 `policy_version` 会加一并标记为 revoked。因此，如果两个卡片的 ID 不同，即使名称相同，它们也分别是“已撤销的旧凭据（v2）”和“仍启用的新凭据（v1）”。单一 client 不可能同时呈现 v2 已撤销和 v1 已启用。当前页面按 client ID 逐卡展示，未聚合同名 profile，容易将同一应用的多份凭据误读为版本历史。

当前数据模型没有“应用”独立字段。为不猜测凭据归属，本版本将以 profile 的完全相同 `name` 作为页面聚合键；每个聚合组中仍保留所有 client ID、状态和授权明细，绝不合并、删除、重新授权或改变后端授权判断。同名但实际属于不同应用的 profile 也会被呈现在同一组中，因此组标题会明确提示“按名称聚合”。若未来需要可靠的应用身份，应另行设计稳定的 application ID，而非从名称推断。

## 实施范围

### 1. 强化系统权限的视觉状态

- 为 `full_access`、`write_only`/`not_determined`、`denied`/`restricted`、`unknown`/检查失败分别提供高对比度的成功、警告、错误和中性 badge、状态条和边框；“已获完全访问”必须在首屏可一眼识别。
- 保留状态名称、状态图标和“最近检查”时间，确保色觉差异用户以及屏幕阅读器可获知同等结论。
- 不改变现有原生权限读取与申请流程：首次读取仍走 `diagnostics.summary`，点击申请仍走 `diagnostics.permissions.request`，未知或失败结果绝不显示为已授权。

### 2. 聚合 Agent 配置中的同名应用

- 在共享的 Web 展示模型中新增纯函数：按完全相同、非空的 profile 名称归组；组内按启用优先、名称/ID 稳定排序，确保 UI 和测试可预测。
- Agent 配置页改为先展示“应用（按名称聚合）”组，再显示该组所有 profile/credential 的 ID、启用或撤销状态、policy 版本及每条 grant。组头显示启用与已撤销 profile 数量，避免把 policy version 当作跨 client 的全局版本号。
- 每条 profile 保持独立的撤销按钮和 session 保护；聚合仅影响显示层，不调用 `clients.update`、不旋转/删除 token，也不修改 `clients.list`、数据库 schema、RPC 白名单或 Agent transport。
- 对没有 profile 的空状态，以及存在无法安全解析 grant 的 legacy 数据，保留明确且不泄露凭据的展示。

### 3. 本地化、测试与版本契约

- 补充中英文文案：权限状态提示、按名称聚合说明、profile/凭据计数和聚合后的空状态。
- 回归测试覆盖：权限状态 CSS/展示语义所需的 tone；同名 active + revoked profile 聚为一组、不同名称不聚合、每个原 ID 和 grant 不丢失；并明确断言“v2 revoked”和“v1 active”属于不同 client ID 时可共存。
- 同步 package、lockfile、native helper `hello`、`release:verify` 及 `docs/cli.md` 至 v0.9.5。

## 验证标准

1. “已获完全访问”显示为高对比度成功状态，拒绝/受限、待决定和未知/失败同样有显著且带文字的差异化提示。
2. UI 不会将不同 client ID 的 profile 误称为同一策略的版本历史；每张 profile 仍显示其独立 ID、状态与 policy version。
3. 完全相同名称的 profile 聚合到一个“按名称聚合”的应用组；不同名称保持分组隔离；组内没有丢失任何 profile、grant 或撤销操作入口。
4. 聚合不会改变数据库、token、授权结果、RPC 权限或 agent transport 隔离。
5. `npm test`、`npm run check:jxa`、`npm run release:verify` 和 `git diff --check` 通过；不发布 npm 包、不创建 Git tag 或 GitHub Release。
