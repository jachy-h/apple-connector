# Apple Connector v0.16.0 计划：合并接入页面，加入 Agent 验证绑定

更新日期：2026-11-18

状态：已批准并实施完成（2026-11-18）

进度：[v0.16.0-progress.md](./v0.16.0-progress.md)

> 本计划建立在已完成的 `v0.15.1`（移除日历字段选择）之上：授权不再包含 `fields`，页面只选择容器和动作。

## 结论

把“系统权限”和“授权”两个页面合并为一个按顺序推进的接入页面，并把接入链路明确为四步：

```text
1. 系统授权     macOS 允许访问日历 / 提醒事项
2. Agent 授权   为单个 Agent 创建独立授权（容器 + 动作 + 过期时间）
3. 复制提示词   页面生成提示词，人类粘贴给 Agent
4. Agent 验证   Agent 运行 auth verify，把身份绑定到该授权
```

第 4 步通过新增的 Agent 端 `auth.verify` 写回授权记录（Agent 名称 + 验证时间）。接入页面轮询授权列表，Agent 完成后无需刷新即可看到“Agent 已绑定”。

版本建议：`0.16.0`。数据库新增列、新增 RPC 和 CLI 命令均向后兼容旧授权和旧提示词，但旧版本程序无法打开 v8 数据库。

## 设计决策

### 绑定信息的“指定位置”

采用“授权记录内的绑定字段”，而不是让 Agent 在文件系统中随意写文件：

- Agent 使用自己持有的授权码（`--auth-file` / `--auth` / `APPLE_CONNECTOR_AUTH`）调用 `apple-connector auth verify --agent <name>`。
- 服务端先做与业务命令相同的 token 鉴权，再把 `agent_name`、`verified_at` 写入该授权。
- 页面通过已有的 `clients.list` 读取绑定状态，并每 3 秒轮询一次。

理由：

- 身份来自已鉴权的 token，页面显示的不是 Agent 自报的任意文本；
- 不需要新文件格式、目录监听或额外的管理端读取文件 RPC；
- 删除授权时绑定信息随记录一起删除，不会留下孤儿文件；
- 同一机制对“只拿到授权码”的 Agent 同样有效。

不采用文件投递方案的原因：页面无法直接读文件，仍需新增管理 RPC，且要处理目录权限、覆盖、清理和伪造，复杂度更高。

### 页面轮询与“立刻看到”

- 接入页在可见且有管理会话时，每 3 秒调用一次 `clients.list`；窗口重新获得焦点时立即刷新一次。
- 创建授权后立即刷新，因此第 4 步从“等待验证”切换为“已绑定”最多延迟约 3 秒。
- 不使用 SSE/WebSocket，避免新增长连接和生命周期管理。
- 若 Agent 只运行了 `auth show` 或业务命令，`lastUsedAt` 会更新，但不会显示为“已绑定”，而是“已使用授权，尚未验证”。

## 页面结构

### 导航

- 顶部导航从 `系统权限 / 授权 / 审计 / 使用文档` 收敛为 `接入 / 审计 / 使用文档`。
- `section=permissions`、`section=agents` 作为旧链接别名，均落到 `接入`；`section=setup` 为新的规范值。
- `apple-connector init` 默认 section 从 `permissions` 改为 `setup`。
- `audit`、`docs` 页面保持不变。

### 接入页：四个带序号的步骤

使用横向步骤引导条（可点击 / 方向键切换）+ 单步骤内容面板，明确“上一步完成才能进入下一步”。默认显示第 1 步；创建授权后自动切到第 3 步；点击任意步骤只显示该步骤的详细信息。

1. **系统授权**
   - 保留现有日历 / 提醒事项权限卡片、请求权限、打开系统设置、重新检查。
   - 完成条件：至少一个 provider 为 `full_access`。
   - 未完成时第 2 步显示锁定说明，并将表单控件设为禁用。

2. **单独 Agent 授权**
   - 保留名称、日历容器、提醒事项容器、动作、过期时间和创建按钮。
   - 文案强调“一个授权对应一个 Agent”。
   - 已有授权列表保留在此步骤下方，并显示绑定状态徽标、上次使用时间和删除操作。
   - 完成条件：至少存在一个未撤销的授权。

3. **复制提示词**
   - 创建授权前：占位说明“完成第 2 步后生成”。
   - 创建后：一次性授权码、推荐版提示词、含授权码备用版、复制按钮和安全警告。
   - 页面切换到其他 tab 后仍按现有行为丢弃内存中的一次性 token。

4. **Agent 完成验证**
   - 始终显示：
     - 尚未创建授权：提示先完成第 2 步；
     - 已创建、未验证：显示“等待 Agent 验证”，并说明 Agent 应运行 `auth verify`；
     - 已验证：显示“Agent 已绑定”、Agent 名称、验证时间；
     - 只使用过未验证：显示“已使用授权，尚未验证”。
   - 下方列出所有授权的绑定摘要。

### 视觉与文案

- 步骤引导条：序号圆点、步骤名、状态徽标（`已完成` / `待完成` / `等待 Agent 验证` / `等待上一步完成`）、当前步骤高亮；点击或方向键切换内容。
- 绑定徽标：`bound`（蓝色）、`used`（琥珀色）、`never`（灰色）。
- 中英文案同步；绑定状态推导放在 `src/web/management-view.ts` 的纯函数 `agentBinding` 中。

## 数据与协议

### 数据库（`user_version=8`）

`clients` 新增两列：

```sql
ALTER TABLE clients ADD COLUMN agent_name TEXT;
ALTER TABLE clients ADD COLUMN verified_at INTEGER;
```

- 迁移只加列，不改旧行；旧授权迁移后 `agent_name`、`verified_at` 为 `NULL`。
- `Store.client()`、`Store.listClients()` 返回 `agentName`、`verifiedAt`。
- 新增 `Store.verifyClient(id, agentName, now)`：更新这两列并返回最新 `Client`。
- `authenticate()` 现有的 `last_used_at` 行为不变。
- `policy/schema.ts` 的 `Client` 接口新增 `agentName: string | null; verifiedAt: number | null`。
- 迁移把最大可识别版本从 7 提升到 8；旧程序打开 v8 数据库会得到“Database was created by a newer version”。

### RPC

- `rpcMethodSchema` 新增 `auth.verify`。
- `agentMethods` 新增 `auth.verify`；管理端不可调用。
- 参数严格校验：`{ agent: string trimmed 1..100 }`。
- 处理流程：鉴权 → `verifyClient` → 审计 → 返回 `{ name, agentName, verifiedAt, expiresAt }`。
- `auth.describe` 与 `clients.list` 返回值追加 `agentName`、`verifiedAt`，旧字段不变。
- 不提升 CLI `schemaVersion`（仅新增字段）。

### 审计

- `auditEventSchema.action` 新增 `agent_verified`。
- `auth.verify` 写入 `{ action: 'agent_verified', outcome: 'allowed', clientId }`。
- 审计仍只保存元数据，不保存 token 或提示词。

## CLI

### 新增 `apple-connector auth verify`

```text
apple-connector auth verify --agent <name> [--auth-file <path> | --auth <token>] [--json]
```

- `--agent` 必填；缺失时 `invalid_request`，退出码 2。
- 复用现有凭证解析优先级：`--auth-file` → `--auth` / `APPLE_CONNECTOR_AUTH` → `--credential-file` / `--profile`。
- 人类输出显示授权名称、Agent、验证时间、过期时间；`--json` 返回标准 envelope。
- `auth show` 增加 `Agent` / `Verified` 两行（未绑定时显示 `never`）。
- 更新 `auth`、`auth show`、新增 `auth verify` 帮助条目、总览命令列表和 `related`。

### section 参数

- `init` / `open --section` 接受 `setup|audit|docs`。
- 兼容 `permissions`、`agents`，统一规范化为 `setup` 后再生成 URL 和返回值。
- 其他值仍返回 `invalid_request`。

## 提示词

`buildAgentPrompt` 增加“完成验证”步骤，输入结构不变：

- 优先使用凭据文件，不展开 token；
- `auth show` 查看范围；
- **新增**：`apple-connector auth verify --agent '<你的名称>' --auth-file '<path>' --json`；
- 说明运行成功后本机管理页会立刻显示“Agent 已绑定”；
- 后续为 Skill、文档、一次有界只读查询和写入幂等要求。
- 含授权码版本使用 `--auth '<token>'` 完成同一验证，并保留存储警告。
- 中英文结构一致；提示词仍不是协议，最终以 `docs/cli.md`、Skill 和 `help` 为准。

## 兼容性与迁移

- 已有授权码、`profiles/<uuid>.token`、`--auth-file`、`APPLE_CONNECTOR_AUTH` 继续有效。
- 旧授权迁移后绑定字段为空，页面显示“尚未绑定”；Agent 重新运行 `auth verify` 即可绑定。
- 旧提示词不含 `auth verify`，Agent 仍可正常使用授权，只是页面不会显示“已绑定”。
- `section=permissions|agents` 旧链接继续可用，并落到合并后的接入页。
- 旧程序打开 v8 数据库会拒绝启动；这是升级到 `0.16.0` 后不支持降级的既有策略。
- 不修改 grants 结构、token 格式、native helper 协议或业务 RPC。

## 风险

- **轮询开销**：每 3 秒一次 `clients.list`，仅在接入页可见且会话有效时运行。
- **绑定身份是自报名称**：`--agent` 由 Agent 提供，但 token 已通过鉴权，页面明确显示“授权已绑定到该名称”，不把它当作强身份认证。
- **跨层改动**：新增 DB 列、RPC、CLI 命令和提示词步骤，需要同步更新测试、Skill 和文档。
- **步骤门槛**：第 2 步在无系统权限时禁用，页会给出明确原因和下一步提示。

## 已确认

1. 合并后的导航与页面名使用 `接入` / `Setup`，保留 `审计`、`使用文档`。
2. 绑定机制采用 `auth verify --agent` + 授权记录字段 + 页面轮询。
3. 无任何完全访问权限时锁定第 2 步。
4. 版本号使用 `0.16.0`。
