# Apple Connector v0.8.2 计划：Agent 默认接入与完整写入工具

更新日期：2026-09-08  
进度记录：[v0.8.2-progress.md](./v0.8.2-progress.md)

## 目标

1. 将接入对象从 nanobot 收敛为通用本地 agent，不要求特定 host 的配置层级。
2. 提供顺序正确的一次性初始化：初始化状态、生成默认策略文件、配对并生成凭证，然后才输出引用 `APPLE_CONNECTOR_TOKEN_FILE` 的 MCP 配置。
3. 默认策略允许读取全部日历和提醒事项清单；仅精确名为 `Agents` 的日历和清单可创建、修改和删除。
4. 为 agent 注册日历事项和提醒事项的创建、修改、删除 MCP 工具，所有写入继续通过范围授权、持久化幂等记录、审批和写后验证。

## 实现要点

- 新增 `agent init`，默认在状态目录生成 `agent-client.json` 和 owner-only 的 `agent.token`；既有文件不覆盖。
- 默认策略使用可动态计算的一年有效期，不写入已过期的固定时间戳。
- 将 `delete` 纳入策略 action；`Agents` 名称授权在写入前解析为唯一 EventKit ID，缺失或重名时拒绝，不猜测目标。
- 新的业务写入工具自动执行 automatic 授权；required 授权返回待审批操作 ID。保留旧 `changes.prepare` / `changes.commit` 兼容入口。
- 更新能力声明、中英文 README 和配置指南，不宣称 Notes 可用。

## 验收

- 全新状态目录中执行 `agent init` 后，策略文件先于凭证生成，输出的 MCP JSON 中凭证路径真实存在。
- 默认策略的全容器授权只含 `read`，`Agents` 授权包含 `create` / `update` / `complete` / `delete`。
- MCP 工具列表包含日历和提醒事项的创建、修改、删除，未授权容器和 action 被拒绝。
- 自动测试覆盖默认配置、名称范围解析、六种写入的工具契约、幂等冲突及凭证文件保护。
- `npm test`、`npm run check:jxa` 和 `git diff --check` 通过。
