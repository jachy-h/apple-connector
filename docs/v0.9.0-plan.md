# Apple Connector v0.9.0 计划：Skill + CLI 主入口与本地管理 Web

更新日期：2026-09-08
进度记录：[v0.9.0-progress.md](./v0.9.0-progress.md)

## 版本决策

v0.9.0 将 Apple Connector 从“以 stdio MCP 为 Agent 入口”调整为“Skill 指导 Agent 调用结构化 CLI”：

1. 保留现有全局可执行文件名 **`apple-connector`**。
2. **完全删除 stdio MCP** 的运行时、CLI 命令、工具契约、依赖、测试和当前集成文档。旧 `mcp` 命令不保留 tombstone 或专用迁移提示，调用时与任意未知命令一样处理。
3. CLI 可按需启动临时本地管理 Web 进程。Web 默认在启动后 1 小时过期，页面显示服务端授时的倒计时，到期后拒绝新管理操作、注销会话并自动关闭 Web 进程。Web 负责：
   - 显示 Calendar / Reminders 的真实系统权限状态；
   - 只在用户明确操作后请求 macOS 系统权限；
   - 创建、修改、撤销 Agent 的容器、动作、字段和审批权限；
   - 处理待审批写入；
   - 查看脱敏审计记录和操作状态。

## 目标架构

```text
Agent
  ↓
Skill
  ↓
apple-connector CLI
  ↓
Local Application Core ──→ Ephemeral Management Web process (default TTL: 1h)
  ├─→ Swift Native Helper    ├─ System permission consent
  │                         ├─ Agent permission configuration
  │                         ├─ Pending approvals
  │                         └─ Audit and operation status
  ↓
EventKit
  ↓
Apple Calendar / Reminders
```

- **Skill** 只负责“什么时候、为什么、按什么流程”调用 CLI。
- **CLI** 是 Agent 和人类的唯一公开业务接口。
- **Application Core** 统一执行 schema 校验、Agent 身份验证、范围授权、幂等、审批、操作状态和审计。
- **Management Web** 是本机用户的按需、限时可视化管理面，不嵌入常驻 Application Core 进程，不是 Agent API，也不是远程服务。
- **Swift Native Helper** 是 Calendar / Reminders 的唯一生产数据访问路径，使用 EventKit 实现原生操作与纵深防护。

CLI 不直接调用 helper。当前已有范围授权、审批、持久化幂等操作、审计和 `outcome_unknown` 恢复均属于入口无关的安全语义，必须继续由 Application Core 强制执行。

## 当前实现与迁移判断

- `src/cli/index.ts` 已提供安装、服务生命周期、客户端、诊断、打开 Web 和 MCP 配置命令，但缺少 Calendar / Reminders 日常业务命令。
- `ServiceFacade`、`AgentOperations`、`Store` 和本地 Unix socket 服务已实现大部分共享应用核心，但应从 transport 目录收敛为清晰的 Application Core。
- 现有管理 Web 已具备 loopback 边界、一次性登录链接、Agent 授权、审批、审计和部分权限诊断能力，但目前嵌入常驻本地服务。v0.9.0 将 Web listener/session/static hosting 拆成独立临时进程，Application Core 与 EventKit helper 继续为 CLI 业务调用服务。
- Swift helper 已使用 EventKit 实现 Calendar / Reminders 查询和经验证写入，无需在 v0.9.0 从零重写原生层。
- JXA 仍有历史 provider 和诊断脚本；Calendar / Reminders 产品路径已是 Swift/EventKit helper。
- stdio MCP 是 v0.8.x 已发布能力。v0.9.0 对其做明确破坏性删除，并提供从 MCP 配置迁移到 Skill + CLI 的文档；不保留运行时兼容层。

## 详细方案

### 1. Skill 层

- 交付审阅友好的 `SKILL.md` 及最小必要参考材料，并将它们纳入 npm tarball 与发布验证。
- Skill 只调用公开 `apple-connector` CLI，不调用 helper JSONL、Unix socket 内部 RPC、SQLite、管理 Web API 或 JXA 脚本。
- Calendar / Reminders 选择：占用时间段、有开始/结束的安排优先 Calendar；待办、截止日期和完成状态优先 Reminders；无法判定时向用户求证。
- 时间自然语言由 Agent 理解；调用 CLI 前转换为带显式时区的 RFC 3339 instant，或明确的 date-only 与 IANA 时区。CLI 不理解“明天下午”等自然语言。
- 更新、完成或删除前先查询，并同时使用返回的容器 ID 与对象 ID；不按标题或名称猜测。
- 同名容器、多个匹配对象、时区、日期、上下文或写入意图不清时停止写入并要求澄清。
- 每个逻辑写入使用稳定幂等 key；超时、连接中断或 `outcome_unknown` 后按原 key 或 operation ID 查询，不换 key 盲目重做。
- Skill 可指导用户意图确认，但不能伪造 Web 中的策略批准或绕过 `approval_required`。
- Skill 不读取、打印、复制或在命令行中传递 token 内容。
- 首次初始化时，Skill 运行 `apple-connector agent init --json`，将返回的本地 Web URL 与剩余有效时间提供给用户，并明确说明需要用户在页面中完成系统权限与 Agent 权限配置。Skill 不代替用户操作管理页。
- 当用户要求修改 Agent 权限、处理审批或查看审计时，Skill 才按需运行 `apple-connector open --section <agents|approvals|audit> --json`，将限时 URL 和倒计时提供给用户。

### 2. CLI 主入口

可执行文件始终为 `apple-connector`。日常业务命令为：

```text
apple-connector calendar list-calendars
apple-connector calendar list
apple-connector calendar create
apple-connector calendar update
apple-connector calendar delete

apple-connector reminder list-lists
apple-connector reminder list
apple-connector reminder create
apple-connector reminder update
apple-connector reminder complete
apple-connector reminder delete

apple-connector operation get
```

管理入口保留并收敛为：

```text
apple-connector setup
apple-connector agent init
apple-connector start
apple-connector stop
apple-connector status
apple-connector open [--section permissions|agents|approvals|audit]
apple-connector doctor
```

- `setup` 只初始化 owner-only 本地状态并启动或复用 Application Core；不启动 Web，不自动请求 Calendar / Reminders 系统权限，不自动创建默认 Agent grants。
- `agent init` 启动或复用 Application Core，再启动一个独立临时 Web 进程并定位到初始化向导。`--json` 返回 `{ url, expiresAt, remainingSeconds, section: "permissions" }`，供 Agent 告知用户打开，不返回 admin token。
- `open` 只在用户需要管理时启动临时 Web 进程，并可定位到权限、Agent、审批或审计页面。人类互动调用可打开默认浏览器；`--json` 模式只返回 URL 与服务端到期时间，由 Agent 提供给用户。
- 业务命令使用用户在 Web 中创建的 Agent profile 和 owner-only credential file。支持明确 `--profile` / `--credential-file` 选择，不默认回退到 admin token。
- 写入需显式幂等 key。Agent/`--json` 路径要求调用方提供；人类可读互动路径可首次生成并显示，但重试不自动替换。
- 对象变更同时需要容器 ID 与对象 ID。CLI 不通过标题模糊更新、完成或删除。
- 标题、备注等私密输入支持从 stdin 或 owner-only JSON 文件读取。Skill 推荐流程不把私密内容放入进程列表可见的命令行参数。
- CLI 通过 Unix socket 调用同一本地 Application Core，保留单实例、持久化操作、审批和审计，不直连 helper。
- 人类可读与机器输出使用同一结果模型，只分离 renderer。

### 3. 统一 `--json` 契约

- 所有非互动公开 CLI 命令支持 `--json`，不只是 Calendar / Reminders 命令。
- stdout 只输出一个完整 JSON 文档，无 banner、日志、进度文本或 ANSI 格式；诊断信息进 stderr。
- 成功 envelope：`{ "ok": true, "data": ..., "meta": { "schemaVersion": 1 } }`。
- 失败 envelope：`{ "ok": false, "error": { "code": "...", "message": "..." }, "meta": { "schemaVersion": 1 } }`。
- 错误不回显 token、标题、备注或其他私密输入。
- 列表命令始终返回数组和显式分页元数据，即使为空也不改变类型。
- 定义稳定退出码：成功为 `0`，参数/权限/冲突类错误、服务不可用以及未知写入结果使用可区分的非零类别，并由文档和契约测试锁定。
- 产生一次性 Agent 凭证的管理流程将秘密直接写入 owner-only 文件；JSON stdout 只返回 profile、credential-file 路径和非敏感元数据。

### 4. 本地管理 Web

Web 继续只监听 loopback，需要 CLI 签发的一次性管理会话，并保留 Host、Origin、CSRF 和 session 保护。它不提供 Agent 调用 API，不提供局域网或公网访问。

#### 临时进程与过期

- 将当前嵌入常驻 local service 的 Admin Web Server 拆成独立进程。Application Core、Unix socket、操作状态和 EventKit helper 可继续为 Agent CLI 常驻；Web listener、静态资源服务和浏览器 session 只在管理期间存在。
- `agent init` 或 `open` 启动 Web 时，服务端写入不可由浏览器篡改的 `startedAt` 和 `expiresAt`。默认 TTL 为 1 小时，到期时间在本次 Web 进程生命周期内固定。
- 页面顶部在所有管理页持续显示“管理会话剩余 `HH:MM:SS`”倒计时和确切到期时间。倒计时以服务端 `expiresAt` 为权威值，不以前端累计计时作安全判定。
- 刷新页面、页面活动、API 调用或重新签发浏览器 session 都不延长 Web 进程的 `expiresAt`。需要继续管理时，到期后重新运行 CLI 显式启动新进程。
- 到期后，Web 进程先停止接受新管理变更，使当前及未使用的一次性链接/session 失效，关闭 listener，清理 Web PID/端口/会话元数据并退出。到期不停止 Application Core，不中断 Agent 正常 CLI 业务调用。
- 浏览器页面在倒计时归零后立即禁用表单与操作按钮，显示“管理会话已过期，请重新运行 `apple-connector open`”。这是用户提示；真正授权仍由服务端到期检查保证。
- 同一状态目录默认只允许一个 Web 进程。若已存在未过期实例，CLI 复用它的原定到期时间并签发新的一次性浏览器链接，不隐式延长 TTL；若已过期或不健康，清理陈旧状态后启动新实例。

#### 系统权限

- 分开显示 Calendar 与 Reminders 的 `not_determined` / `denied` / `restricted` / `write_only` / `full_access` 等实际 EventKit 状态，不以“helper 存在”或“曾经授权”代替实时检查。
- 初始化、服务启动、CLI 读操作和 Skill 都不自动弹出权限请求。
- 只有已认证 Web 中的明确按钮操作才调用 helper 请求系统权限，且 Calendar 和 Reminders 分开授权。
- 在请求前告知用途、将获得的 macOS 权限范围、与 Agent grants 的区别，以及如何在系统设置中撤销。
- 用户拒绝或系统限制后不自动重试，而是显示安全恢复指引和重新检查按钮。

#### Agent 权限配置

- 创建 Agent profile 时，用户选择 Calendar / Reminders 容器、允许的 read/create/update/complete/delete 动作、Calendar 字段级别、是否需要每次审批和有效期。
- 默认不给 Agent 任何 Apple 数据权限。删除 v0.8.x `agent init` 中自动为名为 `Agents` 的容器建立默认 grants 的主流程。
- 容器选择显示名称供人理解，但持久化与执行使用 EventKit 稳定 ID；同名容器不依赖名称猜测。
- 保存 profile 后，服务生成独立凭证并直接写入状态目录下的 owner-only 常规文件。Web 显示 profile 名、文件路径、权限摘要和调用方法，不显示 token 内容。
- profile 修改、撤销或凭证轮换立即影响后续 CLI 调用；待执行操作按已有策略版本规则取消或拒绝。
- 不允许 Agent CLI 创建、放宽或批准自己的 grants；这些动作只在已认证管理 Web 中可用。

#### 审批、审计与状态

- 待审批操作显示 Agent、provider、action、目标容器、字段级预览、创建时间和到期时间；敏感内容只在已认证本地会话中按必要范围展示。
- 批准只能改变已持久化不可替换操作的状态，不允许审批时替换 payload。
- 用户可查看授权、拒绝、成功、失败和未知结果的脱敏审计，并按 Agent、provider、action、outcome 和时间过滤。
- operation 页面显示 `prepared`、`approved`、`executing`、`succeeded`、`failed`、`cancelled`、`expired`、`outcome_unknown` 等稳定状态，对未知结果明确提示不要用新 key 重做。

### 5. 共享 Application Core

- 将当前位于 `src/transports/local/handlers.ts` 的应用 facade 与 transport-specific 解析分离，形成不依赖 CLI/Web 的 Calendar / Reminders query 和 mutation 用例边界。
- CLI 与 Web 仅做协议适配、身份来源分离和结果格式化，不复制授权、幂等、审批或审计。
- 共用同一套 Zod 请求/响应 schema 与稳定错误码；CLI JSON、内部 RPC 和 Web API 在各自协议外壳下保持一致业务语义。
- 所有 Agent CLI 读取都执行 client grant 过滤；所有写入都经持久化幂等状态机、执行前再授权、审批策略与审计。
- 保留现有操作状态和 crash recovery 语义；不将原生超时简化为可盲目重试的普通失败。
- 继续使用后台本地服务与 Unix socket，使 CLI 和 Web 共享一个操作序列、数据库和 TCC 权限承载进程。
- 保持 Agent 方法与 admin/Web 方法分集，并在服务边界强制，不只依赖 UI 隐藏按钮。

### 6. Swift Native Helper / EventKit

- Calendar / Reminders 生产路径只使用 EventKit，不直读 Apple 数据库，不修改 TCC，不以 JXA/Apple Events 作产品写入备用路径。
- helper 负责 EventKit 权限检查与请求、有界查询、稳定 ID 定位、容器/对象归属、可写性、重复项限制、写入与回读核验。
- helper 对时间、范围、分页、字段长度、协议消息大小和 action 白名单做纵深校验，不处理 LLM 语义。
- 保留有界、版本化的内部 JSONL 协议。它只供 Application Core 的 provider adapter 使用，不作公开 Agent API。
- Agent grants、凭证、审批、幂等和审计留在 Application Core；helper 不了解 Agent 身份，不复制 SQLite 状态机。
- 将当前单文件 Swift 实现小步拆分为 protocol/models、EventKit services 和 JSONL executable，以便单元测试；不借机全量重写。

### 7. 删除 stdio MCP

- 删除 MCP stdio 入口、server/tool 注册、MCP-specific transport 和相关测试。
- 删除 `apple-connector mcp`、`apple-connector mcp config` 以及为 host 生成 `mcpServers.apple-connector` 配置的逻辑。
- 删除 `@modelcontextprotocol/sdk` 依赖和仅为 MCP 服务的打包内容。
- 删除或改写 README、`docs/mcp-setup*`、`docs/agent-mcp-install*` 与发布验证中将 MCP 宣称为当前能力的内容。历史版本计划/进度文档保留历史事实，不追溯改写。
- `agent init` 不再生成 MCP 配置。将其删除或改名为清晰的 Web/profile 初始化流程，最终公开命令不保留“已配置 MCP”语义。
- 提供 v0.8.x → v0.9.0 迁移说明：从 Agent host 中手动删除旧 MCP server 条目，运行 `apple-connector setup` / `open`，在 Web 中配置 Agent profile，然后安装/启用 Skill。
- 不保留旧 `mcp` 命令的 tombstone、别名、专用错误或迁移输出。`apple-connector mcp` 与其他未知命令走完全相同的通用 unknown-command 路径。

### 8. 文档、打包与版本

- 更新中英文 README，以 Skill + CLI + Web 作为唯一当前工作流，明确系统权限与 Agent grants 是两个独立边界。
- 新增 CLI 命令参考、Skill 安装/使用说明和 v0.8.x MCP 迁移指南。
- 包描述、keywords 和首屏文案不再将 Apple Connector 描述为 MCP server。
- 将 package、lockfile、CLI、native helper handshake、capability 与版本文档同步到 `0.9.0`。
- 发布验证确认 tarball 不再需要 MCP SDK，不包含将 MCP 宣称为当前接入方式的文档；它应包含 Skill、CLI 文档、v0.8.x 迁移指南、Web 产物和编译后 helper，并从 tarball 安装验证 CLI `--json` 与 `open` 流程。

## 安全责任矩阵

| 规则 | Skill | CLI | Application Core / Web | Native Helper |
| --- | --- | --- | --- | --- |
| Calendar / Reminders 语义选择 | 主责 | 不处理 | 不处理 | 不处理 |
| 自然语言时间理解与歧义 | 主责 | 拒绝非结构化值 | 验证规范值 | 纵深验证 |
| Agent 身份与范围授权 | 不可绕过 | 提供 profile/凭证来源 | 主责，Web 配置 | 不承担 |
| 幂等、审批、状态、审计 | 指导正确调用 | 传递契约 | 主责，Web 审批/查看 | 返回精确结果 |
| 系统权限请求 | 不触发 | 仅打开 Web | 用户在 Web 明确触发 | 执行 EventKit 请求 |
| 容器/对象归属、可写性、重复项限制 | 遵守 | 不放宽 | 编排与错误语义 | 主责原子检查 |
| 凭证秘密保护 | 不读取 | 仅读 owner-only 文件 | 生成/轮换/撤销 | 不接触 Agent 凭证 |

## 实施阶段

### 阶段 A：锁定基线并收敛 Application Core

1. 为当前 local RPC、操作状态、授权、审批、审计和 helper 协议增加基线契约测试。
2. 定义入口无关的 Calendar / Reminders query 与 mutation 用例、schema 和错误。
3. 将 application facade 从 local transport 解析中分离，保持现有数据库与操作恢复语义。

### 阶段 B：Web 权限与 Agent 管理闭环

1. 将 Web 从常驻本地服务中拆为独立按需进程，收敛 `agent init` / `open` / 一次性管理会话流程。
2. 实现服务端默认 1 小时 TTL、本次进程内固定到期时间、全局倒计时、不滑动续期、到期拒绝与 Web 进程自动关闭。
3. 完成系统权限状态、用户明确权限请求和拒绝恢复引导。
4. 完成 Agent profile/grants/凭证文件、审批、operation 与审计的可达导航和负向权限测试。

### 阶段 C：CLI 业务命令与 JSON 契约

1. 建立可测试的 CLI parser/dispatcher/renderer，避免继续扩大单个 `switch`。
2. 实现 Calendar / Reminders / operation 命令，全部通过 Agent profile 调用共享 Application Core。
3. 固化 `--json` envelope、分页、stderr 边界、退出码和私密 stdin/file 输入。

### 阶段 D：Skill 与 MCP 删除

1. 实现 Skill 工作流、安全示例和固定情景验证。
2. 删除 stdio MCP 运行时、入口、依赖、测试与当前文档，不保留旧命令 tombstone 或专用错误提示。
3. 新增 v0.8.x MCP 到 v0.9.0 Skill + CLI 的迁移文档。

### 阶段 E：Native 收敛、集成与发布

1. 补齐 helper 内部 protocol/model/service 分层与纵深校验，不改变已验证 EventKit 语义。
2. 运行单元、CLI 子进程、local service、Web 安全、opt-in EventKit 和 tarball 安装验证。
3. 同步文档、版本、包内容与发布门禁。本计划不授权 npm publish、Git tag 或 GitHub Release。

## 验收标准

1. `apple-connector` 是唯一公开可执行文件，Calendar / Reminders / operation 命令覆盖已支持业务能力。
2. `apple-connector setup` 只初始化/复用 Application Core，不启动 Web；`agent init` 或 `open` 按需启动独立 loopback Web 进程，不自动获取系统权限或 Agent 数据权限。
3. 用户可在 Web 中分别查看和明确请求 Calendar / Reminders 系统权限，并获得拒绝/撤销恢复指引。
4. 用户可在 Web 中创建最小默认权限的 Agent profile，按稳定容器 ID、action、fields、approval 和有效期配置 grants，并获得不暴露 token 的 owner-only credential file。
5. Agent CLI 无法创建或放宽自己的 grants，无法批准自己的 pending operation，无法访问审计管理方法。
6. 所有非互动 CLI 命令的 `--json` stdout 可直接 `JSON.parse`，envelope、schema version、分页和退出码有契约测试。
7. 未授权容器/action、过期/撤销凭证、待审批写入、同 key 异内容和未知结果均由 Application Core 强制处理。
8. 返回丢失、超时、进程重启和同 key 重试不导致重复写入；`outcome_unknown` 可按 operation ID 查询且不自动重做。
9. helper 拒绝无系统权限、不可写、容器/对象 ID 不匹配、不支持的重复项、非递增时间范围和越界分页。
10. Web 可审批不可替换的 pending operation，并可按条件查看脱敏审计和操作状态。
11. Web 的服务端默认 TTL 为 1 小时，全页显示权威倒计时；刷新或活动不续期，到期后管理请求被拒绝、会话失效且 Web 进程退出，Application Core 和 Agent CLI 不受影响。
12. 产物不再注册 stdio MCP，不依赖 MCP SDK，不生成 MCP host 配置；旧 `mcp` 命令不存在且只按通用 unknown-command 处理。
13. Skill 只使用公开 CLI，其 Calendar/Reminders 选择、先查后改、歧义停止、显式时区、幂等重试和凭证保护有情景验证。
14. `npm test`、`npm run check:jxa`、opt-in `npm run test:native`、`npm run release:verify` 和 `git diff --check` 通过。
15. 从 v0.9.0 tarball 安装后，CLI 与 helper 报告 `0.9.0`，Skill、Web 产物和 CLI 文档存在，并完成一次不泄露个人内容的只读 CLI/EventKit 冒烟验证。

## 非目标

- 不在 CLI 或 helper 中实现 LLM/自然语言理解。
- 不将 Skill 当作强安全边界，不移除 Application Core 的授权、幂等、审批或审计。
- 不让 CLI 或 Web 直接访问 EventKit helper、Apple 数据库或 SQLite。
- 不新增 HTTP/SSE/remote MCP，不保留 stdio MCP 兼容 adapter。
- 不开放局域网、公网、跨设备或云端调用。
- 不恢复 Apple Notes，不支持重复事件/提醒的修改或删除，不新增邀请人/参与者管理。
- 不将本轮扩大为全 Swift 重写、GUI 重写或远程服务。
- 不自动修改 Agent host 配置；迁移文档只指导用户删除旧 MCP 条目并启用 Skill。
- 不在本计划下执行 npm publish、Git tag、GitHub Release 或真实个人数据写入。

## 主要风险与控制

- **MCP 删除的破坏性**：只在 README、release notes 和独立迁移文档中说明；代码不保留旧命令分支、tombstone 或运行时兼容层。
- **CLI 隐式越权**：业务命令必须使用 Agent profile，不回退 admin token；用服务边界和负向测试锁定。
- **系统权限与 Agent grants 混淆**：Web 分区展示两类权限，系统授权只由用户明确点击触发，Agent grants 默认为空。
- **Web 成为高权限入口**：保留 loopback、一次性链接、session、Host/Origin/CSRF 验证和 admin/agent 方法分集；增加直接 RPC 越权负向测试。
- **Agent 可见管理 URL 的边界**：按用户要求，`agent init --json` / `open --json` 会让 Agent 获得要转交给用户的限时 URL。Skill 明确禁止 Agent 自行访问或操作管理页，但产品不宣称能对拥有同一 macOS 用户任意 shell/浏览器控制权的 Agent 提供密码学隔离。
- **Web 临时进程残留或续期失控**：到期由服务端而非前端计时器判定；清理 PID/端口/session 状态，不允许页面活动隐式续期，并测试到期竞态与陈旧进程恢复。
- **凭证交付泄露**：凭证由服务直接写入 owner-only 文件，Web/CLI 只显示路径和指纹/元数据，不显示 token。
- **Skill 可移植性**：核心 Skill 只依赖公开 CLI/JSON，host-specific 安装包装与行为规范分开。
- **Native 拆分回归**：先锁定 helper 协议和 opt-in EventKit 行为，再小步拆分，不更改已验证数据语义。

## 开发门禁

本文是根据维护者反馈修订后的 v0.9.0 计划。由于架构范围已从“保留 MCP 兼容 adapter”变更为“删除 stdio MCP”，必须重新取得维护者对本版计划的明确批准。在批准前，不修改源代码、测试、Skill 产物、版本元数据、生成产物或发布资产。
