# Apple Connector v0.3.0 开发计划

状态：需求与实施计划已整理，尚未开始实现。
更新日期：2026-09-06
进度记录：[v0.3.0-progress.md](./v0.3.0-progress.md)

## 1. 目标与需求判断

用户通过一条命令启动 Apple Connector 本地后台服务，终端输出可打开的管理网页地址。打开网页后，可以完成客户端授权、查看和处理审批、查询审计记录、检查服务与数据源状态、运行受控诊断，并取得 MCP 接入配置和验证结果。

这一要求合理：连接器的授权、执行和审计由同一个服务维护，网页作为统一管理入口，能把现有分散在 CLI、JSON 参数和文档中的操作串成完整使用流程。v0.3.0 的重点是让已有能力可发现、可配置、可验证、可排障。

“暴露网页地址”在本版本中指本机 `127.0.0.1` 管理地址；MCP 继续通过本地 stdio 入口连接同一服务。管理网页地址不作为 MCP endpoint。

### 版本衔接

- 复用现有 TypeScript / Node.js / JXA、React 管理页、SQLite、CLI 与 MCP 架构。
- [v0.2.0 计划](./v0.2.0-plan.md)中的原生可靠性、Calendar 稳定定位及安装分发事项继续保留，不因新建计划而视为完成或取消。
- 管理功能可在这些问题调查期间推进；每个 Apple 动作仍按实测证据独立开放。不稳定、关闭和未验证的动作必须在网页、CLI 与 MCP 能力声明中一致呈现。
- 本计划不自动升级 package 版本，也不代表公开发布已获验收。管理流程完成与完整产品发布分别记录。

## 2. 当前基线与差距

| 项目 | 当前实现 | v0.3.0 需要补齐 |
| --- | --- | --- |
| 服务启动 | `setup` 初始化并启动；`start` 需要先 setup，成功后输出 PID | 一条命令完成必要初始化与启动，输出可用地址；重复启动返回现有实例 |
| 管理链接 | 启动时生成一次性链接；`open` 读取已有链接 | 链接已用或过期后可重新签发，无需重启服务 |
| 授权 | 客户端创建、编辑、撤销和凭证轮换已存在 | 用表单与容器选择替代必填 JSON，展示实际授权范围 |
| 审批与审计 | 有基础列表、批准、导出及清空功能 | 可理解的计划预览、拒绝操作、筛选分页、结果关联和未知状态提示 |
| 诊断 | CLI 探针和网页摘要已存在 | 网页触发、阶段进度、历史结果、精确恢复及脱敏导出 |
| MCP | `apple-connector mcp` 与客户端 token 已存在 | 网页生成配置、复制指引、接入验证与故障定位 |

代码复核发现现有 `start` 的就绪判定依赖 PID/socket，需补充真实服务和网页健康检查；一次性链接目前消费后无法重新签发，必须作为功能缺口修复。

## 3. 用户流程与命令约定

推荐入口：

```sh
apple-connector start
```

1. 首次运行时安全初始化必要状态、管理凭证与数据库；不自动授予客户端权限，不自动触发 Apple 数据读写。
2. 启动后台服务，确认本地 RPC 和管理网页均就绪后，输出服务状态、实际运行版本、PID、本机管理地址及登录引导链接。
3. 用户打开链接建立管理会话，进入概览页，按引导检查数据源、创建客户端、选择范围并生成 MCP 配置。
4. 用户在目标 MCP 客户端配置后执行一次受限请求，在网页确认请求结果与审计记录。
5. 关闭终端或网页不停止后台服务；通过 `apple-connector stop` 显式停止。

| 命令 | 预期行为 |
| --- | --- |
| `start` | 初始化必要状态并启动；已运行时复用现有实例，输出新的有效登录引导链接，不创建第二个服务 |
| `start --open` | 同上，并尝试打开默认浏览器；打开失败时仍输出链接，服务保持运行 |
| `open` | 为运行中的服务签发新的一次性登录链接并打开浏览器；失败时输出手动打开方式 |
| `open --print` | 仅输出新的一次性登录链接，适用于手动复制或无浏览器环境 |
| `status` | 显示真实健康状态、运行版本和不含凭证的网页地址；未登录浏览器显示重新登录指引 |
| `stop` | 停止服务并报告结果，保留授权、审计及未决操作；已停止时清楚报告当前状态 |
| `setup` | 保留兼容入口，复用初始化与启动流程，避免维护两套逻辑 |
| `mcp` | 保持 stdio 协议入口，stdout 仅承载 MCP 数据，诊断信息走 stderr |

默认使用随机可用 loopback 端口，输出实际地址。固定端口、远程访问及自动开机启动不属于本次必要范围。

### 管理会话

- 区分可重复访问的基础地址与短期、一次性的登录引导链接；已有有效会话刷新网页继续可用。
- 新链接只能经本机可信管理凭证签发，客户端 token 不具备签发权限。链接重签不重启服务，也不取消合法待执行计划。
- 登录链接沿用 10 分钟有效期，消费后立即失效并跳转到不含凭证的地址；会话沿用 8 小时有效期，支持退出登录。
- 持久管理员 token 不输出到网页地址、常规启动输出、MCP 配置或日志。保留 Host、Origin、CSRF、HttpOnly 与 SameSite 防护。
- 对过期、重复使用、服务重启和浏览器会话失效提供可操作提示，不停留在原始 JSON 错误或无限加载页面。

## 4. 网页功能范围

### 4.1 概览与数据源

- 展示服务健康、版本、运行时间、待审批数、未知结果数、近期脱敏错误与存储摘要。
- 分别展示系统权限、连接器授予的权限、每个动作的实际支持状态及最近验证时间。
- 支持状态至少区分可用、不稳定、未验证和关闭；例如 Reminders 创建不能仅因 writer 存在就宣称可靠。
- 提供首次使用清单：检查数据源 → 创建客户端 → 配置 MCP → 验证一次请求。
- 容器枚举为显式管理操作，仅返回配置范围所需元数据；无法读取时解释原因和恢复步骤，不猜测权限已授予。

### 4.2 客户端与授权

- 以表单配置名称、数据源、容器、动作、字段范围、审批方式和到期时间。JSON 可保留为高级入口，但不作为完成基本流程的前提。
- 展示有效授权摘要、撤销状态和策略版本；容器名称用于理解，实际授权继续使用 provider 已验证的定位方式。
- 编辑范围、撤销和轮换沿用服务端规则：旧 token 失效，受影响的未执行计划失效；已发出的原生调用不能被假定取消。
- 新建或轮换 token 仅在可信会话内当次展示；离开或关闭后不从服务端重新读取明文 token，丢失时通过轮换恢复。

### 4.3 审批与审计

- 审批前显示客户端、动作、目标容器、涉及对象数、拟写入字段、必要内容预览及到期时间；不只展示操作 ID。
- 提供批准与拒绝；明确批准是否仍需 MCP 客户端提交，保留现有“批准不可变计划，commit 才执行”的语义。
- 操作及审计列表支持按时间、客户端、数据源和结果筛选与分页，能通过操作 ID 查看相关记录。
- 明确区分成功、失败、拒绝、待审批和结果未知。未知结果显示核验/恢复入口，不提供盲目重放写入的快捷操作。
- 导出明确注明筛选条件、记录数量和是否完整；不将当前页导出称为全部记录。长期审计不保存正文或凭证。
- 清空审计保留显式确认，并说明不会删除未决操作；日志、逻辑审计量与数据库实际占用分别展示。

### 4.4 调试与诊断

调试以固定诊断动作和清楚的结果解释为核心，复用应用服务、权限与诊断日志，不提供任意 shell/JXA 执行。

| 诊断类型 | 行为与边界 |
| --- | --- |
| 基础检查 | 检查运行时、服务、数据库和桥接能力；默认不读个人内容、不写入 |
| 数据源检查 | 用户显式触发权限或目标容器检查；报告实际执行宿主、时间及结果，无法判定时显示未验证 |
| 受限读取调试 | 用户选择客户端及已授权范围，经同一应用服务执行有界读取，呈现脱敏结果摘要与错误 |
| 写入探针 | 用户明确选择专用测试容器并看到将执行的动作后启动；新建对象绑定预先持久化 UUID，按阶段展示耗时与核验结果 |
| 对账与恢复 | 根据已有诊断日志的容器、UUID/稳定 ID 精确恢复；歧义拒绝处理，缺少可靠身份的历史对象提示人工核验 |

- 有界执行，限制并发和调用频率；网页刷新或断开后仍可根据诊断 ID 查询状态。
- 原生超时不等同于未执行；清理也可能结果未知。不得自动重试写入或按标题前缀批量删除。
- 浏览器触发的诊断使用后台服务执行链路，记录宿主信息；终端检查成功不替代后台或 MCP 启动路径验证。
- 诊断导出仅含版本、阶段、耗时、状态和必要对象引用，不含 token、正文或未经脱敏的原生错误。
- 探针是验证能力的受控管理动作，其成功不自动解除产品写入门禁。

### 4.5 MCP 接入

- 专门页面解释：后台服务保持运行，目标客户端通过 `apple-connector mcp` 的 stdio 入口连接；网页 URL 用于管理。
- 为选定客户端生成可复制的通用 MCP 配置，包括实际可执行命令、`args: ["mcp"]`、`APPLE_CONNECTOR_TOKEN`，以及使用自定义状态目录时必要的 `APPLE_CONNECTOR_STATE_DIR`。
- 使用可验证的绝对启动路径，处理含空格路径和客户端不同 PATH 的情况；未安装时明确标注开发环境命令，不生成虚假的安装路径。
- token 仅在创建或轮换后的当次流程中可插入完整配置；后续展示占位符和轮换指引。配置不包含管理员凭证。
- 提供服务连通、客户端凭证、协议握手、工具发现及选定受限请求的分步验证；网页内验证不能冒充外部客户端已完成接入。
- 根据实际 MCP 请求显示最近访问时间和结果，不用不存在的长连接状态宣称“已连接”；至少记录一个真实目标客户端的端到端验收。
- 区分服务未启动、启动路径错误、token 无效、未授权、系统拒绝和能力关闭，并给出对应修复步骤。

## 5. 实施顺序与交付物

| 阶段 | 主要工作与文件范围 | 完成条件 |
| --- | --- | --- |
| P0 启动与登录 | `src/cli/index.ts`、`src/transports/local/lifecycle.ts`、本地 RPC 与 `src/transports/admin/server.ts` | 首次启动、重复启动、健康检测、输出 URL、会话重新签发完整通过 |
| P1 网页授权与能力 | `web/src/`、管理 handlers、provider capabilities | 无需 JSON 即可创建/编辑授权，系统权限与动作状态准确 |
| P2 MCP 引导 | 网页接入页、MCP 入口、必要管理接口 | 配置可用，诊断区分失败层次，一个真实客户端完成受限请求 |
| P3 审批与审计 | 管理 API、操作查询、SQLite 与网页 | 内容预览、批准/拒绝、筛选分页与导出范围正确 |
| P4 网页诊断 | 诊断编排、journal、管理 API 与网页 | 有界运行、阶段可见、刷新可恢复查看、精确恢复与脱敏成立 |
| P5 集成验收与文档 | 测试、双语 README、版本进度及安装验证记录 | 完成下列验收；真实验证与 mock 证据分开记录 |

优先交付“start → 打开网页 → 授权 → MCP 请求 → 查看审计”的完整路径，再完善高级诊断。复用已有模块，接口/schema 变更需要保持旧状态数据和未决操作的安全解释。

## 6. 验收标准

- [ ] 全新状态目录执行 `start`，无需先手动初始化数据库即可获得有效链接；RPC 与网页未就绪时不报告成功。
- [ ] 重复执行 `start` 不产生第二个实例；浏览器启动失败、端口变化、异常残留与不可写状态目录有明确结果。
- [ ] 已消费、过期或退出后的管理会话可通过 `open` 恢复；无须停止后台服务。未认证访问不能获取授权或审计数据。
- [ ] 无需编辑 JSON 即可创建受限客户端，编辑、撤销和轮换后服务端行为立即符合策略。
- [ ] 用户能在网页看到实际写入内容后批准或拒绝；过期、撤销、重复提交和未知结果处理保持正确。
- [ ] 生成的配置在一个真实 MCP 客户端完成握手、工具发现和一次授权范围内的读取；网页能关联该请求记录。
- [ ] 无效 token、越权请求、关闭动作均被拒绝，错误在接入页和审计中可理解；管理凭证不会进入客户端配置。
- [ ] 审计筛选、分页及导出在超出单页的数据量下正确，清空不丢失未决操作。
- [ ] 诊断覆盖成功、超时、写后响应丢失、清理未知和页面断开；真实写入实验只处理明确指定专用容器中的探针。
- [ ] 网页、CLI、MCP 对不稳定或关闭动作的声明一致；无数据检查成功不会被展示为原生能力通过。
- [ ] `npm run check`、适用的原生检查及 `release:verify` 通过，记录实际执行环境、跳过项与限制。
- [ ] 在最终安装路径验证后台服务、浏览器与目标 MCP 客户端的实际权限流程；若尚无安装产物，仅记录开发环境通过，公开发布仍未验收。

## 7. 依赖、阻塞与决策点

网页和启动入口没有已知不可解决的阻塞。核心工作是已有能力的整合及会话、健康检查、交互与接入体验补齐。

Reminders 原生超时、Calendar 稳定标识与共享/重复状态判定仍沿用 v0.2.0 的门禁。这些问题不阻止实现管理流程，但会限制网页可开放的动作和完整发布验收。页面应准确暴露限制，不能用诊断入口绕过授权或静默开放服务写入。

至少一个真实 MCP 客户端、最终安装方式和执行宿主须在集成验收时记录。Homebrew、签名、升级和用户验证继续由既有发布计划追踪；若需要改变原生技术路线、共享对象授权契约或原定产品范围，应先形成明确决策并更新相关计划。
