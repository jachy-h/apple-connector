# Apple Connector v0.12.0 计划：系统权限前置说明、授权名称展示、默认一年过期与使用文档

更新日期：2026-11-17
状态：已批准并实施（2026-11-17）
进度：[v0.12.0-progress.md](./v0.12.0-progress.md)

## 结论

本版本只改管理 Web 的展示与交互，以及一处增量 CLI section 白名单；不改变 Agent 读写协议、授权判断、native helper 协议、SQLite schema 或 grants JSON 结构：

1. 导航和页面默认入口从“权限”改为“系统权限”，并在页面上明确说明“先获得 macOS 系统权限，才能给 Agent 授权”，新增一张可读的四步流程图。
2. “已有 Agent 配置”的授权范围从 EventKit ID 改为显示容器名称；无法解析名称时回退显示稳定 ID。
3. 创建 Agent 配置时，过期时间默认填写一年后，仍允许用户修改。
4. 新增“使用文档”菜单，用简短步骤说明启动、授权、创建配置、交给 Agent、审批与审计。

版本建议升为 `0.12.0`。若维护者希望把这些调整并入尚未发布的 `0.11.0`，请在批准时说明。

## 现状

- 管理 Web 的导航仍使用 `t.permissions`，中文为“权限”；页面标题已使用 `t.systemPermissions`（“系统权限”）。
- 页面说明当前写成“macOS 权限与 Agent 授权相互独立”，与“系统权限是 Agent 授权前提”的需求不一致。
- `clients.list` 返回的 grants 只有 `containerIds`；UI 直接渲染 `<code>{id}</code>`。
- 创建表单的 `datetime-local` 没有默认值，必须手动选择过期时间。
- 管理 Web 只有“权限 / Agent 配置 / 审批 / 审计”四个页面。
- 工作树包含 v0.10.0、v0.11.0 的未提交改动；本版本叠加在其上，不回退或覆盖。

## 设计

### 1. “系统权限”页面与流程图

- 将中文导航文案 `permissions` 改为“系统权限”，英文改为“System permissions”；页面标题继续使用同一文案，默认页面仍为 `permissions`。
- 重写 `permissionsDescription`，明确关系：系统权限决定 Apple Connector 能看到哪些日历/提醒事项；Agent 授权只能在这个范围内继续收窄。
- 在权限卡片上方新增“授权顺序”区域，包含四步：
  1. `macOS 系统权限`：允许访问日历和/或提醒事项。
  2. `可见容器`：系统只返回已授权的日历与提醒事项清单。
  3. `Agent 授权`：在“Agent 配置”中选择容器、操作、字段和审批。
  4. `受限执行`：Agent 只能按凭据中的范围和审批规则操作。
- 步骤之间显示箭头；窄屏改为纵向排列，箭头向下。流程图使用普通 HTML/CSS，不引入图片或第三方依赖。
- 区域底部明确提示：未完成第 1 步时容器列表为空，无法创建 Agent 配置。
- 保留现有权限状态卡片、请求权限、系统设置深链和重新检查逻辑。

### 2. 授权范围显示容器名称

- 管理 Web 在进入“Agent 配置”页时，分别调用现有 `web.list_containers` 获取日历和提醒事项容器，建立 `provider:containerId -> name` 映射。
- 获取失败（例如系统权限尚未授予）时不阻塞页面，也不显示错误弹窗；相关 grant 回退显示稳定 ID，避免误导为名称解析失败是配置损坏。
- profile grant 的“范围”改为显示名称：
  - 能解析时显示容器名称，`title`/辅助文本保留稳定 ID，便于排查同名容器。
  - 不能解析时显示原 ID。
  - `*` 显示为“全部容器 / All containers”。
- 新增纯函数生成展示名称，便于测试；不修改 `clients.list` 返回结构，不新增 RPC，不重写历史 grants。

### 3. 过期时间默认一年

- 新增纯函数 `defaultExpiry(now)`，返回本地时区的 `YYYY-MM-DDTHH:mm`，用于 `datetime-local`。
- 按本地日历加一年；2 月 29 日落到下一年 2 月 28 日，避免日期溢出。
- 表单使用受控值，初始为一年后；创建成功后重置为新的“一年后”，而不是清空。
- 保留现有校验：过期时间必须是有效时间；用户仍可改成其他时间。

### 4. “使用文档”菜单

- 新增 `Page = 'docs'`，导航最后增加“使用文档 / Usage guide”。
- 页面内容保持简短：
  - 快速开始命令：`apple-connector setup`、`apple-connector open`、`apple-connector agent init`。
  - 三步接入：系统权限 → 创建 Agent 配置 → 把凭据文件路径交给 Agent。
  - 审批与审计：待审批写入进入“审批”页；审计只保留元数据。
  - 安全提醒：管理页仅监听 loopback；不要粘贴凭据内容；链接过期后重新运行 `apple-connector open`。
- 新增页面样式（命令块、步骤卡片），沿用现有黑白灰与蓝色状态 token。
- `?section=docs` 可直达；`apple-connector open --section docs` 加入 CLI section 白名单和帮助文本。该变更为增量允许值，不改变现有 section 行为。

### 5. 兼容性与安全

- 不改 `grantSchema`、`authorize`、Agent RPC、native helper 协议或数据库。
- 旧 grants 无需迁移；名称只在展示时按当前系统可见容器解析。
- 容器名称不是授权标识；授权、审计和 Agent 操作继续使用稳定的 EventKit ID。
- 版本元数据升为 `0.12.0`：`package.json`、`package-lock.json`、native helper `helperVersion`、`scripts/release-verify.mjs`、`docs/cli.md` 的当前版本描述。`protocolVersion` 与 CLI `schemaVersion` 不变。

## 测试计划

- i18n：中文导航为“系统权限”、英文为“System permissions”；中英文都包含流程图、使用文档、全部容器和一年默认值相关文案。
- 过期时间：固定本地时间下返回恰好一年后的 `datetime-local` 字符串；2 月 29 日回落到次年 2 月 28 日；保持本地时区、不返回 UTC `Z` 后缀。
- 容器名称：`provider:id` 命中时返回名称；未命中回退 ID；`*` 返回“全部容器”；日历和提醒事项同名不串用。
- Web 构建：`npm run build` 通过，权限页、Agent 配置页、使用文档页可渲染。
- 定向测试：`web-i18n`、CLI/onboarding 相关测试。
- 门禁：`npx tsc -p tsconfig.json --noEmit`、`npm test`、`npm run check:jxa`、`npm run release:verify`、`git diff --check`。

## 不在本版本范围

- 不新增 profile 编辑能力；创建仍是唯一授权入口。
- 不把容器名称写入 grants 或数据库，避免名称与稳定 ID 形成第二套授权标识。
- 不新增系统权限撤销 API，也不调用 `tccutil`。
- 不改审批、审计、Agent 读写安全和容器发现逻辑。

## 风险与待确认

1. 容器名称依赖当前 macOS 系统权限：权限被拒绝时只能回退 ID。这是系统限制，不额外持久化名称。
2. “一年”按本地日历计算，2 月 29 日按次年 2 月 28 日处理；如需固定 365 天，请在批准时说明。
3. 版本号按新功能建议为 `0.12.0`；如需并入当前未发布的 `0.11.0`，请在批准时说明。
