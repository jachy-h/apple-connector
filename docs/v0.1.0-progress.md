# v0.1.0 实施进展

更新日期：2026-09-06。对应计划：[v0.1.0-plan.md](./v0.1.0-plan.md)。

## 2026-09-06 本轮记录

- 已完成仓库盘点：M1 的服务、授权、计划和审计基础已具备；M2 尚缺既有对象变更与 Calendar 写入；M3 管理网页、M4 构建/CI 已完成基础实现。
- 本轮已在用户明确授权的三个 `Agents` 专用容器完成限定原生验证；所有测试写入均带 UUID 标记、限定范围回读并立即清理。既有对象变更与 Calendar 写入继续保持关闭。
- 已修复后台服务的单实例竞态：`service.lock` 以原子排他创建取得所有权，启动前不再仅凭 pid/socket 的存在性判断并删除 socket；死进程或损坏 lock 可恢复。覆盖“第二个 owner 被拒绝”和“陈旧 lock 回收”的测试已加入。
- **管理网页（M3 基础完成）**：React/Vite 静态资源随构建复制到 `dist/web`；后台服务额外绑定随机 loopback 端口。`apple-connector open` 使用服务启动时生成、仅内存有效且一次性的 bootstrap 链接创建 `HttpOnly; SameSite=Strict` 会话，随后从地址栏移除 secret。管理 API 严格校验 IPv4 Host、Origin 与 CSRF token，且仅可调用既有 admin 方法；页面包含连接与授权、数据源、操作记录、待确认四页。操作记录页显示逻辑审计占用、可导出当前显示的脱敏审计 JSON，并须明确确认才会清空审计；浏览器会话无法调用 agent 方法。
- **构建与 CI 门禁（M4 部分完成）**：`npm run build` 先构建管理网页再编译 TypeScript，并将网页复制到 `dist/web`；`npm run release:verify` 执行完整检查、验证 CLI/网页/JXA 资源并用 `npm pack --dry-run` 检查包内容。GitHub Actions 分别在 Node 24.20.0 的 Linux 上运行发布前校验、在 macOS 上运行无数据原生检查。发布 Release 与 Homebrew tap 尚未执行。
- `setup` 现只在新建管理员 session 时显示 token；重复运行不会重新泄露已有 token。macOS 首次 setup 会启动后台服务并打开一次性管理会话。
- **Calendar 读取（M2 完成）**：固定 JXA 脚本、唯一名称容器解析、时间范围/分页、严格返回 schema 与 busy 字段投影已接入服务和 MCP；同名、缺失日历会拒绝而非猜测。2026-09-06 获授权在 `Agents` 日历的限定窗口（前 30 天至后 365 天、最多 100 条）完成只读验证，测试不输出或持久化事件内容。Calendar 写入仍关闭。
- **测试容器 ID 发现**：新增 `apple-connector doctor --containers Agents` 固定诊断，仅按名称返回 Reminders 清单和 Notes 文件夹的 ID、名称、共享状态与匹配数量；它不打开提醒或笔记内容。首次实际调用若触发 macOS 自动化授权提示，需由用户在系统提示中决定是否允许。

正在进行 M0 原生能力验证，同时实现不依赖个人数据的基础模块。**M0 尚未整体通过，项目尚不能作为可发布连接器。** 三个用户指定的 `Agents` 测试容器已完成创建、限定范围重读和清理验证；没有访问其他容器或保留测试对象。后台服务、客户端管理与 MCP 入口可运行；已验证的 Reminders/Notes 创建 adapter 已接入，Calendar 写入和既有对象变更仍显式拒绝。

## 已落地代码

- TypeScript 严格模式、锁定依赖、构建和 Node 原生测试入口。
- 三个数据源独立目录和能力声明；三类受限读取已验证，Reminders/Notes 的受限创建已验证并接入，Calendar 与既有对象写入仍保持 unverified。
- 固定 JXA 调用器：stdin JSON、无 shell、操作白名单、请求标识/协议校验、输入输出上限、串行调用、超时、stderr 脱敏。
- 不读取个人数据、不请求授权的 JXA/EventKit 探测脚本。
- 不保存对象的 EventKit 文本/日期往返实验；独立 `npm run test:native` 入口。
- SQLite v1 schema、客户端 token 哈希、撤销、严格审计字段、年龄/行数/逻辑字节清理。
- 范围、动作、有效期与审批检查；忙闲输出采用字段白名单。
- 内部提醒创建操作服务：不可变计划、15 分钟有效期、幂等、管理侧审批、提交前授权复查、执行意图、写后核验、崩溃后 unknown 恢复。
- **本地后台服务**：Unix domain socket（状态目录 0700、socket 0600）上的 JSON RPC；agent 方法与 admin 方法分离鉴权（客户端 token 对管理方法不可达，admin token 对 agent 方法不可达）；错误统一映射；请求体 1 MiB 上限。
- **按能力门禁的 native writer**：Reminders 仅接入指定清单的创建与按 ID 核验；Notes 仅接入指定非共享文件夹的简单纯文本创建与按 ID 核验。Calendar 写入、提醒既有对象修改/完成和 Notes 既有对象编辑未接入，保持显式拒绝；不会伪装成功。
- **Reminders JXA writer**：固定脚本支持指定列表 preflight、创建及限定列表内按 ID 回读核验；输入只通过 stdin JSON，回执经 schema 校验。2026-09-06 的专用 `Agents` list 原生创建→回读→删除探针通过后已接入服务。
- **Notes JXA writer 与计划状态机**：指定且非共享文件夹的 preflight、简单纯文本笔记创建、按 ID 核验均由固定脚本实现；正文会被 HTML 转义。操作表升级至 v2，显式记录 provider，Notes 创建可走范围授权、审批、幂等、审计和 unknown-outcome 流程；2026-09-06 的专用 `Agents` folder 原生探针通过后已接入服务。
- **Notes 读取（M2 部分完成）**：`notes.list_folders`、`notes.get`、`notes.search` 已通过固定 Apple Events adapter、服务范围复查与 MCP 注册。客户端列目录仅基于其有效 `notes/read` grant；每次 get/search 再校验 folder ID。共享和锁定笔记被跳过；真实 `Agents` 文件夹已完成 writer→get→search→按 ID 清理的端到端验证。
- **Reminders 读取（M2 部分完成）**：`reminders.list_lists` 与 offset/limit 分页的 `reminders.list` 已通过固定 Apple Events adapter、服务范围复查与 MCP 注册。真实 `Agents` 列表的 ID、名称和空页读取已验证；iCloud 写后即时读可能滞后，因此不以即时可见性伪造写入核验。
- **CLI 服务生命周期**：`setup`（状态目录/管理会话/数据库）、`start`（分离后台进程、就绪轮询、防双开）、`stop`（SIGTERM 优雅关闭）、`status`（进程/DB/客户端/操作概览）。
- **CLI 客户端管理**：`client list`、`client create`（token 仅显示一次）、`client revoke`（pending 计划立即取消）。
- **MCP stdio 入口**：`apple-connector mcp` 连接后台服务，注册 `connector.capabilities`、`changes.prepare`、`changes.commit`、`operations.get` 四个工具；读取类工具在 M2 adapter 落地前不注册，避免把不可用能力伪装成可用工具。
- 管理网页已实施；admin RPC 面现包含 clients、审批、审计列表/统计/清空与操作列表，浏览器入口另有独立会话防护。
- 到期计划清理、终态幂等 30 天清理、未决操作 1,000 条与暂存正文 8 MiB 上限存在；后台服务启动后立即执行一次维护，之后每分钟清理到期计划、终态幂等记录和超预算审计。执行中及结果未知的操作不会被年龄清理。
- **运行日志保留**：后台服务按 5 MiB 轮换，最多保留 3 个文件（含当前文件），并清除超过 7 天的日志；日志故障不会使服务退出。
- 双语开发 README 已同步当前原型状态与可运行命令。

2026-09-05 通过 `/usr/bin/osascript -l JavaScript` 运行固定探测脚本，返回：

```json
{
  "eventKitBridge": true,
  "calendarAuthorization": 0,
  "remindersAuthorization": 0,
  "fullCalendarRequestSelector": true,
  "fullRemindersRequestSelector": true,
  "personalDataRead": false,
  "permissionsRequested": false
}
```

证明 JXA 可加载 EventKit、实例化 EKEventStore 并查询当前授权状态；不证明授权回调、查询、写入、TCC 归属或发布可用性。首次记录时两项 EventKit 状态为 notDetermined；后续运行会如实返回系统当前状态（本机一次运行观察到 calendarAuthorization 4、remindersAuthorization 3），这通常反映本机其他程序获得的 TCC 授权，固定探测脚本自身始终未调用 request selector、未读取个人数据。

本机脚本字典检查：

| 数据源 | 发现 | 下一步 |

| Calendar | 提供事件 recurrence、attendees、calendar writable；脚本字典与公开 EKCalendar.h 均未公开可靠共享标记 | 已向用户提出范围授权方案的取舍；不以 writable 推断个人日历 |

## 已知待办与风险

- 用户已明确授权三个 `Agents` 专用容器作为 M0 测试范围；后续仅操作其中由连接器新建且明确标注的测试对象，不访问其他容器。
- 不因脚本字典缺字段而静默删减版本目标；先验证替代 adapter，必要时明确更新计划。
- 暂存计划包含执行所需标题/正文，成功、撤销、结果未知和到期维护时清除；运行中的服务每分钟维护一次，服务停止期间到期的正文会在下次启动时立即清除。
- SQLite 使用 Node 内置 `node:sqlite`，已在 Node 24/26 验证，避免第三方原生 ABI 分发；实际长期磁盘占用仍需负载验证。
- 后台服务使用 `service.lock` 保证单一实例所有权；pidfile/socket 仍仅用于状态与连接。开机自启未实现，且不应在首版默认启用。
- 审计预算控制逻辑条目并执行 WAL checkpoint；运行日志已实施 5 MiB × 3 文件及 7 天保留。实际长期磁盘占用仍需负载验证。
- 不承诺 exactly-once、跨应用事务或自动恢复；写入结果未知时停止盲目重试。
