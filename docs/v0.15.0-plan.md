# Apple Connector v0.15.0 计划：简化接入链路，移除 `setup` 与 onboarding 握手

更新日期：2026-11-18

状态：已批准并实施完成（2026-11-18）

进度：[v0.15.0-progress.md](./v0.15.0-progress.md)

## 结论

按最新确认的方向，接入链路收敛为：

```text
1. 人类运行 apple-connector init
   → 自动打开本机管理页（从系统权限开始）
2. 人类在页面完成系统权限和授权
   → 页面生成一段 Agent 接入提示词
   → 人类把提示词复制给 Agent
3. Agent 按提示词保存授权码/凭据，并直接调用 apple-connector
```

同时删除已经冗余的 `setup` 命令，并删除不再需要的 onboarding 握手：

- 删除 `apple-connector setup`；
- 新增 `apple-connector init`，行为等同 `open`，默认打开管理页并自动打开浏览器；后续再次运行与 `open` 完全一致；
- 删除 `apple-connector agent init` 和 `apple-connector agent init-status`；
- 删除数据库 onboarding 表、onboarding RPC、Web bootstrap 中的 onboardingId；
- 页面创建授权后生成可复制的 Agent 接入提示词；
- 使用文档明确区分“面向人类”和“面向 Agent”。

版本建议：`0.15.0`。删除公开命令、数据库表和 RPC 属于破坏性变更。

## 命令面

### `apple-connector init`

- 用途：人类首次接入的唯一入口。
- 行为：
  - 调用 `startService()`，自动初始化状态目录、admin token、数据库；
  - 启动或复用管理 Web；
  - 默认打开 `permissions`（系统权限）页，与 `open` 的默认 section 一致；
  - 非 `--json` 且在 macOS 上时自动调用 `open` 打开浏览器；
  - `--json` 只返回链接，不弹浏览器，便于自动化。
- 返回：

```json
{
  "url": "http://127.0.0.1:<port>/?bootstrap=...&section=permissions",
  "expiresAt": 1790000000000,
  "remainingSeconds": 3600,
  "section": "permissions"
}
```

### `open`

- 保留，用于打开指定管理页：
  - `open` 默认权限页；
  - `open --section permissions|agents|audit|docs`。
- `init` 与 `open` 共享同一套管理 Web 启动和 URL 签发逻辑，避免两套实现。
- 默认 section 和行为完全一致；区别只在人类输出文案。`init` 是首次接入语义，`open` 是日常管理语义；后续再次运行 `init` 与 `open` 等价。

### 删除

- `setup`：没有独有行为，`start` 已包含初始化。
- `agent init`、`agent init-status`：由 `init` + 页面提示词取代。
- `agent` 命令组：上述两个子命令删除后不再保留空命令组。

### 保留

- `start`、`stop`、`status`、`open`、`auth show`、`skill path`；
- 全部 Calendar / Reminders / operation / doctor / version / help 命令；
- 写入仍要求 `--idempotency-key`，认证仍优先 `--auth-file` / `APPLE_CONNECTOR_AUTH` / `--auth`。

## 页面提示词

创建授权后，页面从 `clients.create` 结果中取得：

- `token`（授权码）；
- `client.name`、`client.grants`；
- `credentialFile`（服务已写入的 owner-only 文件路径）；
- 过期时间。

页面生成两种提示词：

### 1. 推荐：不含授权码的提示词

适用于 Agent 与本机 CLI 运行在同一台 Mac、且能读取本地文件的情况。

内容包含：

- 授权名称、范围、过期时间；
- `credentialFile` 绝对路径；
- 要求 Agent 使用 `--auth-file <path>`；
- 要求 Agent 不得读取后打印 token；
- 使用文档获取方式：
  - `apple-connector skill path --json`
  - `apple-connector open --section docs --json`
  - 或阅读 `docs/cli.md`；
- 验证命令：
  - `apple-connector auth show --auth-file <path> --json`
- 一次有界只读验证建议：`calendar list-calendars` 或 `reminder list-lists`。

### 2. 备用：含授权码的提示词

用于 Agent 宿主无法访问本机文件、只能接收文本凭据的场景。

- 包含完整 token；
- 明确要求 Agent 立即存入宿主 secret store 或写入 `0600` 文件；
- 明确要求不得回显、不得写入仓库、日志或聊天记录；
- 页面显示醒目警告：提示词包含 bearer token，粘贴后会留在聊天记录中。

默认复制按钮使用“不含授权码”的版本；含授权码版本需要用户明确点击。这样既支持用户要求的“带授权码提示词”，又不把泄露 token 变成默认路径。

### 提示词生成位置

- 新增纯函数 `buildAgentPrompt(input)`，放在 `src/web/`，便于单元测试。
- 输入：语言、授权名称、token、credentialFile、grants、expiresAt、是否包含 token。
- 输出：Markdown 文本。
- Web 页面只负责展示和复制，不在 React 组件里拼字符串。
- 页面仍保留一次性授权码展示，作为人工兜底；但主操作改为复制提示词。

## 移除 onboarding

当前 onboarding 的职责是“把页面创建的 credentialFile 关联回 CLI 的 `agent init-status`”。提示词直接携带 `credentialFile` 和授权信息后，这层关联不再需要。

### 数据库

- `src/storage/database.ts`
  - 新增 `user_version=7` 迁移：删除 `onboarding` 表及其索引。
  - 删除 `createOnboarding`、`onboarding`、`completeOnboarding`。
  - `deleteClient` 不再清理 onboarding 记录。
  - 旧库升级时直接丢弃 onboarding 数据；这些记录本来就是一小时临时状态，没有长期价值。

### RPC 与本地服务

- `src/transports/local/rpc.ts`
  - 删除 `onboarding.create`、`onboarding.status`、`onboarding.complete`；
  - 从 `localAdminMethods` 删除对应方法。
- `src/transports/local/handlers.ts`
  - 删除 onboarding schema、case 和处理逻辑。
- `src/transports/local/lifecycle.ts`
  - 删除 `createOnboarding`、`onboardingStatus`；
  - `openManagementWeb()` / `issueManagementUrl()` 删除 `onboardingId` 参数；
  - 不再向 `/control/issue` 附加 onboarding 查询参数。

### 管理 Web 服务

- `src/transports/admin/server.ts`
  - Session 和 bootstrap 删除 `onboardingId`；
  - `/control/issue` 不再接受或校验 onboardingId；
  - `/api/bootstrap` 不再返回 onboardingId；
  - `clients.create` 不再自动附加 onboardingId。
- `src/transports/admin/main.ts`
  - 删除 onboardingId 提取和 `onboarding.complete` 调用；
  - 继续写入 `profiles/<client-id>.token`；
  - `clients.create` 继续返回 `credentialFile`，供页面生成提示词。

### Web

- `web/src/main.tsx`
  - `Bootstrap` 删除 `onboardingId`；
  - 创建授权后保存 `credentialFile`；
  - 渲染两种提示词复制按钮；
  - 删除 `configurationComplete` 等“回复已完成”的 onboarding 文案。
- `src/web/i18n.ts`
  - 删除 onboarding 相关文案；
  - 新增提示词标题、复制按钮、安全警告和“不含授权码/含授权码”说明。

## 兼容性与迁移

- `setup`、`agent init`、`agent init-status` 删除后，旧脚本会得到 `invalid_request`，退出码 2。
- 旧数据库的 onboarding 表在升级时删除；没有需要保留的用户数据。
- 已保存的 `--auth-file` / `APPLE_CONNECTOR_AUTH` 授权码继续有效。
- 已保存的 `profiles/<uuid>.token` 文件继续有效。
- 不修改 grants、授权 token 格式、数据库的 clients/operations 结构、native helper 协议或 CLI `schemaVersion`。
- 当前未发布的 `0.14.1` 状态目录迁移保留在 `0.15.0` 中。

## 风险

- **把 token 粘贴到聊天记录**：含授权码提示词会进入 Agent 对话历史。因此默认推荐不含 token 的版本，含 token 版本必须由用户明确选择。
- **删除 onboarding 是跨层变更**：涉及数据库、RPC、Web 和 CLI；旧版 `agent init` 流程不再可用。
- **`init` 与 `open` 有部分重叠**：两者共享实现且默认行为一致，只保留不同的人类输出文案；不复制逻辑。
- **提示词内容可能随版本变化**：提示词不是协议，Agent 应以 `docs/cli.md`、Skill 和 `help` 为最终依据。

## 已确认

1. 在 `0.15.0` 一次性删除 `agent init` / `agent init-status` 和 onboarding，不兼容旧版本。
2. 提示词默认使用“不含授权码（credentialFile 路径）”，另提供“含授权码”备用按钮。
3. `init` 作为首次接入命令；后续使用 `open`，两者共享同一套 Web 启动和 URL 签发逻辑。
