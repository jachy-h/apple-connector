# Apple Connector v0.9.1 计划：通用 Skill 与闭环初始化接入

更新日期：2026-09-08
状态：根据维护者反馈修订，等待重新批准
进度：[v0.9.1-progress.md](./v0.9.1-progress.md)

## 版本决策

v0.9.1 解决的核心问题是：第一次接触 Apple Connector 的用户，不需要理解 CLI、内部容器 ID 或 credential 文件，就能让自己的 Agent 引导完成安装、把本机授权页面交给用户，并在用户回复后自行验证接入。

正式主线为：

```text
用户把安装指令交给 Agent
  ↓
Agent 检查环境、安装 CLI、加载通用 Skill
  ↓
Agent 运行 apple-connector agent init --json
  ↓
CLI 初始化本地服务并启动临时 Apple Connector Web
  ↓
Agent 把临时链接和说明交给用户，然后等待
  ↓
用户在同一台 Mac 的 Web 中完成系统权限和 Agent profile 授权
  ↓
页面提示“配置完成，请回到 Agent 回复：已完成”
  ↓
用户回复 Agent
  ↓
Agent 查询本次初始化状态，并进行真实的有界只读验证
```

Skill 面向任意 Agent，不以 OpenClaw、Codex、Claude Code 或其他单一宿主为产品边界。兼容对象是满足以下运行条件的 Agent：

- 与 Apple Connector 运行在同一台受支持的 Mac 上；
- 能执行本机 `apple-connector` CLI；
- 能读取符合 Agent Skills 规范的 `SKILL.md`，或允许用户/Agent 将该 Skill 导入宿主；
- 能保存本次 `agent init` 返回的非秘密初始化上下文，并在用户后续回复时继续流程。

“面向任意 Agent”是宿主中立的接口和文档目标，不等于对所有 Agent 产品逐一完成兼容认证。纯网页聊天、远程 Linux Agent、另一台设备上的 Agent，或不能执行本机命令的宿主无法直接访问这台 Mac 的 Apple 数据，文档必须明确说明。

本版不恢复 MCP，不增加云端接口、局域网监听、远程代理或静默 `postinstall`。本计划不授权 npm publish、Skill registry 发布、Git tag 或 GitHub Release。

## 当前实现与首次接入断点

本计划以当前 v0.9.0 工作区实现为事实来源；历史计划中的目标不能直接当作已实现能力。

| 已核对事实 | v0.9.1 影响 |
| --- | --- |
| npm metadata 限定 darwin / arm64；Native deployment target 为 macOS 14 | 接入页首屏明确 Apple Silicon Mac、macOS 14+ |
| Node 范围为 `>=24.20.0 <25 || >=26.8.1 <27` | Agent 必须先检查准确版本，不写模糊的“Node 18+” |
| npm 包含 CLI、编译后的 helper、Web 和 `skill/` | 普通用户不需要 clone 仓库或安装 Xcode；必须用打包产物验证 |
| `agent init` 当前会初始化状态、启动/复用服务及临时 Web，并返回 URL | 以它作为唯一推荐初始化入口；不要求用户先手动运行 `setup` |
| `--json` 不自动打开浏览器 | Agent 将 URL 和剩余时间交给用户；人类手动终端路线仍可自动打开 |
| Web 进程默认一小时固定 TTL，复用实例不会续期 | Agent 告知实际 `remainingSeconds`；链接过期时重新初始化 |
| Web 当前要求用户手填 Container IDs | 用户无法顺畅完成首次授权；Web 应直接列出可选日历/清单 |
| Web 创建 credential 后才返回文件路径，初始 `agent init` 不知道最终路径 | 用户只回复“已完成”时 Agent 无法继续；需要把 Web 创建结果绑定到本次初始化 |
| CLI `--profile` 根据文件名读取，Web credential 当前以 client ID 命名 | 不让用户猜 profile 名；初始化状态向 Agent 返回准确 `credentialFile` |
| `skill/SKILL.md` 缺少 YAML frontmatter | 补齐 Agent Skills 必需的 `name` / `description`，保持宿主中立 |
| README、CLI 和 Skill 文档当前只有概述 | 新增完整的用户页、Agent 安装页、命令参考与排障闭环 |
| 2026-09-08 查询 npm registry，`@jachy/apple-connector` 返回 HTTP 404 | 未发布前不能对用户宣称 npm 安装可用；发布可用性是最终门禁 |

当前工作区已有大量 v0.9.0 未提交改动。v0.9.1 实施必须只修改计划列出的文件和必要邻接代码，不覆盖或回退既有工作。

## 参考腾讯页面后的文档结构

参考地址：[腾讯文档接入页面](https://docs.qq.com/scenario/open-claw.html?nlc=1)。维护者提供的截图显示，该页面先列能力，再将安装、更新、token 恢复和开发者文档组织成可复制的独立卡片。Apple Connector 借鉴这个信息顺序，但不复制其 token 和无人值守授权方式。

### 首屏：先列用户能做什么

建议标题：「让你的 Agent 使用这台 Mac 上的 Apple 日历和提醒事项」。能力清单只陈述已经实现并验证的边界：

- 查看已授权的日历，以及指定时间范围内的日程；
- 创建、修改、删除非重复日程；
- 查看已授权的提醒事项清单及提醒；
- 创建、修改、完成、删除提醒；
- 为每个 Agent profile 限制容器、动作、Calendar 字段、审批方式和有效期；
- 在本机处理写入审批，并查看不保存标题、正文、备注和凭证的审计记录。

重复事件/提醒的修改删除、参与人管理、跨设备远程接入不列为当前能力。文档应说明 Connector 在本机访问 EventKit，但 Agent 宿主如何把结果发送给模型取决于该宿主，因此不能笼统宣称“数据绝不离开设备”。

### 接入区：三步即可完成

1. **复制安装指令给你的 Agent**：代码块提供复制按钮体验；指令使用当前项目的 Agent 安装说明，不包含版本号。
2. **在本机完成授权**：Agent 自动运行初始化并发回临时链接，用户只操作 Apple Connector Web 和 macOS 系统权限弹窗。
3. **回复“已完成”**：Agent 收到回复后查询本次初始化状态并做只读验证；用户不复制 credential 路径或 token。

后续另列三个短入口：复制更新/修复指令、撤销 Agent 或系统访问、查看完整用户及开发者文档。

## 详细方案

### 1. 宿主中立的 Skill

- `skill/SKILL.md` 使用通用 Agent Skills frontmatter，至少包含 `name: apple-connector` 和清晰的一行 `description`。
- Skill 主体只调用公开 `apple-connector` CLI，不依赖某个宿主的专有 tool 名、配置文件、Agent ID 或目录结构。
- 不在通用 Skill 中写 OpenClaw 专属 gating。若特定宿主支持额外 metadata，在不破坏通用解析的前提下放独立适配说明，不能让它成为主路径。
- 新增 `apple-connector skill path --json`，返回当前安装包内 Skill 目录的绝对路径和版本，避免 Agent 猜测 npm、NVM 或 Homebrew 的全局目录。
- Agent 根据自身宿主的官方方法导入该目录。能自动管理 Skill 的宿主由 Agent 执行；需要用户操作宿主设置时，Agent 给出准确路径并暂停等待。
- 文档按“通用接入协议 + 已验证宿主示例”组织。OpenClaw 可以作为示例，但不能占据标题、推荐路径或能力定义。
- 至少验证一种支持 Agent Skills 的真实宿主和一种“直接读取 `SKILL.md` 后执行”的通用路径；其他宿主不写成已经验证。

Skill 中固化以下行为：初始化时保存 `onboardingId`；把 URL 交给用户；明确要求用户授权后回复；收到回复前不轮询、不访问管理页、不尝试业务调用；收到回复后先检查初始化状态，再做只读验证。

### 2. 初始化上下文与 CLI 契约

`apple-connector agent init --json` 继续负责初始化本地状态、启动或复用 Application Core、启动或复用临时 Web。v0.9.1 扩展成功结果：

```json
{
  "ok": true,
  "data": {
    "onboardingId": "opaque-id",
    "url": "http://127.0.0.1:.../...",
    "expiresAt": 0,
    "remainingSeconds": 0,
    "section": "permissions"
  },
  "meta": { "schemaVersion": 1 }
}
```

- `onboardingId` 是不承载 credential 的不透明随机标识，用于把本次 CLI 初始化与 Web 中新建的一个 Agent profile 关联。
- URL 继续使用现有一次性本机管理登录保护，并携带本次 onboarding 上下文。Web 进程可以复用，但不同初始化记录不能互相覆盖。
- onboarding 与当前 Web 到期时间绑定。链接过期且未完成时状态变为 `expired`；重新运行 `agent init` 会创建新 ID，不复用旧初始化上下文。
- 同一次 onboarding 只允许完成一次 profile 创建；重复提交返回原完成状态，不能生成第二枚 credential。
- 支持同时存在多个初始化记录；每条记录只能返回自己关联的 profile 元数据和 credential 文件路径。
- onboarding 记录存入 owner-only 本地状态，不包含原始 credential；过期未完成记录可安全清理。

新增机器接口：

```text
apple-connector agent init-status --id <onboarding-id> --json
```

返回状态 `pending | configured | expired | failed`。`configured` 返回 client ID、profile 显示名、授权摘要和准确的 `credentialFile` 绝对路径，但绝不返回 token 或文件内容。`pending` 明确提示用户尚未完成；`failed` 只返回脱敏错误。

Agent 收到用户“已完成”后才调用 `init-status`。如果状态仍是 `pending`，Agent 说明页面尚未完成并继续等待；如果 `expired`，重新运行 `agent init` 并给用户新链接；如果 `configured`，使用返回的 credential 路径验证。

### 3. 本机 Web 初始化向导

初始化链接进入明确的顺序流程，而不是把用户直接丢进通用管理页面：

1. 显示当前 Calendar / Reminders 系统权限，仅在用户点击对应按钮后请求 macOS 权限。
2. 按 provider 读取并列出用户已授权可见的日历或提醒事项清单，让用户直接勾选。增加仅限认证管理 Web 的 `web.list_containers`；它复用 EventKit reader 空 scope 枚举语义，不开放给 Agent transport。
3. 选择允许的 read/create/update/complete/delete、Calendar busy/full 字段、每次审批/范围内自动执行以及有效期。默认建议从一个容器的 read 开始，但最终权限由用户明确选择。
4. 用户确认后创建一个 profile，将 credential 写入 owner-only 常规文件，并把 client/profile/credential path 关联到 onboarding 记录。
5. 成功页只显示 profile 和授权摘要，以及「配置完成，请回到 Agent 回复：已完成」。不要求用户复制路径，不展示 token，也不要求用户把管理 URL 再发回 Agent。

同名容器同时显示稳定 ID 以供区分，保存时只保存稳定 ID。尚未授权、空列表、读取失败和管理会话过期均给出可恢复下一步。容器可写性目前没有出现在 helper 的列表协议中，本版不为文档任务扩大该协议；实际写入仍由已有的执行前可写性检查保护。

通用 `apple-connector open --section ...` 继续用于权限管理、profile 管理、审批和审计，不创建 onboarding 记录，也不作为首次接入入口。

### 4. 用户回复后的验证

安装成功、Web 能打开、profile 已创建都不是最终“接入成功”。Agent 必须在收到用户回复后完成：

1. 运行 `agent init-status`，取得与本次 onboarding 绑定的 credential 路径和授权摘要。
2. 根据已授权 provider 调用 `calendar list-calendars` 或 `reminder list-lists`。
3. 对 Calendar 使用带显式时区的短时间窗口做有界读取；对 Reminders 使用较小 limit 做有界读取。
4. 向用户报告已连接的 provider、授权容器和允许动作。空结果属于成功读取，但必须区分“容器内没有项目”与“没有授权预期容器”。

首次验证禁止创建、修改、完成或删除真实项目。写操作只在用户之后提出明确业务意图时进行，并继续遵循稳定 ID、幂等 key、审批与 `outcome_unknown` 恢复规则。

### 5. Agent 安装指令

维护者修订（2026-09-08）：可复制指令不包含固定版本号。Agent 必须先检测当前项目是否已经通过 `npm link` 提供 `apple-connector`；若没有，则在当前项目中运行 `npm install`，而不是安装 npm registry 上的某个版本。此路线用于当前项目开发/验证；对外已发布版本的安装方式在发布后另行明确。

README 提供一段宿主中立的可复制提示词，不包含版本号：

可复制提示词必须直接列出要执行和验证的步骤，不能要求 Agent 阅读仓库中未提供或无法解析的“安装说明”。采用简短的有序格式：每步以明确动词开始；命令使用行内代码；命令后说明它完成或检验什么；包含兼容性检查、`npm link` 检查与当前项目 `npm install` 回退、Skill 路径发现/加载、初始化与等待、用户回复后的状态检查和有界只读验证。不得包含版本号、registry 安装命令、凭证内容或测试写入。

Agent 安装文档必须逐步要求 Agent 报告：环境检查结果、CLI 版本、Skill 路径、宿主加载结果、初始化链接、等待用户、初始化状态和只读验证结果。若宿主无法持久加载 Skill，Agent 应说明限制并仍可在当前会话按 `SKILL.md` 执行，不伪造安装成功。

### 6. 更新、撤销与手动路线

- **更新/修复**：开发/验证路线先重新检查当前项目的 `npm link`，未链接时在当前项目运行 `npm install`，再重新解析 `apple-connector skill path --json` 并按当前宿主的方法更新 Skill；不假定所有宿主有同名 update 命令。
- **撤销 Agent 访问**：运行 `apple-connector open --section agents`，由用户撤销 profile。删除 credential 文件不能替代服务端撤销。
- **撤销系统访问**：引导用户到 macOS「系统设置 → 隐私与安全性」修改 Calendar / Reminders 权限。
- **手动安装**：为不希望 Agent 安装的用户提供环境检查、npm 安装、Skill 路径、宿主导入、初始化、授权和只读验证的完整命令。
- **故障恢复**：按现象覆盖 npm 版本不存在、Node/平台不兼容、命令找不到、宿主无法加载 Skill、链接过期、浏览器不在同一台 Mac、系统权限拒绝、容器为空/重名、用户回复后仍 pending、credential 文件不存在、授权到期/撤销、等待审批和未知写入结果。

故障文档不得建议读取 token、关闭系统保护、开放本地端口、把 credential 内容粘贴给 Agent，或用新幂等 key 重试未知写入。

## 实施阶段

### 阶段 A：锁定通用契约

1. 定义 Agent 运行条件、Skill frontmatter、`skill path`、onboarding 状态与 JSON schema。
2. 为 `agent init` 当前初始化/启动 Web 行为建立基线测试，确保精简文档不依赖隐含 `setup`。
3. 定义 onboarding 的生命周期、并发、过期、重复提交和脱敏规则。

### 阶段 B：完成初始化闭环

1. 创建 onboarding 记录并扩展 `agent init --json`。
2. 将一次性 Web 链接绑定 onboarding，新增容器列表选择和顺序向导。
3. 创建 profile 后原子关联 credential 路径并标记 configured。
4. 实现 `agent init-status`，保证只返回非秘密结果。

### 阶段 C：通用 Skill 与接入文档

1. 补齐通用 `SKILL.md`，实现 `skill path`。
2. 编写中英文 README、用户指南、Agent 安装说明、Skill 与 CLI 参考。
3. 用能力清单、三步接入、更新、撤销和深入文档的结构组织首页。
4. 添加已实际验证的宿主示例；未验证宿主只说明通用要求。

### 阶段 D：端到端验证与发布准备

1. 从 v0.9.1 tarball 安装到隔离 prefix，验证 CLI、helper、Web、Skill 路径及所有文档引用。
2. 使用隔离状态目录验证 pending → configured、expired、并发 onboarding、重复 Web 提交、状态脱敏和 credential 权限。
3. 在至少一种真实 Agent Skill 宿主验证“Agent 发链接 → 用户回复 → Agent 再验证”的完整交互；记录宿主与版本。
4. 运行 `npm test`、`npm run check:jxa`、适用的 `npm run test:native`、`npm run release:verify` 和 `git diff --check`。
5. 最终检查 npm registry 能安装 `@jachy/apple-connector@0.9.1`，且 tag 绑定的 Agent 文档和 tarball 内容一致。对外发布操作另行取得明确授权。

## 验收标准

1. README 不以任何单一 Agent 宿主命名产品，Skill 不依赖宿主专有 API 或目录。
2. Agent 可通过 `apple-connector skill path --json` 找到随包 Skill，并按宿主能力加载。
3. `agent init --json` 一次完成本地初始化和 Web 启动，并返回 URL、有效期及唯一 onboarding ID。
4. Agent 明确告知用户在同一台 Mac 打开链接、完成授权后回复，并在回复前停止后续验证。
5. 用户无需填写内部容器 ID；可在 Web 中看到并选择已授权日历/清单。
6. Web 完成页只要求用户回复“已完成”，不要求复制 credential 路径、token 或管理 URL。
7. `agent init-status` 将本次初始化准确关联到唯一 profile，configured 时返回 credential 文件路径但不返回其内容。
8. 多个并发初始化不会串联 profile；过期、重复提交和失败均有稳定状态与恢复方法。
9. 用户回复后，Agent 先检查状态，再使用正确 credential 完成有界只读查询；没有默认测试写入。
10. 系统权限、Agent grants、管理 Web 会话和 credential 文件在文档中明确区分。
11. 中英文文档的命令、页面标签、JSON 示例与实际实现一致，示例可在打包产物中复现。
12. npm tarball 包含通用 Skill 和完整接入文档，版本、helper handshake 与发布验证统一为 0.9.1。
13. 自动化检查通过；真实系统权限和 Apple 数据验证若未获明确授权，必须单独标为未验证，不能由 mock 测试替代。

## 非目标

- 不承诺所有现有 Agent 产品都已逐一验证。
- 不让远端 Agent 直接访问本机 EventKit，也不增加公网或局域网 API。
- 不让 Agent 代替用户点击 macOS 权限或配置管理页面。
- 不把 Skill 当作安全边界；授权、审批、幂等、审计继续由 Application Core 强制执行。
- 不新增自然语言解析到 CLI，不恢复 stdio MCP。
- 不在首次接入中写入真实日历或提醒事项。
- 不在本计划批准时自动执行 npm、Skill registry 或 GitHub 发布。

## 主要风险与控制

- **“任意 Agent”被误解为远程/纯聊天兼容**：首屏明确同一 Mac、本机命令和 Skill 加载三个条件；宿主验证与通用兼容声明分开。
- **用户回复与错误 onboarding 串联**：Skill 保存本次 onboarding ID，状态查询必须显式传 ID；Web 原子关联且单次完成。
- **Agent 提前轮询或绕过用户操作**：Skill 明确在用户回复前停止；Web 仍要求本机一次性认证和用户明确点击。
- **credential 泄露**：CLI/Web 只传路径与摘要，日志、JSON、复制内容和错误不返回 token；文件保持 owner-only。
- **链接失效**：Agent 转交服务端实际剩余时间；过期状态指导重新初始化，不隐式延长现有 Web TTL。
- **文档先于发行可用**：固定版本安装说明、npm registry、tag 和 tarball 在发布前联合验证；未发布稿不宣称可执行。
- **宿主安装差异**：通用入口返回 Skill 路径；宿主专属步骤只在实际验证后加入示例。

## 开发门禁

维护者反馈已将范围从“OpenClaw 优先接入并由用户回传 credential 路径”调整为“宿主中立 Skill，用户只回复完成，Agent 根据 onboarding 上下文继续验证”。这是实质性方案变化。

依照仓库 `AGENTS.md`，必须重新取得维护者对本版计划的明确批准。在批准前，不修改正式文档、Skill、源码、测试、版本元数据、生成产物或发布资产。
