# Apple Connector v0.10.0 计划：Reminder Patch、结构化 Due 与重复标记

更新日期：2026-11-15
状态：已批准并实施（终验待本机 Terminal 复跑）
进度：[v0.10.0-progress.md](./v0.10.0-progress.md)

## 结论

本版本为 JachyBot 提供三项能力，并保持 Apple 为唯一数据源：

1. 新增 `reminders.patch` / `reminder patch`，只修改调用方明确提供的字段；现有 `reminders.update` 保持完整替换语义不变。
2. `reminder list` 返回结构化 `due`，区分 date-only、floating 和 instant，并返回 `recurring`。
3. 补齐清空 due、取消完成、重复提醒稳定错误码、ID 稳定性边界和 Skill 契约。

这是一次跨层变更，涉及 native helper JSONL 结果、TypeScript schema、Agent operation、CLI、Skill、测试和发布版本。`reminder list` 的 `due` 从字符串直接替换为对象，不保留旧字段；JachyBot 尚未上线，按已确认决策执行破坏性替换。

工作树当前已有未提交改动（`docs/install-for-agent*.md`、`skill/SKILL.md`、`src/transports/local/handlers.ts`）。实施必须叠加在这些改动之上，不得回退或覆盖。

## 已确认决策

- 保留 `reminders.update` 的完整替换语义；新增独立的 `reminders.patch`，不采用 `set_due`。
- `reminder list` 的 `due` 直接替换为结构化对象，不提供旧字符串兼容层。
- due 增加 `kind: "floating"`，用于 EventKit 中无时区的 wall-clock due。
- ID 保证范围限定为“同一本地 EventKit store 内正常编辑稳定”；full sync、账户重置或数据重建后可能失效。
- `patch` 包含清空 due（`due: null`）和取消完成（`completed: false`）。
- CLI 正式模板中 `title`/`body` 只通过 owner-only `--input` 文件传入；`--title`/`--body` 不进入 `reminder patch` 契约。

## 契约设计

### 1. 结构化 due

公开 due 类型：

```json
{ "kind": "date", "date": "2026-11-20" }
{ "kind": "floating", "date": "2026-11-20", "time": "17:00:00" }
{ "kind": "instant", "at": "2026-11-20T17:00:00+08:00", "timeZone": "Asia/Shanghai" }
null
```

- `date`：EventKit components 只有年月日，没有 hour/minute/second，也没有时区。
- `floating`：有 hour/minute/second，但 `dueDateComponents.timeZone` 为 nil。
- `instant`：有 hour/minute/second，且有可识别的 IANA 时区。
- `null`：没有 due。
- 输入接受三种 kind；输出也返回三种 kind，保证读回可以原样再写回。
- `time` 输出固定为 `HH:mm:ss`；输入接受 `HH:mm` 和 `HH:mm:ss`，缺省秒为 `00`。
- `instant.at` 按组件时区输出带 offset 的 RFC 3339，秒精度；输入继续允许小数秒。
- 若 EventKit 返回的时区标识不是已知 IANA zone（例如固定偏移标识），输出降级为 `floating`，避免伪造 IANA 名称。该行为会写入文档。
- `dueDateComponents` 的构造和读取统一使用 Gregorian 日历，修复当前 date-only 分支使用 `Calendar.current` 的潜在非公历问题。
- `floating` 只描述 wall-clock，不声称绝对时刻；JachyBot 需要绝对时刻时应使用 `instant`。

### 2. `reminder list` 输出

每个 reminder item 增加：

```json
{
  "id": "...",
  "listId": "...",
  "title": "...",
  "body": "...",
  "completed": false,
  "due": { "kind": "date", "date": "2026-11-20" },
  "recurring": false
}
```

- `due` 使用上面的结构化类型或 `null`。
- `recurring` 由 `recurrenceRules` 非空推导，布尔值即可，不返回完整 recurrence rule。
- CLI envelope `schemaVersion` 升为 `2`。
- native helper `protocolVersion` 升为 `2`，避免旧 helper 与新客户端静默交换不同的 `due` 形状。
- `EventKitHelperClient` 的 `VERSION` 同步为 `2`，并在 `hello` 握手时校验。

### 3. `reminders.patch`

新 operation kind：`reminders.patch`。

```json
{
  "kind": "reminders.patch",
  "containerId": "<listId>",
  "id": "<reminderId>",
  "title": "optional",
  "body": "optional, empty string clears",
  "due": { "kind": "instant", "at": "...", "timeZone": "Asia/Shanghai" },
  "completed": false
}
```

规则：

- `title`、`body`、`due`、`completed` 全部可选，但至少提供一个；否则 `invalid_request`。
- 字段缺省 = 保持原值；`body: ""` 清空备注；`due: null` 清空截止时间；`completed: true/false` 设置完成状态。
- `due` 与 `title`/`body`/`completed` 可以同时出现。
- 授权动作映射到现有 `update`，不新增 grant action。
- 幂等 key、审批、`operations.submit`、`operation get`、审计和 `outcome_unknown` 状态机复用现有 AgentOperations。
- 写入通过 native helper 的 `reminders.patchVerified` 单次完成：解析目标、检查写权限、拒绝重复提醒、应用字段、保存、重读并验证。
- 返回 `{ id, containerId }`，其中 `id` 必须是重读后的 `calendarItemIdentifier`；若与输入不同，返回 `outcome_unknown`。
- 验证必须覆盖：ID、列表、所有显式字段的期望值、所有缺省字段保持原值；due 使用语义比较而非 `Date` 直接相等。
- `reminders.update` 保持现状：仍要求 `title`、`body`、`completed` 完整替换；Skill 建议优先使用 `patch`，但不得改变 update 行为。

### 4. CLI

新增命令：

```text
apple-connector reminder patch \
  --list-id <listId> \
  --id <reminderId> \
  [--due <RFC3339> | --due-date <YYYY-MM-DD> | --clear-due] \
  [--time-zone <IANA>] \
  [--completed | --not-completed] \
  --input <file> \
  --idempotency-key <key> \
  --profile <profileId> \
  --json
```

- `--due`、`--due-date`、`--clear-due` 三者互斥。
- `--completed` 与 `--not-completed` 互斥；都不传时保持原值。
- `title`、`body` 以及 floating due 只从 `--input` 读取。
- `reminder patch` 显式拒绝 `--title`/`--body`，提示改用 `--input`，避免私密文本进入 argv。
- `--input` 可以包含 `title`、`body`、`due`、`completed`；显式 CLI 标志覆盖同名 input 字段。
- `reminder update` 的 CLI 参数保持不变。
- CLI 帮助文本增加 `reminder patch`，并继续强调私密字段走 `--input`。

### 5. 重复提醒

- `list` 返回 `recurring`。
- native helper 的 patch/update/complete/delete 对重复提醒返回稳定错误码 `unsupported_operation`，而不是只依赖 `invalid_request` 文本。
- `Failure` 增加 `unsupported` 分支，映射到 `unsupported_operation`；`EventKitHelperClient` 接受该错误码。
- JachyBot 可据 `recurring=true` 禁用编辑/完成/删除；若状态过期，收到 `unsupported_operation` 后重新 list 并刷新 UI。

### 6. ID 保证范围

写入 `capabilities`、Skill 和 CLI 文档：

> `calendarItemIdentifier` 在同一本地 EventKit store 内用于定位和编辑是稳定的；正常修改标题、备注、due、完成状态不会改变它。完整同步、账户重置、数据重建或重新安装可能使其失效。失效时应重新 list 解析，不得把它当作永久主键或直接把“查不到”视为用户删除。

JachyBot 的映射建议：

- `appleReminderId` 作为外部身份主键；
- `listId` 作为当前所在列表属性，而不是身份的一部分；
- 用户移动提醒到其他列表时，更新映射中的 `listId`，不要新建一条身份。

## 测试计划

### Phase 0：EventKit 实测（写源码前）

在专用测试列表（`APPLE_CONNECTOR_REMINDERS_TEST_LIST_ID`）用一次性探针验证：

1. date-only due 写入后，components 是否只有年月日、hour 是否为空、timeZone 是否为 nil。
2. `Asia/Shanghai` instant due 写入后，重新 fetch 是否保留时分秒和时区标识；换一个新进程重新读取是否仍保留。
3. floating due（有 time/hour 但 timeZone nil）写入后能否原样读回。
4. due 修改后 ID 是否不变；complete 后 ID 是否不变；delete 后 ID 是否不再出现。
5. 重复提醒的 `recurrenceRules` 是否非空，helper 的写拒绝是否可稳定触发。

如果 EventKit 实际不保留 IANA 时区：

- 读回降级为 `floating`，文档明确“wall-clock 保留，IANA 时区不保证回读”；
- 不引入连接器 sidecar，不做第二数据源；
- 在进度文档记录实测矩阵，并据此调整验收。

Phase 0 需要 Reminders TCC 权限；按 v0.9.7 约定从本机 Terminal 运行，不使用 agent 的 SSH 会话。

### 单元与回归

- due schema：date/floating/instant、null、互斥、非法时间、非法时区。
- patch schema：至少一个字段、`due:null`、`body:""`、`completed:false`、未知字段拒绝。
- AgentOperations：patch 映射 `update` 授权、幂等 key 重放、同 key 不同 payload 冲突、receipt ID 校验。
- Provider：结构化 due/recurring 解析、非法 helper 输出拒绝、patch receipt。
- CLI：`parseDuePatch` 的 `--clear-due`/互斥、patch 拒绝 `--title`/`--body`。
- Skill 契约：patch 模板、无 `--title`/`--body`、floating/recurring/ID 边界说明。
- 删除 JXA reader 后，notes-service 测试改用 stub。

### Opt-in native 测试

新增 `tests/native/reminders.test.ts`，仅在 macOS 且设置测试列表时运行：

- create date-only → list → patch due → list → complete → delete；全程断言 ID 一致、其他字段不变、删除后 ID 不存在。
- create instant（含 IANA 时区）→ list，按 Phase 0 结果断言 instant 或 floating。
- create floating → list 读回 floating。
- 重复提醒探针：创建带 recurrence 的探针，list 断言 `recurring=true`，patch/complete/delete 断言 `unsupported_operation`，finally 清理。
- 所有探针使用 UUID 标题，`finally` 按 ID 删除；清理失败使测试失败。

## 验收标准

1. `reminder list` 返回结构化 `due`（date/floating/instant/null）和 `recurring`，`schemaVersion=2`。
2. date-only 读回仍是 date-only；instant 按 Phase 0 结论保留时间与时区或明确降级为 floating；floating 读回仍是 floating。
3. `reminder patch --due` 只改 due，标题、备注、完成状态保持不变，ID 不变，保存后重读验证通过。
4. `reminder patch --clear-due` 清空 due；`--not-completed` 取消完成。
5. `reminder update` 仍是完整替换，行为不变。
6. 同一幂等 key 重放返回同一结果；同 key 不同 payload 返回 `conflict`；`outcome_unknown` 后可通过 list 对账。
7. 重复提醒 `recurring=true`；patch/update/complete/delete 返回 `unsupported_operation`。
8. create/list/patch/complete/delete 的 ID 在 opt-in 测试中一致；删除后该 ID 不再出现。
9. Skill 和 CLI 文档不含 `--title`/`--body` 正式模板；ID 边界和重新解析流程已写入。
10. 构建、测试、JXA 检查、release verify 和 `git diff --check` 通过。

## 范围外

- 不支持修改重复提醒的 recurrence rule，也不支持按 span 编辑/删除重复提醒。
- 不新增 `web.reminders.patch`；管理 Web 端现有 reminder create/update/delete RPC 保持原样，管理页不做 reminder CRUD UI。
- 不保留旧 `due` 字符串兼容层，不提供 `dueInfo` 双字段。
- 不引入连接器本地 due/ID sidecar。
- 不实现 `calendarItemExternalIdentifier` 或跨设备 ID 映射。
- 不发布 npm 包、不创建 Git tag 或 GitHub Release。
