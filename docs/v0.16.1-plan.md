# Apple Connector v0.16.1 计划：审计页改为授权分组热力图

更新日期：2026-11-18

状态：已批准并实施完成（2026-11-18）

进度：[v0.16.1-progress.md](./v0.16.1-progress.md)

## 结论

把“审计”页改为 **GitHub 贡献图风格的每小时热力图**，每个授权一张：

```text
横轴  = 本地小时 00–23
纵轴  = 最近 7 个本地自然日（6 天前在上，今天在下）
方块  = 该授权在该小时的操作次数
颜色  = GitHub 绿色 5 级：0 次灰，1 次浅绿，2–3、4–7、≥8 逐级加深
```

- 本机管理页面、每条授权记录、每条已删除授权各一张热力图。
- 保留隐藏泳道、删除该泳道全部历史审计数据。
- 原始审计表格保留为图表下方的可折叠明细。
- 悬停方块显示日期、小时、总次数，以及查询/创建/更新/完成/删除和拒绝/失败/未知的细分。

## 已确认的决策

| 项 | 决定 |
| --- | --- |
| 版本 | `0.16.1`（叠加在已完成的 `0.16.0` 上） |
| 布局 | 每个授权一张 7×24 热力图 |
| 横轴 | 本地小时 `00`–`23` |
| 纵轴 | 最近 7 个本地自然日，6 天前在上、今天在下 |
| 强度 | 固定阈值：`1 / 2–3 / 4–7 / ≥8`，跨授权可比较 |
| 颜色 | GitHub 贡献图绿色；不再读取容器颜色，不提供手动选色 |
| 泳道操作 | 隐藏；删除该泳道全部历史审计数据 |
| 数据库 | 不新增表/列，保持 `user_version=8` |

## 颜色

GitHub 浅色主题绿色色阶：

| 次数 | 色值 |
| --- | --- |
| 0 | `#ebedf0` |
| 1 | `#9be9a8` |
| 2–3 | `#40c463` |
| 4–7 | `#30a14e` |
| ≥8 | `#216e39` |

图例显示“少 → 多”和“每个方块 = 该小时的操作次数”。

## 计数规则

- 只统计 `calendar` / `reminders` 的操作，且事件必须有容器 `target` 或 `operationId`；
  容器发现、授权创建/删除等无容器事件不计入热力图。
- 同一 `operationId` 的 `allowed` 与终态事件合并为一次操作，终态优先，避免一次写入计两次。
- 事件按浏览器本地时区落入“日期 + 小时”格子；未来小时保留为空。
- `audit.query` 分页读取，单次最多 2000 条；超过时页面显示截断提示。

## 泳道

- **本机管理页面**：`source = 'web'` 的操作。
- **每条授权记录**：按 `clientId` 分组；同名授权在标题后加短 ID 区分。
- **已删除授权**：保留历史泳道，名称来自审计事件的 `clientName`，缺失时回退短 ID。
- 默认只显示最近 7 天有操作的授权；可勾选“显示无操作的授权”。
- 隐藏状态保存在当前浏览器的 `localStorage`，不影响服务端数据。

## 数据与协议改动

### 审计事件

`src/audit/schema.ts`：

- 新增可选 `clientName`，删除授权后历史仍可读。

`src/operations/agent.ts`：

- 授权拒绝、执行允许、成功、失败事件写入 `target: change.containerId`。

`src/transports/local/handlers.ts`：

- `calendar.list_events`、`reminders.list` 增加容器级读审计（`read`、`target`、`count`、`durationMs`、结果与错误码）。
- `diagnostics.read_summary` 的读审计补 `target`。
- 管理端新增 `audit.delete_lane`：
  - `{ kind: 'client', clientId }` 或 `{ kind: 'web' }`；
  - 删除该泳道全部历史审计事件，返回 `{ deleted: number }`；
  - 仅管理端可调用，不写替代审计记录。

`src/storage/database.ts`：

- `audit()` 在 `clientId` 存在且未提供 `clientName` 时从 `clients` 表补齐。
- 新增 `deleteAuditLane(ref)`。
- 不新增表/列，`user_version` 保持 `8`。

### 移除的内容

上一版时间轴方案中的容器颜色读取、手动选色、`container_colors` 表/RPC 已移除；
原生 helper、Provider 与 Agent 容器列表恢复为只返回 `{ id, name }`。

## 兼容性与迁移

- **数据库**：保持 `user_version=8`，不新增表/列。
- **旧事件**：缺少 `target` 的旧 Agent 事件不计入热力图，但仍保留在明细表格。
- **CLI / Agent 契约**：容器列表仍为 `{ id, name }`；`audit.list` / `audit.query` 只新增可选字段。
- **审计量**：新增容器级读事件，每次查询一行；保留策略（30 天 / 20,000 行 / 50 MB）不变。
- **删除泳道数据**：只删审计，不影响授权、令牌和业务数据；不可恢复。

## 风险

1. **读取上限**：单次最多读取 2000 条事件；高频授权可能截断，页面会提示。
2. **本地时区**：日期与小时按浏览器本地时区分桶，跨时区查看同一份数据可能落在不同格子。
3. **删除不可撤销**：仅管理端可用，必须二次确认，且明确只删审计、不删授权。
4. **旧事件缺失**：没有 `target` 的旧事件无法定位容器，不进入热力图。
5. **泳道数量**：授权很多时页面较长；默认只显示最近 7 天有操作的授权，并支持隐藏。
