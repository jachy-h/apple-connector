# Apple Connector v0.3.0 实施进展

更新日期：2026-09-06
对应计划：[v0.3.0-plan.md](./v0.3.0-plan.md)

## 当前状态

P0 启动与登录已实现并通过自动化复核。package 已进入 `0.3.0-dev.0`；管理流程开发完成不等同于公开发布验收，原生能力门禁仍按 v0.2.0 记录执行。

## 本轮完成

- [x] 确认“命令启动后台服务并输出管理网页，集中提供授权、审计、调试和 MCP 接入”的需求合理。
- [x] 核对现有 CLI、服务生命周期、管理会话、网页和 MCP 入口。
- [x] 明确当前差距：start 不输出地址、依赖预先 setup、重复启动报错；一次性链接无法重新签发；授权仍依赖 JSON；MCP 接入引导与网页诊断未完整实现。
- [x] 制定启动/会话行为、页面范围、实施顺序、验收标准及与 v0.2.0 原生门禁的衔接。
- [x] `start` 自动创建状态目录、管理员凭证与数据库，启动后以本地 RPC 复核服务可用；重复 `start` 复用既有实例。
- [x] `start` 输出新的一次性管理链接，新增 `start --open`、`open --print`；`open` 通过仅限本地管理员凭证的 RPC 重新签发链接，无需重启服务。
- [x] 新签发链接会替换未使用的旧链接，但不会使既有 HttpOnly 管理会话失效。
- [x] 网页创建客户端改为范围表单：数据源、容器 ID、动作、字段投影、审批方式与到期时间均可直接配置；旧客户端的 JSON 高级编辑入口暂保留。
- [x] 新建或轮换客户端凭证后，网页仅在当次可信会话中生成可复制的 MCP stdio 配置；配置只含客户端 token，不含管理员凭证。
- [x] 管理页可拒绝仍处于待审批的计划；拒绝会清除待执行内容并取消计划，不触发原生调用。
- [x] 审计新增有界查询 API，按数据源、客户端、结果、时间范围过滤后再分页；网页已提供数据源/结果筛选、翻页及明确标记为“当前筛选页”的导出。
- [x] 管理会话可预览尚未执行的不可变计划，包括目标容器和拟写入字段；计划取消、执行或结果未知后内容仍不会保留或再展示。
- [x] 客户端可在网页以范围表单编辑名称、数据源、容器、动作、字段、审批方式与到期时间；多授权客户端可逐项选择并编辑，其他授权不会被静默压缩或覆盖。保存会清楚说明并执行既有的未执行计划取消规则。
- [x] 管理页新增受控 Reminders M1 诊断：仅可指定明确测试列表运行固定 UUID-journaled 流程，页面显示阶段、耗时、恢复状态与精确清理入口；不提供任意脚本/JXA 输入，且不会自动重放写入。
- [x] 操作记录页面接入有界查询，支持按数据源与状态筛选、分页和匹配记录计数；待审批列表继续独立刷新以避免分页隐藏待处理计划。
- [x] 双语 README 已改为 v0.3.0 管理流程，记录无预先 setup 的启动、链接重签、网页授权/审批/诊断与 MCP 接入边界；`release:verify` 已验证构建产物、CLI、注册脚本、管理静态资源及 dry-run 包内容。
- [x] 网页授权表单可按精确名称触发 metadata-only 容器发现，返回匹配的 Reminders 清单和 Notes 文件夹 ID/共享状态，不读取任何项目内容。
- [x] 管理页可执行固定、无个人内容的 EventKit 基础探针，显示桥接与授权状态，不申请权限、不读取项目、不写入；结果不会被表述为完整原生能力通过。
- [x] `status` 在发现 PID/socket 后还会经管理员 RPC 做真实健康探测，明确报告 healthy 或 degraded，而不是将残留进程文件误报为服务就绪。
- [x] 管理页新增独立 MCP 接入页：提供 stdio 配置、当次凭证或安全占位符、绝对启动路径提示、受限读取验收步骤，并明确网页 URL 不是 MCP endpoint、管理员 token 不得进入客户端配置。
- [x] 管理页新增受限读取调试：必须选择有效客户端、已授权的 Reminders/Notes 容器和不超过 20 项的边界；调用复用授权规则，只返回计数/分页摘要，不返回标题、片段、正文、对象 ID 或 token，并写入元数据审计。
- [x] 网页审计筛选已补齐客户端与本地时间范围，并和数据源、结果、分页组合生效；导出仍明确限定为当前筛选页。
- [x] 新增 `npm run start` 一键开发入口：先构建再执行 `start --open`，无需手动拼接 CLI 路径；服务仍输出可复制的本地管理链接。

## 验证与阻塞

`npm run check` 在可监听 loopback/Unix socket 的本机环境通过：65 项测试通过、0 项失败，及 20 个固定 JXA 脚本语法检查通过。受限沙箱中同一服务测试会因禁止监听而失败，未将其误判为代码失败；未执行真实 Apple 写入。

`npm run release:verify` 已在 `0.3.0-dev.0` 版本提升后重新通过，验证开发包的构建、CLI doctor、运行依赖、全部注册 JXA 脚本、网页静态资源与 `npm pack --dry-run` 内容；它不是最终安装或 Apple 原生能力的证据。

当前没有已确认不可解决的管理功能阻塞。Reminders 超时、Calendar 稳定定位和共享/重复判定仍未解决，详见 [v0.2.0 进展](./v0.2.0-progress.md)；新计划不将其视为完成。
