# Apple Connector v0.11.0 计划：逐容器授权、撤销后删除与最近使用时间

更新日期：2026-11-16
状态：已批准并实施；2026-11-16 增加“权限页关闭/重新开启”调试补充，已批准并实施
进度：[v0.11.0-progress.md](./v0.11.0-progress.md)

## 结论

本版本只改管理侧，不改变 Agent 的读写协议，也不改变 Apple 作为唯一数据源的前提：

1. Agent 配置表单支持为每个日历/提醒事项清单分别选择操作、字段范围和审批模式，再把权限完全相同的容器合并成一条 grant。
2. 已撤销的 profile 可以从数据库和本地凭据目录中删除；审计事件保留。
3. 每个启用中的 profile 显示最近一次成功使用其凭据的时间；从未使用则明确显示“从未使用”。

这是一个跨层变更，涉及 SQLite schema、`clients.*` 管理 RPC、管理 Web UI、i18n、文档和版本元数据。当前工作树已有 v0.10.0 的未提交改动，本版本必须叠加在它们之上，不回退、不覆盖。

## 已确认决策

- 每个容器的权限粒度为：操作、字段范围（仅日历的 full/busy）、审批模式；过期时间由整个 profile 统一设置。
- 删除仅适用于已撤销 profile。删除时移除该 client 的 operations 和 onboarding 记录、删除本地 token 文件，保留审计事件；存在 `executing` 操作时拒绝删除。`outcome_unknown` 允许删除，其不确定性由保留的审计事件记录。
- “上一次使用时间”以最近一次成功用 client token 认证为准，包含读取调用；数据库写入按分钟节流。
- 版本号升为 `0.11.0`，native helper 的 `protocolVersion` 仍为 `2`，CLI `schemaVersion` 仍为 `2`。

## 契约设计

### 1. 逐容器授权

现有策略 schema 已允许一个 client 携带多条 grant，`authorize` 也按容器匹配 grant；本版本不改变授权判断，只改变管理页创建 profile 的方式。

表单行为：

- 保留 `name`、`provider`、过期时间三个 profile 级字段。
- 每个可见容器单独一行，可选择是否授权，并分别设置：
  - 操作：日历为 `read/create/update/delete`，提醒事项为 `read/create/update/complete/delete`。
  - 字段：仅日历显示 `full/busy`；选择 `busy` 时强制只能读取。
  - 审批：`required/automatic`。
- 未选中的容器不生成 grant；已选中但没有任何操作的容器在提交前拒绝。
- 提交时按 `provider + actions + fields + approval + expiresAt` 分组：权限完全相同的容器合并到同一条 grant 的 `containerIds`，避免每个日历都产生一条 grant，并保持在现有 `grants.max(30)` 与 `containerIds.max(100)` 限制内。
- 不新增通配符授权入口；仍只授权页面列出的明确 EventKit ID。
- 后端 `clientInputSchema`、`grantSchema`、`authorize` 和 Agent operation 映射保持不变。

展示行为：

- 已有 profile 继续按 grant 展示容器、操作、字段和审批；同一 grant 下的多个容器会一起显示。
- 不新增编辑 profile 的能力；创建新配置仍是唯一授权入口。

### 2. 删除已撤销 profile

新增管理方法 `clients.delete`，仅接受已撤销 client：

```json
{ "id": "<clientId>" }
```

规则：

- client 不存在或未撤销时返回 `conflict`/`permission_denied`，不删除任何数据。
- 存在 `operations.state = 'executing'` 时返回 `conflict`，等待当前写入结束后再删除。`outcome_unknown` 不阻塞删除，因为当前仓库没有关闭该状态的命令；删除后不确定性由保留的审计事件记录。
- 成功时在单个事务内删除：
  - 该 client 的 onboarding 记录；
  - 该 client 的 operations 记录；
  - `clients` 行本身。
- 审计事件不删除；写入一条 `client_deleted` 事件。审计表按 JSON 保存 `clientId`，不依赖外键，因此删除 client 后历史仍可查询。
- 管理 Web 的 `admin/main.ts` 在数据库删除成功后尽力删除 `${stateDir}/profiles/<clientId>.token`；文件已不存在时不报错。
- 删除入口只出现在已撤销 profile 卡片上，并要求浏览器确认；启用中的 profile 不显示删除按钮。
- `clients.delete` 加入 RPC 白名单和管理方法集合，Agent token 无法调用。

### 3. 最近使用时间

数据库迁移到 `user_version=5`：

```sql
ALTER TABLE clients ADD COLUMN last_used_at INTEGER;
```

- `Client` 增加 `lastUsedAt: number | null`，`clients.list`、`clients.create`、`clients.update`、`clients.rotate` 返回该字段。
- `Store.authenticate(token, now = Date.now())` 在 token 验证成功后更新 `last_used_at`，但仅在为空或早于 `now - 60_000` 时写入，避免每个 Agent 请求都产生写事务。
- 更新 `last_used_at` 不增加 `policy_version`，不取消 operations，不属于策略变更。
- 认证失败、已撤销 client、管理 token 调用都不更新时间。
- 管理页只对启用中的 profile 显示“上次使用 · <本地时间>”；为空显示“从未使用”。已撤销 profile 继续显示撤销状态，不展示使用时间。
- 时间精度按分钟接受，允许最多约 60 秒的展示滞后。

### 4. 系统权限关闭与重新开启（调试补充）

macOS 不提供撤销自身 TCC 授权的公开 API，App 不能主动关闭已经授予的日历/提醒事项权限，也不能在用户关闭后再让系统重新弹出首次授权框。本版本只做系统允许的调试流程：

- 权限卡片在已授权或仅写入时增加“关闭权限…”按钮；其他状态显示“系统设置…”按钮。
- 两个按钮都打开对应深链：
  - 日历：`x-apple.systempreferences:com.apple.preference.security?Privacy_Calendars`
  - 提醒事项：`x-apple.systempreferences:com.apple.preference.security?Privacy_Reminders`
- 用户在系统设置中手动关闭或重新打开权限；返回管理页时自动重新检查状态，另提供“重新检查”按钮。
- 保留现有“请求日历权限/请求提醒事项权限”按钮；仅在 `not_determined` 等状态由系统弹窗授权。
- 不新增 RPC、不调用 `tccutil`、不写 TCC 数据库、不改变权限判断，也不影响 Agent 授权。
- 页面帮助文案说明“重新开启在系统设置中完成”，避免把“请求权限”误当成可重复触发的授权弹窗。

### 5. 兼容性

- 旧数据库从 v4 自动添加 `last_used_at`，现有 client 初始为 `NULL`。
- 旧 v1/v2/v3 数据库继续沿现有迁移链升级到 v5。
- `user_version > 5` 的数据库继续被拒绝打开。
- 不改变 `grants` JSON 结构、token、Agent RPC、native helper 协议或 CLI 输出 schema。

## 测试计划

- 存储迁移：v4 数据库升级后存在 `last_used_at`，旧 client 为 `null`；v1 迁移测试的期望 `user_version` 更新为 5。
- 最近使用：认证成功后写入；60 秒内重复认证不改变值；超过 60 秒后更新；失败认证和撤销 client 不更新。
- 删除：启用中拒绝；已撤销成功删除 client、operations、onboarding；审计保留且新增 `client_deleted`；`executing` 拒绝，`outcome_unknown` 允许。
- 管理 RPC：`clients.delete` 需要管理身份，Agent token 被拒绝；删除后 `clients.list` 不再返回该 profile；返回结构包含 `lastUsedAt`。
- Web 展示模型：逐容器选择按权限完全相同合并、不同权限拆分、busy 强制只读、空操作拒绝、provider 操作集合正确。
- 系统权限调试：日历/提醒事项深链分别指向 `Privacy_Calendars`/`Privacy_Reminders`；中英文均包含“关闭权限…/系统设置…/重新检查”文案。
- i18n：中英文均包含新增的逐容器权限、最近使用、从未使用和删除文案。
- 门禁：`npm run build`、`npm test`、`npm run check:jxa`、`npm run release:verify`、`git diff --check`。

## 验收标准

1. 创建 Agent 配置时可分别为不同日历/提醒事项清单选择操作、字段范围和审批模式；相同权限的容器合并成一条 grant，权限不同的容器保持独立。
2. busy 字段只能与 `read` 组合，提交前和 schema 两层都拒绝非法组合。
3. 已撤销 profile 可从管理页删除，数据库不再返回该 client，关联 operations/onboarding 和本地 token 文件被删除，审计仍保留并能看到 `client_deleted`。
4. 启用中的 profile 显示最近一次凭据认证时间；从未使用时显示“从未使用”；已撤销 profile 不显示使用时间。
5. 数据库从 v4 平滑迁移到 v5，旧 client 的 `lastUsedAt` 为 `null`。
6. Agent token 不能调用 `clients.delete`；更新使用时间不改变授权策略或使 operation 失效。
7. 权限页可打开对应系统设置面板手动关闭/重新开启权限；返回页面后状态自动刷新，也可点击“重新检查”手动刷新。
8. 构建、测试、JXA 检查、release verify 和 `git diff --check` 通过。

## 范围外

- 不新增 profile 编辑、复制、重新启用或 token 明文展示。
- 不改变 Agent 的授权判断、native helper 协议、CLI `schemaVersion` 或 `clients.list` 以外的响应结构。
- 不实现 `outcome_unknown` 的自动对账或关闭命令；该状态不阻止删除，审计事件保留其不确定性。
- 不自动调用 `tccutil`、不重置 TCC、不提供“一键撤销系统权限”能力。
- 不发布 npm 包、不创建 Git tag 或 GitHub Release。
