# Apple Connector v0.9.2 计划：Skill 路径与授权引导修复

更新日期：2026-09-08
状态：已实施并验证
进度：[v0.9.2-progress.md](./v0.9.2-progress.md)

## 背景与结论

v0.9.1 的 `apple-connector skill path --json` 存在包内路径解析错误。CLI 编译产物位于 `dist/src/cli/index.js`，当前相对路径 `../../skill/` 会解析为 `<package>/dist/skill/`，但 npm 包实际将 Skill 放在 `<package>/skill/`。因此 Agent 报告的“`dist/skill/` 目录不存在”与 Apple Connector 直接有关；Agent 创建 workspace Skill 符号链接只是绕过了该缺陷。

本机 `npm link` 会让全局包目录链接回当前仓库，但不会制造这次层级错误：链接与普通 npm 安装最终都执行 `<package>/dist/src/cli/index.js`，而 tarball 也同样把 Skill 放在 `<package>/skill/`。所以当前缺陷在 link 和 registry/tarball 安装中都会出现，修复不应加入 `npm link` 特判。

本版本同时收紧 Agent 返回授权链接时的展示契约：使用 Markdown 链接，并用简洁、正向的操作提示代替“我不会打开该 URL 或轮询状态”这类面向用户的内部边界说明。收到用户确认前不访问页面、不轮询 onboarding 状态、不调用业务命令的安全约束保持不变。

本计划不授权 npm publish、Git tag、GitHub Release，也不改变授权协议、onboarding 状态机或 credential 边界。

## 实施范围

### 1. 修复打包后的 Skill 路径

- 修正 `src/cli/index.ts` 中 `skill path` 的包根目录层级，使构建后的命令返回 `<package>/skill/`。
- 保持现有 JSON schema 不变：仍返回 `{ path, version }`。
- 不把 Skill 复制进 `dist/`；继续使用 npm 包已声明的根目录 `skill/`，避免重复产物和路径分叉。

### 2. 增加路径回归测试

- 在 CLI 测试中执行构建后的 `skill path --json`。
- 断言返回路径真实存在、指向包根目录 `skill/`，且其中包含 `SKILL.md`。
- 在发布验证中创建实际 tarball，将其安装到临时目录后执行安装包的 CLI，并断言 `skill path` 返回该安装包根目录下真实存在的 `skill/`。这同时覆盖普通 npm 安装布局，防止只在当前仓库或 `npm link` 下通过。
- 临时打包、安装与 npm cache 全部放在独立临时目录，验证结束后清理；不依赖或修改用户现有 npm cache，也不要求修复本机 cache 权限。

### 3. 规范 Agent 的授权链接输出

- 更新 `skill/SKILL.md`，要求面向用户返回 URL 时使用 Markdown 链接，而不是裸 URL。
- 中文交互固定使用：`请打开[授权链接](URL)，完成授权后在此回复「已完成」。`
- 英文交互使用等义的简洁提示，并与用户当前语言一致。
- 不再要求 Agent 向用户陈述“我不会打开该 URL 或轮询状态”；这些限制仍作为 Skill 内部执行约束保留。
- 对 permissions、agents、approvals、audit 等其他管理页链接同样使用 Markdown 链接。

### 4. 同步接入文档

- 更新 `README.md`、`README_zh.md`、`docs/install-for-agent.md`、`docs/install-for-agent_zh.md` 和 `docs/skill.md`，让复制给 Agent 的指令与 Skill 契约一致。
- 文档明确区分：用户看到的是正向授权提示；Agent 内部仍须等待用户确认且不得提前轮询。
- 更新版本元数据、锁文件、helper 版本契约和发布验证中的版本断言至 v0.9.2；若代码检查发现还有其他必须同步的版本位置，只做机械一致性更新并记录到进度文档。

## 验证标准

1. 构建后的 `apple-connector skill path --json` 返回真实存在的 `<package>/skill/`，其中可读到 `SKILL.md`。
2. 回归测试能在旧的 `dist/skill/` 错误路径下失败，在修复后通过；实际 tarball 临时安装验证也返回安装包内的根目录 `skill/`。
3. Skill 明确要求以 `[授权链接](URL)` 形式返回链接；中文提示与维护者指定文案一致。
4. Skill 仍禁止在用户回复“已完成”前打开授权页、轮询状态或进行业务调用，但 Agent 不再向用户输出生硬的否定声明。
5. `npm test`、`npm run check:jxa`、`npm run release:verify` 与 `git diff --check` 通过。
6. 不覆盖或回退工作区中已有的其他未提交改动。
