# Upgrade guide

[中文摘要](#中文摘要) · English

Apple Connector keeps the state directory, database, audit records and authorization model
stable across patch releases. The changes below are the ones that require action.

Current version: **0.17.0**.

## v0.16.x → v0.17.0: permission owner changed to Apple Connector

The EventKit helper now runs inside the self-signed `AppleConnector.app`. macOS records
Calendar/Reminders permission for **Apple Connector**, not for Terminal, OpenCode or another
agent host.

What to do:

1. Run `npm run signing:check`; if you build from source, create the self-signed identity first
   ([Signing](signing.md)).
2. Run `npm ci && npm run build`, then `npm link` (or install the npm package).
3. Run `apple-connector stop`, then `apple-connector init`.
4. On the setup page, grant Calendar and/or Reminders once more. The prompt names **Apple
   Connector**. The old host-app grants remain in System Settings but are no longer used.
5. Confirm with `apple-connector doctor`: helper permissions should read `full_access`.

The existing `~/.apple-connector` state, authorizations, tokens and audit records are not
removed. Rebuilding with the same certificate and bundle id keeps the new grant; changing the
certificate or using ad-hoc signing requires a new grant. See
[System permissions](system-permissions.md) and [Signing](signing.md).

## v0.15.x → v0.16.0: merged setup page and Agent binding

`setup` and onboarding handshakes were removed in v0.15.0; v0.16.0 merged permission,
authorization and prompt generation into one setup page and added `auth verify`. Prompts from
that era that reference `agent init`, `agent init-status` or an onboarding ID no longer work.

Use `apple-connector init`, create one authorization per Agent, and pass the generated prompt
to the Agent. `apple-connector open --section setup` replaces the old permission and agent
pages; `permissions` and `agents` remain accepted aliases.

## v0.16.3: authorization key instead of an ID in the prompt

The recommended prompt now contains an authorization key, a local profile identifier, and no
bearer token. Pass it with `--auth-key`. The CLI resolves the owner-only credential under
`<state dir>/profiles/<key>.token`. Do not read, copy, scan or print those token files.

Older prompts with an explicit `Credential file` path still work with `--auth-file <path>`.
An authorization ID still works with `--auth-file`, `APPLE_CONNECTOR_AUTH` or `--auth <token>`.

## v0.14.0: immutable authorizations and one-time tokens

Authorizations can no longer be edited or prepared/approved. A write inside the scope executes
immediately. The authorization ID is shown once at creation and written to an owner-only local
file; delete and recreate an authorization to change its scope. Existing authorizations remain
valid.

## v0.14.1: state directory moved to `~/.apple-connector`

If an older build used `~/apple-connector`, run once:

```bash
apple-connector migrate-state
```

The command stops the legacy service and management page, removes stale runtime files, and
renames the directory. It never merges a non-empty destination. Most other state commands also
migrate automatically when the legacy service is not running. `APPLE_CONNECTOR_STATE_DIR` must
be unset for an explicit migration.

## v0.8.x → v0.9.0: stdio MCP removed

v0.9.0 removed the stdio MCP server completely. Remove the `mcpServers.apple-connector` entry
from the agent host configuration; it is no longer a supported integration. Install the
packaged Skill, run `apple-connector init`, create an authorization on the local page, and give
the generated prompt to the Agent. All machine calls use `apple-connector ... --json`.

## Older releases

- **Before v0.8.0**: no published npm package and no Skill. Upgrade through a source build.
- **v0.5.0 – v0.7.0**: introduced the persistent Swift helper and web management. The current
  CLI replaces those internal entry points; keep only the public `apple-connector` commands.
- **v0.2.0 – v0.4.0**: prototype and validation builds. Upgrade by installing the current CLI,
  running `apple-connector migrate-state` if a legacy `~/apple-connector` directory exists, and
  recreating the authorizations you still need.

## 中文摘要

- **v0.16.x → v0.17.0**：EventKit helper 改为运行在自签名 `AppleConnector.app` 中，日历/提醒事项权限改归 **Apple Connector**。从源码安装时先创建签名身份，重新构建并 `npm link`，然后 `apple-connector stop`、`apple-connector init`，在接入页重新授权一次。现有状态、授权和审计不会被删除；同一证书和 bundle id 重建后授权保留。
- **v0.15.x → v0.16.0**：接入页合并，加入 `auth verify`。旧的 `agent init`、`agent init-status` 和 onboarding ID 都不再使用；用 `apple-connector init` 创建授权并把提示词交给 Agent。
- **v0.16.3**：推荐提示词改为授权 key，不含 bearer token，用 `--auth-key` 传入。旧提示词的 `Credential file` 路径仍可用 `--auth-file`。
- **v0.14.0**：授权不可编辑，写入不再审批，授权码只在创建时显示一次。需要改范围时删除并重建。
- **v0.14.1**：状态目录改为 `~/.apple-connector`。旧用户运行一次 `apple-connector migrate-state`。
- **v0.8.x → v0.9.0**：stdio MCP 已完全移除，从 Agent 宿主配置中删除 `mcpServers.apple-connector`，改用随包 Skill 与 CLI。

全部指南见[文档索引](README_zh.md)。
