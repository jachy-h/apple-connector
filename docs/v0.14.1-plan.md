# Apple Connector v0.14.1 计划：状态目录迁移到 `~/.apple-connector`

更新日期：2026-11-18
状态：已批准并实施完成（2026-11-18）
进度：[v0.14.1-progress.md](./v0.14.1-progress.md)

## 目标

1. 默认状态目录从 `~/apple-connector` 改为 `~/.apple-connector`。
2. 为已有安装提供一次性迁移，保留数据库、授权 token、profiles、日志和审计。
3. `APPLE_CONNECTOR_STATE_DIR` 显式覆盖保持原样，测试和临时实例不受影响。

版本建议：`0.14.1`（补丁版本；不改变协议、数据库 schema 或 CLI envelope）。

## 现状

- `src/transports/local/paths.ts` 中默认路径为 `join(homedir(), 'apple-connector')`。
- 当前机器 `~/apple-connector` 存在：
  - `db.sqlite3`
  - `admin-token`
  - `profiles/`
  - `service.sock` / `service.pid` / `service.lock`
  - `service.log`
  - `agent.token` / `agent-client.json`（更早版本遗留）
  - `admin-url` / `web.pid` / `web-expires-at`
- 当前旧服务仍在运行（`service.pid` 指向 pid 3010），因此迁移必须先停止旧服务，不能直接移动目录。
- `~/.apple-connector` 目前不存在。

## 设计

### 1. 新默认路径

```ts
export function defaultStateDir(): string {
  return join(homedir(), '.apple-connector');
}
export function legacyStateDir(): string {
  return join(homedir(), 'apple-connector');
}
```

- `statePaths()` 默认返回 `~/.apple-connector`。
- `APPLE_CONNECTOR_STATE_DIR` 仍优先，且不触发自动迁移。
- 继续拒绝 `/` 和 `$HOME` 本身作为状态目录。
- 目录权限保持 `0700`，token/DB 文件权限保持 `0600`。

### 2. 自动迁移（无运行中服务时）

在 CLI 分发前和 `setup()` 中调用一次同步迁移：

- 旧目录不存在：不做任何事。
- 旧目录存在、新目录不存在：
  - 如果旧 `service.pid` 指向存活进程，拒绝并提示运行 `apple-connector migrate-state`。
  - 否则 `renameSync(legacy, current)`，保留全部文件和权限，`chmod 0700`。
- 旧目录和新目录同时存在：
  - 不合并、不覆盖；返回 `conflict`，提示手动处理。
- 新目录存在但为空：
  - 删除空目录后迁移；避免 `rename` 到已存在目录失败。
- 迁移是幂等的：完成后旧目录不存在，后续命令直接使用新目录。

### 3. 新增 `apple-connector migrate-state`

用于安全地迁移正在运行的旧服务：

```text
apple-connector migrate-state [--json]
```

行为：

1. 读取旧目录的 `service.pid` 和 `web.pid`。
2. 如果旧服务存活：
   - 发送 `SIGTERM`；
   - 等待旧 `service.sock` 消失（最多 10 秒）；
   - 超时则失败，不移动任何文件。
3. 尽力停止旧管理 Web 进程（`SIGTERM`，不等待）。
4. 按第 2 节的规则移动目录。
5. 返回：

```json
{
  "migrated": true,
  "from": "/Users/<user>/apple-connector",
  "to": "/Users/<user>/.apple-connector",
  "stoppedService": true,
  "stoppedWeb": true
}
```

- 没有旧目录时返回 `migrated: false`，不报错。
- 新旧目录同时存在时返回 `conflict`，不删除任何一边。
- 命令只做本机文件迁移，不读写业务数据内容。

### 4. 兼容性

- 不修改 SQLite schema、grants JSON、Agent RPC、native helper 协议或 `schemaVersion`。
- 迁移后旧路径不再使用；不保留兼容读取，避免两套状态目录。
- 旧版本 CLI 仍会读取旧路径；升级后第一次运行会迁移，之后不要回退到旧版本操作同一份状态。
- 迁移不修改 token 内容；`--auth-file`、`--profile` 和 onboarding 的绝对路径仍然有效。
- 迁移后旧路径的绝对路径（例如 Agent 保存的 token 文件路径）会失效；文档提示使用新路径或直接使用 `APPLE_CONNECTOR_AUTH`。

## 测试计划

- 路径：
  - `statePaths().dir` 默认以 `/.apple-connector` 结尾。
  - `APPLE_CONNECTOR_STATE_DIR` 仍然优先。
- 迁移纯函数（使用临时目录，不碰真实 HOME）：

- CLI：
  - `migrate-state --json` 返回 `migrated`、`from`、`to`。
  - 迁移后 `status --json` 指向新目录，授权数量和 DB 可读。

## 本机迁移步骤（批准后执行）

1. 停止当前旧服务（pid 3010）和旧管理 Web（pid 10557），使用旧路径的 CLI 或 `migrate-state`。
2. 运行 `apple-connector migrate-state --json`。
3. 验证：
   - `~/apple-connector` 不再存在；
   - `~/.apple-connector` 存在且权限 `0700`；
   - `apple-connector status --json` 显示新目录；
   - `clients.list` 中授权数量与迁移前一致；
   - 旧 token 文件可继续通过 `--auth-file` 使用。
4. 保留旧目录备份？迁移使用 `rename`，不保留副本；如需回滚，必须在迁移前手动备份。

- 不改变数据库 schema、授权协议或 token 格式。
- 不自动删除旧版本 CLI 的备份或历史文件。
