## 已验证

- `npm test`：84 项通过。
- `npm run check:jxa`：21 个固定脚本通过语法检查。
- 在完整本机构建权限下，`npm run test:native`：2 项无数据 EventKit/JXA 检查通过；11 项显式依赖测试容器 ID 的检查按设计跳过，其中包括新的 helper 无小数秒范围查询。
- `npm pack --dry-run`：生成 `@jachy/apple-connector@0.8.4` 的 123 文件、242.4 kB tarball 预览；`git diff --check` 通过。
- `npm link --force --offline --no-audit --no-fund`：成功替换旧的同名全局命令，`apple-connector version` 返回 `0.8.4`。

## 未完成与阻塞

- 真实 MCP/EventKit 冒烟仍需 Calendar full access 和显式测试日历 ID；本轮未请求、修改或读取个人日历数据。
- 进程采样确认常驻 native helper 正常阻塞在 stdin 等待 JSONL；本地服务启动时的 `permissions.status` warm-up 已成功，先前手工 `hello` 探针的无输出不是 helper/EventKit 初始化卡死证据。
- JXA 探针的 Calendar/Reminders 状态为 `3`（write-only），但这属于独立 JXA 进程，不能推断 Swift helper 的 TCC 授权。管理 RPC 已确认 production Swift helper 的 `calendar` 与 `reminders` 均为 `full_access`。
- 因此真实 `calendar.list_events` 冒烟的剩余条件不是权限或 helper 故障，而是用户尚未指定稳定的专用测试日历 ID 和明确读取范围。新增 opt-in 测试需要 `APPLE_CONNECTOR_EVENTKIT_CALENDAR_TEST_ID`，当前未设置。

## 当前状态

MIT 许可证与发布验证已完成；真实 MCP 冒烟仅等待显式的专用测试日历 ID 与读取范围。
