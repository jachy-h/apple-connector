# Apple Connector v0.4.0 进展

更新日期：2026-09-06
对应计划：[v0.4.0-plan.md](./v0.4.0-plan.md)

## 当前状态

P0 已开始：增加受管理会话保护的 Web 读取接口与来源隔离的审计基础；未修改 package 版本。

## 已完成

- [x] 确认主菜单为 APPs、审计，App 范围为日历、提醒事项、备忘录。
- [x] 确认日历操作对象是日程事件，本期只接入底层已支持能力。
- [x] 确认 Web 调试不需要创建 MCP 客户端，审计只考虑 Web 调试来源。
- [x] 核对 reader/writer、现有 Web、RPC 与 v0.2.0 支持矩阵，区分服务能力、诊断脚本及原生稳定性。
- [x] 明确 Calendar 查询、Reminders 读取/不稳定新增、Notes 搜索/详情/新增的范围；修改和删除不纳入本期。
- [x] 制定页面流程、Web 身份与执行入口、审计闭环、实施阶段和验收标准。
- [x] 记录未来纯 CLI 可行，本期不实施 CLI 改造或移除 MCP。
- [x] 新增仅供已认证 loopback 管理会话调用的 Web 读取 RPC：Calendar 时间范围读取、Reminders 分页读取、Notes 搜索与详情读取；这些方法不接受或创建 MCP 客户端凭证。
- [x] 审计事件增加 `source=web` 与最小目标引用字段，旧客户端记录默认保持 `source=client`；查询可按来源筛选，Web 审计不会混入旧记录。
- [x] 为 Web 读取增加服务端参数边界与成功/失败审计，审计不保存查询结果正文。
- [x] 增加独立于客户端表的 `web_operations` 持久化写入路径，用于 Notes、Reminders 新增；浏览器生成的 UUID 同时是幂等键与操作编号，刷新后可恢复状态；重启时执行中操作转为结果未知，成功或未知后清除正文。
- [x] Web 默认入口已切换为 APPs / 日历，一级导航仅保留 APPs、审计；APPs 下可执行 Calendar 时间范围读取与分页、Reminders 容器发现/分页读取与新增、Notes 容器发现/搜索/详情/新增，并显示实际服务返回值。
- [x] 新增 Web 专用审计页，仅请求 `source=web` 的记录并显示目标、结果和关联操作编号；旧客户端审计不再作为主导航内容。
- [x] Web 审计记录补充实际耗时；一次写入仅记录最终成功、失败或结果未知，内部预检/调用/核验不会伪装为多次用户操作。
- [x] 修复 Reminders Web 表单将精确名称误作清单 ID 提交的问题：容器发现结果现在提供显式“使用此 ID”选择；已重新构建并重启本机服务加载 Web RPC 与前端修复。
- [x] 诊断确认 Reminders 已获 macOS 完整访问权限，专用清单可由 EventKit 解析且有界读取成功；将清单解析失败的原生通用错误改为网页可行动的“发现并使用此 ID”提示。一次 create/verify/delete 探针未返回确定结果，按安全策略未自动重试。
- [x] 修复 iCloud Reminders 读取超时：将分页读取从会阻塞的 Apple Events `list.reminders()` 改为 EventKit 异步 scoped fetch。相同专用清单的 `offset=0, limit=50` 实测从超过 60 秒变为 218 ms（返回 1 条）；本机服务已重启加载该路径。

## 验证与已知限制

本轮已通过 `npm run check`：67 项自动化测试及 20 个固定 JXA 脚本语法检查均通过；定向 Web 存储/服务测试共 9 项通过。浏览器已在当前构建的隔离临时服务中确认 APPs/审计双主导航、默认日历页及无错误的 Web 审计页加载；该临时服务已停止并清理，未影响用户现有服务。未执行真实 Apple 数据读写；自动化测试中的 reader/writer 使用受控替身。现有工作区其他未提交变更保持原样。

Reminders 新增已实现但原生调用不稳定；日历写入、提醒事项修改/完成/删除、已有备忘录修改/删除不作为本期能力。真实验收必须单独记录，不能以自动化通过代替。

继续 P4：补齐审计耗时等元数据、端到端受控替身闭环及真实 Apple 测试容器验收记录；真实写入不会在未指定测试容器的情况下执行。
