### 需要代码改动的使用障碍（未实现）

1. **配对/权限/审批缺少可达入口。** web/src/main.tsx 的导航只提供 APPs 和审计；connections、sources、pending 等内部视图不可通过现有导航到达。required 写入会停在 prepared，CLI 也没有用户可用的审批命令。需要恢复完整管理路径，不能靠文档指导 agent 越权审批或降低策略。
2. **配置生成缺少 host 适配。** mcp config 仅生成顶层 mcpServers；nanobot 需要 tools.mcpServers，并且默认 30 秒调用超时低于连接器 60 秒 RPC 超时。建议生成器提供 host 选项、合理超时和已有配置的可审阅合并结果。
3. **配对步骤仍过多。** 配置者需要手工发现 ID、构造 grant、设置毫秒有效期、准备凭证父目录。Calendar 也没有统一 CLI 容器发现。建议一次性配对向导完成选择、授权、凭证落盘和配置生成。
4. **凭证生命周期不完整。** rotate 不更新文件，MCP 进程只在启动时读取凭证；需要安全文件轮换及清晰的重载机制。create 在写凭证文件前已经创建客户端，路径无效或文件存在可能留下无可用文件的新客户端，建议先校验或补偿处理。
5. **工具描述与实际实现存在陈旧内容。** MCP schema 描述仍称 Notes 只读、日历名称必须唯一，服务已切换 EventKit ID 并禁用 Notes。agent 主要读取工具描述，README 无法替代代码中的描述修正。
6. **agent 写入闭环仍有限。** 创建提醒必须 prepare/commit 两步；日历写入、提醒事项编辑/完成/删除未通过 MCP 注册。后续按 v0.8.0 方向实现业务工具与可靠性，不在本次文档修改中宣称已可用。
7. **源码运行仍依赖路径和本机工具链。** 移动仓库或更换 Node 路径后配置会失效；正式安装包尚未提供。未来打包还需将 README 引用的新配置指南纳入产物（当前 package.json 的 files 未包含它们）。
