# Apple Connector v0.6.2 计划：可靠的前台开发启动

更新日期：2026-09-07  
进度记录：[v0.6.2-progress.md](./v0.6.2-progress.md)

## 目标

将 `npm start` 改为开发专用的前台运行入口。每次执行均在完成构建后停止已有服务实例，再由当前终端进程运行新构建；按 `Ctrl-C` 时执行现有的安全关闭流程并退出。

## 设计

- 新增 CLI `start --foreground` 模式：初始化状态，正常停止已有实例，随后在当前 Node 进程加载本地服务。
- 前台模式不 detached、不 unref，也不把 stdout/stderr 丢弃；启动完成后打印 PID、管理地址和 `Ctrl-C` 提示。
- `npm start` 固定执行构建后调用 `start --foreground`，保证同版本源码重新构建时也不会复用旧进程。
- 保留普通 `apple-connector start [--open]` 的后台、幂等语义，供非开发场景使用。
- 前台服务仍使用现有 SIGINT/SIGTERM 关闭逻辑，有限等待服务、管理站点和 EventKit helper 后移除 PID、socket 与临时管理地址。

## 验收

1. 已有后台服务运行时执行 `npm start`，旧 PID 停止并出现不同的新前台 PID。
2. `npm start` 命令持续占用终端；发送 SIGINT 后进程退出，socket、PID 文件与管理地址被清理。
3. 连续两次运行均启动新 PID，不依赖 package 版本变化。
4. 完整构建、测试、JXA 检查与提交前 diff 检查通过。
