# Apple Connector v0.14.0 计划：不可变授权、一次性 token、移除审批

更新日期：2026-11-17
状态：已批准并实施完成（2026-11-18）
进度：[v0.14.0-progress.md](./v0.14.0-progress.md)

## 结论

按你最新确认的 4 点，模型收敛为：

1. **授权创建后不可编辑**，页面只能查看和删除。
2. **授权 ID 就是 token**，只显示一次；同时写入本地 owner-only 文件，保证本地仍能按 token 找到授权。
3. **完全移除审批逻辑**：没有审批页、没有 `prepared` 状态、没有 approve/reject，所有有写权限的调用直接执行。
4. **幂等键继续保留**：写入仍要求显式 `--idempotency-key`。

一个授权仍然对应：

- 日历的 N 个容器，每个容器分别勾选 `read` / `create` / `update` / `delete`；
- 提醒事项的 M 个容器，每个容器分别勾选 `read` / `create` / `update` / `complete` / `delete`；
- 统一的过期时间；
- 不包含审批字段。

版本建议：`0.14.0`。移除审批和授权编辑是行为上的破坏性变更，但 CLI JSON envelope 结构不变，`schemaVersion` 建议保持 `2`。

## 最终使用流程

```text
1. apple-connector open
2. 系统权限：分别请求日历、提醒事项
3. 创建授权：
     - 日历：N 个容器，每个容器勾选动作
     - 提醒事项：M 个容器，每个容器勾选动作
     - 设置过期时间
     - 创建
4. 页面显示一次授权 ID（token），复制给 Agent
5. Agent 保存 token，调用时带 --auth-file / 环境变量 / --auth
6. 增删改查直接执行，不再有审批
```

页面导航变为：

```text
系统权限 | 授权 | 审计 | 使用文档
```

“审批”页面和导航项删除。

## 授权不可变

### 允许

- 查看授权列表；
- 查看单个授权的范围、过期时间、状态、最近使用时间；
- 删除授权；
- 创建新授权。

### 不允许

- 编辑名称；
- 编辑容器范围；
- 编辑每个容器的动作；
- 编辑过期时间；
- 轮换 token；
- 再次查看已创建的 token。

### 删除

- 页面只提供“删除”，不再提供“撤销”按钮。
- 删除活跃授权时：
  - 立即让 token 失效；
  - 删除 `profiles/<internal-uuid>.token` 文件；
  - 删除该授权的 onboarding 记录和 operations 记录；
  - 保留审计事件；
  - 如果存在 `executing` 操作，拒绝删除并提示等待。
- 删除前必须二次确认，提示“删除后该授权 ID 立即失效，无法恢复”。
- 已撤销授权不再是一个用户可见状态；如果迁移前存在 `revoked=1` 的记录，仍可查看并删除。
- 内部 `clients.revoked` 字段保留，用于历史/迁移兼容；新流程不产生新的撤销操作。

### 为什么不再编辑

- 授权是不可变能力凭证：token 与权限范围绑定，Agent 拿到后不需要重新协商。
- 需要变更范围时，删除旧授权并创建新授权；旧 token 立即失效。
- 这避免了“编辑后旧 token 权限变化”导致的 Agent 行为不确定。

## 授权 ID 与本地文件

### 创建时

- 服务生成随机 token（现有 `randomBytes(32).toString('base64url')`）。
- DB 只保存 `token_hash`。
- 页面显示 token 一次，并提供复制按钮。
- 同时写入 `~/apple-connector/profiles/<internal-uuid>.token`，权限 `0600`。
- 页面关闭/刷新后不再显示 token；本地文件仍存在，供本地恢复和兼容流程使用。

### 根据 token 找授权

- 服务端认证：`Store.authenticate(token)` 通过 `token_hash` 找到 client；这条路径本来就不需要知道内部 UUID。
- 本地文件：`profiles/<internal-uuid>.token` 内容就是 token；文件权限 owner-only。
- 新增只读命令：

```text
apple-connector auth show --auth-file <path> --json
apple-connector auth show --auth <token> --json
```

返回：

```json
{
  "name": "默认授权",
  "grants": [
    {"provider":"calendar","containerIds":["..."],"actions":["read","create"],"fields":"full","expiresAt":1790000000000},
    {"provider":"reminders","containerIds":["..."],"actions":["read"],"fields":"full","expiresAt":1790000000000}
  ],
  "expiresAt": 1790000000000,
  "lastUsedAt": 1760000000000
}
```

- `auth show` 不返回 token、token hash、内部 UUID 或 credential 路径；只回答“这个 token 对应哪个授权、有什么范围”。
- 不新增 `auth list`：没有 token 就不应该枚举可用授权；页面负责列表。

### CLI 认证优先级

1. `--auth-file <path>`：从文件读取 token（owner-only）。
2. `--auth <token>`：直接传入 token（文档不推荐，避免 shell history）。
3. `APPLE_CONNECTOR_AUTH`：从环境变量读取 token。
4. `--profile <internal-uuid>`：旧方式，从 `profiles/<uuid>.token` 读取。
5. `--credential-file <path>`：旧方式。

`--auth` 只接受 token，不接受内部 UUID，避免两种 ID 混淆。

## 完全移除审批

### 移除内容

- 页面：
  - 删除“审批”导航项；
  - 删除审批列表、approve/reject 按钮；
  - 创建/查看授权时不再显示 approval 字段。
- 数据：
  - `grantSchema` 删除 `approval` 字段；
  - 旧 grants JSON 中的 `approval` 在数据库迁移时删除；
  - 新建授权不写入 approval。
- 状态机：
  - `AgentOperations.prepare` 不再产生 `prepared`，直接产生 `approved`；
  - `submit` 直接 commit；
  - `execute` 不再检查 `prepared`；
  - 删除 `approve` / `reject` / `preview` 服务方法。
- RPC：
  - 从 `rpcMethodSchema` 删除 `operations.approve`、`operations.reject`、`operations.preview`；
  - 从 `adminMethods` 删除对应条目；
  - 管理 Web 不再调用。
- 错误码：
  - 不再产生 `approval_required`；
  - 审计 schema 中保留 `approval_required`，仅用于解析历史审计记录。
- 文档 / Skill：
  - 删除审批章节、`prepared` 分支、`operation get` 等待审批的说明；
  - `operation get` 保留，用于幂等键和 `outcome_unknown` 恢复。

### 数据库迁移

新增 `PRAGMA user_version=6`：

1. 取消所有未完成审批状态：
   ```sql
   UPDATE operations SET state='cancelled', payload=NULL
   WHERE state IN ('prepared', 'approved');
   ```
   - `prepared`：原来等待审批，升级后不再有人能批准，必须取消。
   - `approved`：可能是在 prepare 与 commit 之间崩溃留下的意图；为避免升级后自动执行，统一取消。
2. 遍历 `clients.grants`，解析 JSON，删除每个 grant 的 `approval` 字段，重新写回。
3. 保留 `revoked`、token hash、operations 终端状态和审计不变。
4. `PRAGMA user_version=6`。

迁移失败时启动失败，不进入半迁移状态；迁移在事务中执行。

### 兼容性影响

- 旧授权升级后变为“无审批、直接执行”；这正是你要求的移除审批。
- 旧的 `prepared` / `approved` 操作被取消，不会在升级后突然执行；需要的话由调用方用同一幂等键重新提交。
- 旧 `{ name, grants }` 配置文件中如果带 `approval`，将不再通过 `clientInputSchema`；需要移除该字段。相关文档会给出迁移说明。
- 旧页面/脚本调用 `operations.approve` / `operations.reject` / `operations.preview` 会得到 `invalid_request`（未知方法）。
- `operation get` 的返回结构不变。
- CLI `schemaVersion` 建议保持 `2`：envelope 结构未变；但审批相关行为是 breaking change，需要在 release notes 中明确。

## 页面设计

### 创建授权（唯一表单）

```text
创建授权
  名称 [默认授权]
  过期时间 [一年后]

  日历
    [ ] 工作日
        read [ ]  create [ ]  update [ ]  delete [ ]
        字段 [完整内容 / 仅忙碌状态]
    [ ] 家庭
        ...

  提醒事项
    [ ] 提醒
        read [ ]  create [ ]  update [ ]  complete [ ]  delete [ ]
    [ ] 购物
        ...

  [创建授权]
```

- 不分简单/高级。
- 双 provider 同时展示。
- 每个容器独立勾选动作。
- 日历 `仅忙碌状态` 仍只能搭配 `read`。
- 没有 approval 控件。
- 提交前校验：
  - 至少一个容器；
  - 每个选中容器至少一个动作；
  - 总 grant 数 ≤ 30，单条容器数 ≤ 100。
- 相同权限组合仍合并为一条 grant。

### 创建结果卡

```text
授权已创建

授权 ID（只显示一次）
  <token>
  [复制]

范围
  日历：工作日（读/写）、家庭（只读）
  提醒事项：提醒（读/写/完成）

有效期至 2027-11-17

请立即复制给 Agent。关闭页面后不再显示。
Agent 示例：
  export APPLE_CONNECTOR_AUTH='<token>'
  apple-connector calendar list-calendars --json
```

- 只显示一次。
- 刷新页面后不显示。
- 不显示 credential 文件路径作为主结果。
- 复制按钮只复制 token。

### 授权列表

每张卡片：

```text
默认授权
日历：2 个容器
提醒事项：1 个容器
有效期至：2027-11-17
最近使用：2026-11-17 10:00（或“从未使用”）
[查看详情] [删除]
```

- 查看详情展开 grants、容器名称、每个容器的动作、字段、过期时间。
- 不显示 token、token 前缀、hash、内部 UUID（或只在“技术详情”折叠中显示内部 UUID）。
- 删除需要确认。

- 不提供授权编辑、轮换、再次查看 token。
- 不提供审批、approve/reject/preview、`prepared` 状态。
- 不新增 `auth list`、自动选择授权或容器。
