# Apple Connector v0.2.0 实施进展

更新日期：2026-09-06
对应计划：[v0.2.0-plan.md](./v0.2.0-plan.md)

## 当前状态

实现进行中，package 已进入 `0.2.0-dev.0`。P0 的恢复代码与 P1 分阶段/持久化诊断已经落地；真实复核证明 Reminders 会“写入已发生但调用超时”，且仍有 1 个无法取得 UUID 的已完成历史探针待人工核验。Calendar EventKit 稳定定位不成立，因此 P3 写入门禁保持关闭。P4 管理切片与 P5 本地发布验证已推进，但完整 v0.2.0 尚未达到发布条件。

- [x] 明确恢复脚本可能遗漏已更新标题的探针，历史 `removed: false` 不足以证明无残留。

## 已有证据与限制

本轮 `npm run check` 已通过：60 项核心测试与 20 个固定 JXA 脚本语法检查。首次沙箱运行因本地监听受限失败，允许监听后全部通过；这不是原生写入成功证据。`npm run release:verify` 对 `0.2.0-dev.0` 的构建、CLI、doctor、运行依赖、全部注册 JXA 脚本、管理静态资源和 dry-run 包内容验证通过。

历史原生证据见 [native-validation.md](./native-validation.md) 与 [v0.1.1-progress.md](./v0.1.1-progress.md)。其中恢复结果须按本计划重新核验，不能将未匹配原始标题解释为所有可能状态下均无残留。

## 下一步

先解决 Reminders 宿主/同步层阻塞，并在新诊断日志下取得每个动作三次独立成功证据；在此之前不接入既有提醒修改/完成。Calendar 稳定标识与共享边界需要产品/技术决策，未成立前继续关闭写入。并行完成最终安装权限与 Homebrew/签名路径实测。
