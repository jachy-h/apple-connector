# Apple Connector v0.16.3 计划：提示词改用授权 key，由 CLI 解析本地凭据

更新日期：2026-11-19

状态：已批准并实施完成（2026-11-19）

进度：[v0.16.3-progress.md](./v0.16.3-progress.md)

## 问题

当前管理页生成的 Agent 提示词直接暴露凭据文件的绝对路径：

```text
- 凭据文件：`/Users/<user>/.apple-connector/profiles/<uuid>.token`
apple-connector auth verify --agent '<name>' --auth-file '/Users/<user>/.apple-connector/profiles/<uuid>.token' --json
```

这会让 Agent 把注意力放在文件路径上，容易主动 `cat`、复制、备份或扫描该文件，也让人误以为 Agent 需要自己读取凭据。实际应只由 `apple-connector` 进程在本地解析凭据。

## 结论

提示词只展示一个**授权 key**（不是 bearer token），业务命令统一改用新的 `--auth-key <key>`：

- CLI 收到 key 后，自行到 `<state dir>/profiles/<key>.token` 读取 owner-only 凭据。
- 默认 state dir 为 `~/.apple-connector`，因此实际目录是 `~/.apple-connector/profiles/`（用户描述中的 `~/apple-connector/profiles` 是旧目录；旧目录仍由现有 `migrate-state` 机制迁移）。若设置了 `APPLE_CONNECTOR_STATE_DIR`，则以其为准。
- 授权 key 复用现有 `client.id`（UUID），也就是当前 token 文件的文件名。它不新增秘密、不改变数据库结构、不影响删除或轮换。
- 提示词不再出现 token 文件路径，并明确要求 Agent 不要读取、扫描或打印 profile 目录中的 token 文件。

授权 key 不是 bearer token：拿到 key 但没有本机 owner-only 文件权限，仍然无法认证；真正的认证仍由文件内容和 `token_hash` 校验完成。

## 具体改动

### 1. CLI 认证参数

`src/cli/index.ts`：

- 新增 `--auth-key <key>`，解析为 `<state dir>/profiles/<key>.token`，读取仍复用现有 `readClientToken()`（要求普通文件、非符号链接、`0600`）。
- key 只允许安全文件名：`^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`，并拒绝 `.`、`..`。禁止路径分隔符，避免目录穿越。
- 找不到对应文件时返回稳定的 `invalid_request` 错误，例如 `Unknown authorization key. Run \`apple-connector open\` to create or recover an authorization.`，**错误信息不打印解析后的文件路径**。
- 保留现有优先级和兼容参数，不破坏旧提示词与脚本：
  1. `--auth-file <path>`
  2. `--auth <token>` / `APPLE_CONNECTOR_AUTH`
  3. `--auth-key <key>`（新增）
  4. `--profile <key>`（新参数的同义旧名，继续可用）
  5. `--credential-file <path>`
  6. 现有 `profiles/default.token` 兜底行为保持不变
- `--auth-key` 和 `--profile` 同时出现时，以 `--auth-key` 为准。

### 2. 管理页返回与提示词

`src/transports/admin/main.ts`：

- `clients.create` 的响应在保留 `credentialFile` 的同时新增 `credentialKey: created.client.id`，让前端不依赖路径字符串。
- 不改变 `clients.delete` 的清理逻辑，仍删除 `profiles/<client.id>.token`。

`src/web/agent-prompt.ts`：

- 输入从 `credentialFile` 改为 `credentialKey`。
- 推荐版提示词改为：

```text
- 授权 key：`<client-id>`

执行 3 步：
1. apple-connector skill path --json
2. apple-connector auth verify --agent '<your name>' --auth-key '<client-id>' --json
3. apple-connector calendar list-calendars --auth-key '<client-id>' --json
   （或 apple-connector reminder list-lists --auth-key '<client-id>' --json）
```

- 增加一句固定说明：凭据由本机 `apple-connector` 根据授权 key 自动解析；不要读取、复制、扫描或打印 profile 目录中的 token 文件。
- 含授权码的兜底版本继续使用 `--auth '<token>'`，保留现有 `0600`/secret store 警告。
- 中英文同步。

`web/src/main.tsx`：

- 创建授权后接收 `credentialKey` 并传给 `buildAgentPrompt`。
- “内部记录 ID”标签改为“授权 key”（`internalRecordId` → `authorizationKey`），方便用户在创建页之后仍能找回 key；中英文 i18n 同步。
- 第 4 步等待绑定提示中的示例命令从 `--auth-file <path>` 改为 `--auth-key <key>`。

### 3. 帮助、文档与 Skill

统一以 `--auth-key <key>` 作为面向 Agent 的推荐方式，`--auth-file <path>` 仅作为自定义路径的兼容方式保留：

- `src/cli/ui.ts`：`calendar`、`reminder`、`auth show`、`auth verify`、`operation get` 的 options/examples，以及全局帮助底部说明。
- `src/web/docs.ts`：中英文快速命令、业务命令示例和认证说明。
- `skill/SKILL.md`：Connect 步骤改为“授权 key”；说明 key 由 CLI 解析，禁止扫描 profile 目录；`--auth-file` 作为兼容项保留。
- `docs/cli.md`、`docs/skill.md`、`docs/getting-started.md`、`docs/getting-started_zh.md`、`docs/install-for-agent.md`、`docs/install-for-agent_zh.md`、`README.md`、`README_zh.md` 同步。

## 兼容性

- 旧提示词中的 `--auth-file <path>`、`--auth <token>`、`APPLE_CONNECTOR_AUTH` 继续有效。
- 已存在的 `profiles/<uuid>.token` 不改名、不重写，直接作为 `--auth-key <uuid>` 的数据源。
- 数据库结构、RPC 契约、审计格式不变；不破坏旧录像/计划/配置。
- `clients.create` 只是新增响应字段，旧前端忽略新字段也能工作。

## 不在本次范围

- 不新增可自定义、可轮换的短 key，也不引入 key 数据库字段（复用 `client.id` 已满足需求）。
- 不移除 `--auth-file` / `--credential-file` / `--profile`，避免破坏既有 Agent 配置。
- 不改变 token 生成、哈希、撤销或删除语义。

## 影响范围

- CLI 参数解析、管理页提示词、管理页标签、帮助文本、文档和 Skill、相关测试、版本号。
- 不涉及 native helper、EventKit/JXA、数据库迁移或权限判定逻辑。
