## Phase 0 实测（已完成）

在专用测试列表 `Agents`（`D4DD0F18-98A9-408F-932F-49001E9653F6`）用一次性 Swift 探针（临时目录，未写入仓库）验证：

- [x] EventKit 授权为 `full_access`（`authorization=3`）。
- [x] date-only：components 为 `y=2032 mo=2 d=29`，hour/minute/second 均为 nil，`timeZone=nil`，calendar 为 gregorian；direct 与 list fetch 一致。
- [x] instant：`Asia/Shanghai` 的 `2032-03-01 17:30:00` 在保存、换新进程重新读取和 list fetch 后仍保留 `h=17 mi=30 s=0 tz=Asia/Shanghai`。
- [x] floating：`2032-03-02 18:45:00` 无时区写入后，重新读取仍为 `tz=nil`。
- [x] 修改 instant due 为 19:15 后，direct/list fetch 均为 19:15，时区仍为 `Asia/Shanghai`，ID 不变。
- [x] date/instant/floating 的 `calendarItemIdentifier` 在 direct、list 和 update 后保持一致。
- [x] 重复提醒写入后 `recurrenceRules.count = 1`。
- [x] 探针清理后 `leftovers=[]`。

结论：EventKit 在本机数据存储中保留 IANA 时区和 date/floating 区别，原计划的 due 契约不需要降级，不引入 sidecar。

实现期间额外发现并验证：把已存在的 date-only/floating 提醒改为 instant 时，如果只设置 `dueDateComponents.timeZone`，EventKit 会丢掉时区并把它读成 floating；必须在设置 components 之后显式设置 `reminder.timeZone = zone` 再保存。helper 已按此顺序实现，并已验证 instant→date、instant→floating、date→instant、floating→instant、instant→null 的双向转换。

环境备注：从当前 SSH 会话直接执行 `dist/native/apple-connector-helper` 会被系统以 SIGKILL 结束（exit 137）；执行 `native/.build/release/` 二进制或临时目录副本正常。该现象未影响 Phase 0，但 native opt-in 测试仍需从本机 Terminal 运行。
