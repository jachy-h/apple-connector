# Apple Connector v0.4.0 计划：Web 调试 MVP

状态：实现进行中（P1–P4）。
更新日期：2026-09-06
进度记录：[v0.4.0-progress.md](./v0.4.0-progress.md)

## 1. 本期目标与已确认需求

打开本地 Web 界面后，用户通过 APPs 直接调用 Apple App 已有能力、查看实际结果，再到审计页面查询最近的 Web 调试操作。基本流程不依赖 MCP，也不需要创建、选择或配置客户端。

已确认：

- 一级主菜单只有 **APPs** 和 **审计**；APPs 下包含日历、提醒事项、备忘录。
- 日历中的操作对象是日程事件，不是日历集合。日历集合用于选择查询目标。
- 本期只覆盖底层服务已经支持的能力，不为了凑齐增删改查扩展原生能力。
- 本期审计只考虑 Web 调试，不要求接入 MCP 或 CLI 操作记录。
- 本期不提升 package 版本；实现按本计划分阶段推进。

未来可以采用纯 CLI：将应用服务与 Web、CLI、MCP 入口解耦，CLI 可直接调用同一套服务，MCP 不是核心依赖。本期不增加完整 CLI 调试命令，也不删除已有 MCP 实现。

## 2. 能力范围

以当前服务 reader/writer、参数契约和 [v0.2.0 支持矩阵](./v0.2.0-support-matrix.md) 为基线。存在诊断脚本不等于已具备可开放的服务能力。

| App | 本期操作 | 输入与结果 | 本期不支持 |
| --- | --- | --- | --- |
| 日历 | 选择日历、按时间范围查询日程事件、分页查看 | 精确日历名称、开始/结束时间；显示标题、起止时间、全天状态及已有地点/备注字段 | 新增、修改、删除事件；日历集合增删改；额外全文搜索 |
| 提醒事项 | 选择清单、分页读取、新增 | 清单、标题、备注、可选到期日期或带时区时间；显示实际列表与新增回执 | 修改、完成、删除；新增底层关键词搜索 |
| 备忘录 | 选择文件夹、搜索、读取详情、新增纯文本笔记 | 文件夹、搜索词；新增标题与正文；显示搜索结果、详情及新增回执 | 修改、删除、富文本编辑 |

提醒事项新增沿用已有原型能力，页面明确标记“不稳定，可能超时”。不得把它展示为已通过可靠性验收；也不将解决其原生超时问题扩大为本期任务。结果未知时提示去原 App 核验，禁止自动重放写入。

Notes 沿用非共享、未锁定对象限制。Calendar 沿用精确名称定位，缺失或重名时拒绝并解释原因。已有原生限制在服务端继续生效。

不支持的操作不提供可提交表单；在 App 内用简短说明标明本期范围。不能提供看似可用、点击后才统一报错的增删改入口。

## 3. 页面与交互

### APPs

- 默认进入 APPs / 日历；二级菜单为日历、提醒事项、备忘录，界面以中文为主。
- 每个 App 使用“选择目标 → 选择操作 → 填写参数 → 执行 → 查看结果”的表单流程，不要求手填 JSON、token 或客户端授权。
- 容器选择复用现有元数据发现能力。可按精确名称查找日历、清单或文件夹，再选择已验证目标；无法自动发现时提供精确标识输入及明确帮助，不能猜测目标或要求用户先创建客户端。
- 容器发现不顺带读取内容；选定目标并提交查询后才加载实际数据。
- 日历的“查询”就是已有时间范围读取；提醒事项的“查询”就是已有分页列表读取。不能将当前页过滤冒充全量搜索。
- 查询显示可读的真实结果，不能只显示计数或诊断摘要；详情按已有 reader 的返回字段展示。笔记内容安全渲染，不执行原始 HTML。
- 新增直接在当前页填写表单并提交，服务端完成执行和核验，不跳转审批页，也不要求手动 prepare/commit。
- 区分加载中、空结果、成功、失败、结果未知；显示可理解的错误原因及关联操作编号。提交期间防止重复点击，刷新不重发写入。
- 分页或数量上限沿用服务契约，明确显示是否还有结果或达到返回上限，不把受限结果宣称为全部。

### 审计

- 展示 Web 调试触发的容器发现、查询、详情读取、新增记录，按时间倒序；审计页自身的查询不产生新的业务操作记录。
- 最小字段：时间、App、动作、目标容器/必要对象引用、结果、耗时、操作编号；失败或未知结果提供脱敏原因。
- 支持 App、结果、时间范围筛选、分页与手动刷新。
- 一次用户操作关联一个操作编号；内部准备、调用、核验阶段不伪装成多次用户操作。
- 记录成功、失败和结果未知；执行中的写入可显示“执行中”，刷新后可继续查询其状态。拒绝或参数校验失败也需可追踪，但不将原始请求正文写入审计。
- 审计只保存必要元数据，不保存笔记正文、提醒备注、完整事件内容、凭证或原始原生错误。当前结果页可显示用户主动查询的内容，审计不是内容备份。
- 本期页面只查询明确标记为 Web 调试来源的记录；旧记录不猜测来源、不混入新列表。导出、清空、统计报表不属于本期 MVP。

## 4. 实现设计与边界

### 本机 Web 身份

复用现有本机启动、一次性登录链接和管理会话。管理员登录后可直接调试所选目标，无需客户端 token；“无需 MCP 客户端”不等于取消本机会话验证或 macOS 系统权限。

新增专用 Web 调试接口与应用服务入口，显式携带 Web 管理操作身份、动作和目标容器。不得通过创建隐藏的全权限 MCP 客户端来适配现有 API，也不得把管理员 token 当作客户端 token 使用。

服务端校验会话、动作白名单、参数、目标容器及原生限制。保留现有 loopback、Host、Origin、CSRF 和 Cookie 防护。Web 提交只授权当前明确动作，不开放任意脚本执行。

### 复用应用服务

- 复用已有 Calendar、Reminders、Notes reader/writer、参数校验、写后核验和结果未知处理。
- 将现有写入流程中绑定客户端鉴权的部分与执行逻辑分离，以 Web 管理身份执行；内部持久化准备/执行步骤可以保留，用户界面只需一次提交。
- 写入开始前持久化操作编号和执行状态；重复提交同一请求不重复创建，断开或刷新后可按编号查询，未知结果不自动重试。
- 操作记录与审计支持明确的来源/执行身份，不能为通过旧数据库约束伪造客户端。兼容旧记录和已有未决操作，不重写其身份或执行语义。
- 能力展示反映实际服务能力与已知稳定性；尤其不能仅依赖当前静态 `available` 字段把 Reminders 创建展示为可靠。

### 主要文件范围

| 范围 | 计划变更 |
| --- | --- |
| `web/src/` | 双主菜单、App 表单、结果展示、Web 审计页面 |
| `src/transports/admin/server.ts`、本地 RPC/handlers | 已认证的 Web 调试接口、状态查询、参数校验 |
| `src/application/`、`src/operations/` | 与客户端 token 解耦的 Web 执行入口、复用原生调用与核验 |
| `src/audit/schema.ts`、`src/storage/database.ts` | Web 来源、执行身份、状态与查询兼容 |
| `tests/`、README 与版本文档 | 必要自动化测试、真实操作验收记录、使用说明 |

现有授权、MCP 配置、审批及诊断探针不再作为本期 Web 主导航；本期不扩展这些页面，不删除后端兼容能力。v0.3.0 尚未完成的外部 MCP/发布验收仍保留历史状态，不作为本期 MVP 前置条件。

## 5. 实施顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 Web 执行与审计基础 | 明确 Web 身份、调试接口、操作状态与来源，解耦客户端依赖 | 无客户端记录也能完成受控读取并产生 Web 审计 |
| P1 APPs 查询 | 双主菜单、容器选择、三个 App 已有读取/搜索与结果界面 | 能选择目标、提交查询、查看真实数据和错误 |
| P2 已有新增 | Notes、Reminders 表单与现有 writer 接入，写入状态恢复 | 一次提交完成执行和回执；Reminders 不稳定提示准确 |
| P3 审计闭环 | Web 来源过滤、时间倒序、筛选分页、关联结果 | 每次调试可查询到对应记录，刷新后仍存在 |
| P4 验收与文档 | 自动化、浏览器交互、真实原生验证、使用说明 | 记录通过项与原生限制，区分 mock 与真实证据 |

## 6. MVP 验收标准

- [ ] 沿用启动命令打开网页，主菜单只有 APPs、审计，默认进入日历。
- [ ] 未创建任何 MCP 客户端时，仍能选择目标并执行本期支持的 Web 操作。
- [ ] 日历按指定时间范围分页返回真实日程；重名/不存在日历和无效时间范围有明确错误。
- [ ] 提醒事项能读取清单内容、提交已有新增能力，页面显示不稳定状态；超时/回读失败正确显示结果未知。
- [ ] 备忘录能搜索、打开详情及新增纯文本笔记；既有共享/锁定限制仍生效。
- [ ] 修改、删除等未支持动作没有可执行入口，不调用隔离诊断脚本补位。
- [ ] 新增不要求客户端、token 或审批页面；重复点击、同一请求重复提交、刷新不会自动重复写入。
- [ ] 成功、失败、结果未知及执行中状态可理解，写入可在刷新后通过操作编号继续查询。
- [ ] 审计只返回 Web 调试记录，时间倒序、App/结果/时间筛选及分页正确，包含查询与新增操作。
- [ ] 审计和日志不保存内容正文或凭证；未认证/非法来源请求无法执行调试操作或读取结果。
- [ ] 自动化覆盖无客户端路径、动作白名单、身份隔离、审计来源筛选、写入重复提交及未知结果；相关检查与 `npm run check` 通过。
- [ ] 浏览器完成“APPs 操作 → 查看结果 → 审计定位记录”闭环。真实写入使用明确测试清单/文件夹，验收记录区分通过、失败与未验证；清理由原 App 人工完成，不新增删除能力。

## 7. 不在本期范围

完整增删改查、新 Apple App、原生技术路线迁移、解决所有原生可靠性问题、MCP 客户端配置与接入验收、完整 CLI 调试命令、远程 Web、多用户权限管理、复杂审批、审计导出/清空、发布安装体系。

本期完成标准是已有能力在 Web 中可发现、可直接执行、可查看结果、可追踪操作，而不是所有 Apple 数据操作均已可靠支持。
