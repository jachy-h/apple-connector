# Apple Connector v0.8.3 计划：npm 首次发布与 Agent-first README

更新日期：2026-09-08  
进度记录：[v0.8.3-progress.md](./v0.8.3-progress.md)

## 目标

1. 将当前项目整理为可公开安装的 npm 包，包名为 `@jachy/apple-connector`，版本为 `0.8.3`，全局命令仍为 `apple-connector`。
2. 完全重写中英文 README，将“全局安装 + 把一段可复制指令交给 Agent 完成接入”作为首要流程。
3. 建立可重复的发布门禁：审计 tarball，从 tarball 全局安装，在干净状态目录中验证 CLI 与 Agent 初始化，最后再发布并回读 registry。

## 已确定的产品与发布决策

- npm 包名：`@jachy/apple-connector`。
- 全局安装命令：`npm install -g @jachy/apple-connector`。
- CLI 名保持 `apple-connector`，不让 scope 影响用户后续命令。
- 发布为 public scoped package；在 `package.json` 显式声明 `publishConfig.access: "public"`，不依赖发布者手工记住 `--access public`。
- npm 包携带已构建的 macOS 原生 helper，普通用户全局安装时不需要 Swift 工具链。
- README 不把源码开发流程放在主路径；开发、手动配策、排障继续下沉到 `docs/`。
- npm 首次发布是最后的外部写入步骤，必须在包名、账号、2FA/授权和本地验收都通过后执行。

## 实现范围

### 1. 发布元数据

- 将 `name` 改为 `@jachy/apple-connector`，将 `version` 改为 `0.8.3`，同步 lockfile。
- 移除 `private: true`，增加 `publishConfig.access: "public"`。
- 补充并核对 `license`、`repository`、`homepage`、`bugs`、`keywords`、`os` 和 `engines`。如果仓库尚未选定开源许可证，在发布前必须明确，不猜测。`release:verify` 必须拒绝缺少这些发布元数据的构建。
- 保留 `bin.apple-connector`，并验证 tarball 内入口脚本和 helper 都有可执行权限。

### 2. 打包边界与体积

- 不再将整个 `native/` 纳入 npm 包；当前 `native/.build` 会让 tarball 达到约 57 MB、解压约 127 MB。
- 发布包仅保留运行所需的 `dist/src`、`dist/web`、`dist/native/apple-connector-helper`、必要的 `scripts/jxa`、README 与用户文档。
- 排除 `dist/tests`、`native/.build`、本地缓存、调试符号和其他非运行产物。source map 是否保留以实际包体积和排障价值为准。
- 增强 `release:verify`，同时检查必需文件存在、禁止路径不存在、包大小/文件数不超过上限。

### 3. README 完全重写

README 主线参考用户给出的[腾讯文档 Agent 接入页](https://docs.qq.com/scenario/open-claw.html?nlc=1)：让用户获得一段可直接交给 Agent 的安装指令，由 Agent 完成环境检查、安装、配置和验收。

拟定信息架构：

1. 一句话定位：只在 macOS 本机运行，通过 stdio MCP 读写 Calendar 和 Reminders。
2. 前置条件：macOS 与受支持的 Node.js 版本；明确 Apple Notes 当前不可用。
3. 最短手动路径：

   ```sh
   npm install -g @jachy/apple-connector
   apple-connector agent init
   ```

4. 首屏提供“复制给 Agent”的完整指令块，要求 Agent：
   - 检查 macOS 和 Node 版本。
   - 全局安装 `@jachy/apple-connector@0.8.3`。
   - 运行 `apple-connector agent init`。
   - 只合并输出的 `apple-connector` MCP 条目，不覆盖 host 已有配置。
   - 不读取或展示 token，不把 token 内容写进配置。
   - 重载 host 后只调用 capabilities 与列表类工具验收，不为测试写入真实 Apple 数据。
5. 简短解释默认权限边界：全部容器只读，精确名为 `Agents` 的容器可写。
6. 用一个紧凑表格展示可用能力，再链接完整配置、权限和排障文档。
7. 开发者入口、限制、安全模型与版本链接放在后半部分。

中文 `README_zh.md` 与英文 `README.md` 保持结构和事实一致；中文版用作本轮文案评审的基准。

### 4. 发布与回滚准备

- 检查 npm 当前账号、`@jachy` scope 权限、包名可用性和 2FA/发布授权；不在日志或文档中暴露 token。
- 在新建的临时目录中对生成的 `.tgz` 执行全局安装测试，验证 `apple-connector version`、`--help`、`doctor` 和隔离状态目录的 `agent init`。
- 通过后执行 public 发布，再用 registry 回读包名、版本、dist-tag 和 tarball 元数据，并从 registry 安装一次。
- npm 版本不可覆盖。若发布后发现问题，优先尽快发布修复版；只在符合 npm 规则且确有安全必要时考虑 unpublish/deprecate。

## 验收标准

- `npm pack --dry-run --json` 显示包名为 `@jachy/apple-connector@0.8.3`，不包含 `native/.build` 和 `dist/tests`，包体积回归到运行产物的合理数量级。
- 从 tarball 安装后，全局命令仍为 `apple-connector`，且不依赖源码仓库或 Swift 编译。
- README 首屏同时提供 npm 全局安装和可交给 Agent 的接入指令，指令与实际 CLI 输出一致。
- Agent 验收默认只读，不会覆盖 host 配置，不会暴露 token。
- `npm test`、`npm run check:jxa`、`npm run release:verify` 和 `git diff --check` 通过。
- registry 回读 `@jachy/apple-connector` 的 `latest` 为 `0.8.3`，从 registry 的干净安装通过。

## 实施前待确认

1. 仓库当前没有 LICENSE 文件；首次公开发布前需要由维护者选定许可证。
2. 已定为仅支持 Apple Silicon：当前 native helper 为 arm64 Mach-O，npm `os`/`cpu` 元数据和 README 据此限制安装范围。x86_64/universal helper 不在 v0.8.3 范围。
3. 若将当前未提交的 v0.8.1/v0.8.2 改动一并作为首发内容，需先确认这批改动就是 v0.8.3 的发布基线。
